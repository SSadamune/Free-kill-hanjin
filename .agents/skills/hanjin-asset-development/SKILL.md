# 汉晋素材开发

用于图片、音效等资源的配置、替换和导入；不负责技能语义、规则裁定或游戏逻辑。素材是实际交付，稳定规范、功能设计、具体接线和验证状态各有归属，本 skill 只规定动作顺序与资料入口。

## 从短指令开始

用户给出动作、范围和素材即可启动，例如：

| 指令 | 默认执行方式 |
| --- | --- |
| 按照 `hanjin-asset-development` 替换刘协默认插画，素材在 `assets/` | 查实际程序 ID 与引擎入口，导入并核对路径／字节，必要时构建验证 |
| 按照 `hanjin-asset-development` 接入某技能语音，素材已提供 | 查技能骨架名、武将 ID 和真实音频入口后导入；不猜文件名或目录 |
| 按照 `hanjin-asset-development` 核对客将插画路径 | 只核对素材路径与注册状态，不把静态检查写成客户端显示验收 |

默认由当前 agent 完成，不要求委派；不自动提交、推送或更新 PR。用户已授权的动作按授权范围执行，不另加确认门槛。动作若只要求核对，不顺手改素材或接线。

## 分层

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 通用约定 | `AGENTS.md` | 授权、图片目录、发布边界 |
| 工作流 | 本 skill | 素材任务的动作顺序与资料导航 |
| 稳定规范 | `docs/development/assets.md`；`docs/rules/`、`rulebook/` | 路径／命名／音效接口；游戏语义 |
| 功能设计 | `guest-illustrations.md` 等 | 待实装行为与验收范围 |
| 具体接线 | `docs/development/implementation/` | 入口、状态判断、加载位置 |
| 实际结果 | `docs/development/status.md` | 已验证、未验证与待办 |
| 实际交付 | `image/`、`audio/`、`pkg/`、`scripts/` | 安装包内容与开发工具 |

不要用 skill 代替规范，也不把状态记录写成设计或规则。

## 1. 确认素材与授权

- 优先使用用户提供的原稿或 `assets/` 中已存在的文件；缺少原材料时说明需要的程序 ID、用途、尺寸／格式和来源，向用户索取。
- 从零生图或绘制素材沿用 `AGENTS.md`，须用户明确批准；用户明确请求制作音效本身即任务授权，已有素材按任务授权处理。
- 新音效依用户目标和现有引擎接口处理；只有缺少会影响成品的关键需求（如目标技能、素材、格式）时再澄清，不强制询问所有码率／音量参数。

## 2. 查实际 ID 与引擎入口

- 正式程序 ID 以项目数据为准，例如 `pkg/qiao_generals/data/standard.lua` 与卡牌数据；外部参考的 `heroes.json`（本仓库未收录）、设计编号和文件名推测都不是正式登记依据。
- 按锁定引擎 `Fk/Base/SkinBank.qml` 核对入口：武将图、附加图、卡牌图、装备图标、延时锦囊图各自按固定目录和程序 ID 查找；不递归搜索分包目录。
- 临时程序 ID 不能当正式登记依据，也不能仅为图片或音效命名去改武将 ID、建全量路径映射或新增分包层级。
- 找不到对应入口时，先查锁定源码和项目现有接线；仍无法确认就明确记录边界，不编造目录、后缀或文件名。

## 3. 保存、转换与迁移

- 默认图片按实际程序 ID 原路径保存；客将图与普通图同名，放 `image/generals/guest/`。不维护逐将路径清单。
- 目标入口要求的扩展名与真实格式必须一致，不能只改后缀冒充格式转换。
- 区分两种操作：迁移原稿时保持字节不变；按目标要求转换或裁切时记录来源、工具与参数，并分别核对结果。两者不能混写成一个“已处理”。
- 色彩空间、裁切、画布和音量依据目标入口、已有素材和用户要求确定；不能只凭 JPEG 3 分量推断 sRGB，也不把某一批的尺寸或 ICC 状态定为全项目规范。
- 音效放入项目根 `audio/`，按 `assets.md` 与引擎实际查找路径命名；技能语音前缀使用技能骨架名，武将语音使用程序 ID。不要用未核实的命名习惯套新文件。

## 4. 接线

- 普通图片替换通常只需文件到位及既有注册／入口；不为普通换图补联网、重连全套验收。
- 只有涉及状态换图时才检查客将设计：登记了客将势力不等于本局实际发生替换，主将和副将分别判断，注意隐藏信息与重连恢复，并按[客将默认插画设计](../../../docs/development/guest-illustrations.md)验收。
- 音频接线要核对技能骨架名、武将 ID、触发入口、`audio_index`／静音设置和实际播放调用；不确定时保持现有调用，不新增未经验证的音量或格式参数。
- 面向玩家的接线随正式扩展发布，开发脚本和原稿不进入安装包。

## 5. 发布与验证

- 涉及发布或加载路径时执行 `python scripts/build_release.py`，核对安装包包含 `init.lua`、`pkg/`、`image/`、`audio/` 的实际文件，且不含测试、脚本、原稿或 `.dev/` 内容。
- `scripts/verify_image_assets.py` 的默认模式只检查当前图片批次（固定该批数量与尺寸），不能当作未来素材的通用验收标准；`--release` 按当前发布集合核对 ZIP 路径与逐文件字节，可用于含图片／音效的安装包，但不解码或播放音频。
- 音效至少核对源文件路径、构建包含和引擎调用入口；需要实际播放或客户端显示时按人工验收处理。没有可用运行时或接口未核实时，写明未验证范围。
- 仅在改动 Lua、注册或加载逻辑时按[测试规范](../../../docs/development/testing.md)运行相关测试；纯素材复制不机械重跑全量。共享运行时遵守唯一执行者与锁约定。
- 稳定事实写回 `assets.md`；具体接线写 `implementation/`；真实命令与结果写 `status.md`。不另建长报告，不把计划或未执行项写成已通过。

## 边界

- 不修改 `docs/rules/`、`rulebook/` 的游戏语义，不修引擎，不为素材改游戏逻辑。
- 不建立全量图片／音效路径映射，不擅自改程序 ID，不提交或推送未经授权的改动。
- 不把某一批的数量、尺寸、色彩或 ICC 状态固化为全项目要求。
- 静态路径、构建和脚本检查不代替客户端显示、声音播放或人工验收。

## 交付

说明实际改动文件、素材来源、真实执行命令与结果、未验证项或阻塞。需要规则判断时交回负责人，不自行裁定。
