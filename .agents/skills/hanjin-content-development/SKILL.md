# 汉晋内容开发

目标是让规则语义、玩家描述、新月杀实现及测试相互一致，不把现有代码当作规则裁定。

## 找到正确依据

- 先区分`docs/rules/` 外部来源副本、[项目设计与裁定](../../../rules/README.md)及独立的[《汉晋规则集》工作底稿](../../../rulebook/README.md)。项目方向见[愿景](../../../docs/vision.md)。工作底稿已复制基础条文，汉晋专属改编尚未完成；具体条文引用统一指向 `rulebook/`，结合已确认的项目差异开发。
- 只查本次内容相关的逐将或公共规范，再按术语、时机、消耗和目标查基础原文，不加载全部参考库。保留待裁定事项；不因实装或测试通过而将建议升级为规则。
- 写规范描述时读[描述指南](../../../docs/development/normalized-descriptions.md)。卡面文本、精确的规则抽象和引擎代码各有职责，不将实现报告直接当作正式条文。

## 选择实现路径

- 查[实现导航](../../../docs/development/implementation/README.md)，核实锁定引擎源码中的回调执行端、事件数据类型和方法所属对象。客户端判定不依赖服务端私有字段。
- 优先复用已有公共目标、转换、应变与武将来源机制；明确用牌入口只选择、返回待执行数据还是已执行，避免重复结算。结合本次语义检查主副将、明暗置、势力及来源变化，不机械扩展所有边界。
- 面向玩家的功能按正式安装包设计；客户端交互使用扩展可发布的接口，不能用开发本体补丁代替成品交付。

## 验证与交回

- 按[测试规范](../../../docs/development/testing.md)决定本轮少量核心验证，尽早触达真实请求或主要效果，先定向、稳定后默认全量。普通夹具建立明确状态；间歇失败保留输入与回复证据，不能靠重跑刷出通过。
- 仅在遇到同类问题时查[故障案例](../../../docs/development/lessons.md)。不为每个技能重新写一套公共回归或完整场景映射。
- 按[开发指南](../../../docs/development/README.md)收尾：更新实际受影响的规范及[开发状态](../../../docs/development/status.md)，区分自动化与人工验证。未经用户要求不提交、推送或更新外部 PR；确需交付时读取仓库模板。
- 跨模型交接明确本轮目标、允许文件、验收项及所需文档路径，不假设其他模型已自动加载此 skill。遵守 AGENTS.md 的规则维护权限与用户当前的协作要求。
