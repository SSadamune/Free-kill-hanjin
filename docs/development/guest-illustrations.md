# 客将默认插画：待实装功能设计

本文记录通用显示功能的需求与验收范围，当前尚未实装。资源路径见[图片资源保存规范](assets.md)。

## 预期行为

本局某张武将牌实际发生客将替换时，选将环节和入场后的武将区域优先显示 `image/generals/guest/<程序ID>.jpg`；缺图时沿用普通默认插画流程。仅登记了客将势力或后来改变角色势力，不等于本局已发生客将替换。

所有武将共用状态判断与图片选择入口，通过引擎 `SkinBank.getGeneralExtraPic(程序ID, "guest/")` 读取附加插画。新增素材只需按程序 ID 放置文件，不增加逐将路径配置或专属换图代码。

## 接入与验收要求

- 在选将候选展示前取得本局客将替换结果，候选卡片、确认选择和入场后的武将区域共用图片选择逻辑。
- 主将、副将分别依据各自武将的替换结果处理，不能仅按角色当前势力同时切换两张图。君主、野心家等独立武将版本始终使用各自实际程序 ID 查图。
- 当前 `GeneralCardModel.frontSkin` 调用 `SkinBank.getGeneralPicture(name)`；未来实装须接通这一选将默认图入口，以及局内头像、主副将等实际显示入口。
- 实际发生替换且客将图存在时优先显示客将图；缺图则沿用原有默认流程，包括原有 `dual/`、`avatar/` 等附加图与裁切逻辑。客将图自身在不同尺寸下的显示须实际验收。
- 重连依据本局真实武将与替换状态恢复显示；武将交换、移除或重新加入时更新对应来源，不残留旧图片。
- 客户端只接收其有权知道的武将与插画信息，不通过他人暗将的图片泄露身份。
- 核心验证包含替换与未替换、附加图存在与缺失、选将与入场一致、主副将分别处理、重连与来源变化，以及暗将可见性。公共行为集中验证，不为每名客将重复实现或重复公共测试。

## 当前进度

已确认同名文件分目录的保存方式符合引擎读取接口。通用状态传递和显示接线尚未实现；联网、重连及客户端实际显示须在实装后验收并更新开发状态。
