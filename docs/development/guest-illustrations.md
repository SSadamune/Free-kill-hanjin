# 客将默认插画

资源路径见[图片资源保存规范](assets.md)，扩展接线见[客将实现记录](implementation/guest-factions.md#客将插画)。

## 显示行为

房间开启「客将替换规则」时，选将环节和入场后的武将区域按程序 ID 优先显示 `image/generals/guest/<程序ID>.jpg`。换图也适用于按原势力出场的武将，以及朱儁这类只有客将插画的武将。朱儁显示汉势力，按通常的汉势力配将规则处理。房间关闭规则或对应武将缺图时，沿用普通默认插画流程。

所有武将共用图片选择入口，通过引擎 `SkinBank.getGeneralExtraPic(程序ID, "guest/")` 读取附加插画。新增素材只需按程序 ID 放置文件。

武将一览的「客将势力」开关默认关闭，对所有分包生效。开启时，已有客将登记的武将优先使用客将图，并按登记顺序显示全部客将势力。分包列表与各包的武将列表继续正常显示，未登记客将势力的武将保留原牌面。这个预览可以在大厅使用，无需建立对局。

## 接入与验收要求

- 选将候选、确认选择和入场后的武将区域都依据房间开关显示插画。候选的客将势力和重抽资格依然按本局替换结果显示。
- 对局内武将牌组件共用换图接线，包括原生弹窗、公开武将牌堆和技能预览。实际启用客将势力时，牌面显示其全部登记的客将势力，合法选择仍以本局允许的势力为准。
- 主将、副将各用当前可见的程序 ID 查图，君主、野心家等独立武将版本使用各自的 ID。
- 选将卡面优先用客将图，原 `GeneralCardModel.frontSkin` 提供缺图回退。局内主副将头像沿用引擎的遮罩和裁切。
- 缺图时沿用原有默认流程，包括 `dual/`、`avatar/` 等附加图与裁切逻辑。客将图在不同尺寸下的显示须实际验收。
- 重连依据房间设置和真实可见武将恢复显示。武将交换、移除或重新加入时按当前武将更新。
- 客户端只接收其有权知道的武将与插画信息，不通过他人暗将的图片泄露身份。
- 核心验证包含开关开启和关闭、附加图存在和缺失、选将与入场一致、主副将分别处理、重连与来源变化，以及暗将可见性。

当前验证范围见[开发状态](status.md#图片资源保存)。
