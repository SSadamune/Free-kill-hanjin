# 客将初始皮肤：待实装功能设计

本文记录未来通用功能的需求与验收范围，当前尚未实装。文件命名、默认槽位与引擎注册约定见[图片资源保存规范](assets.md)，不在本页重复定义。

## 预期行为

当本局某张武将牌实际触发客将替换时，将其已注册的默认客将皮肤作为初始皮肤，选将环节也显示同一外观。没有对应皮肤时使用引擎默认图。仅登记客将势力、后来改变角色势力或存在客将图片，不等于本局已触发替换。

所有武将共用状态判断、资源键转换、注册关联及皮肤选择入口，不要求每名客将单独填写图片路径或编写换图逻辑。常规武将只需正常登记编号、分包、客将规则，并按约定提供默认客将皮肤。

## 接入与验收要求

- 客将替换结果在选将候选展示时即可使用；候选卡片、确认选择和入场后的武将区域共用选择结果。主将与副将分别按各自武将处理，不按角色势力一次性给两将换图。
- 当前 `GeneralCardModel.frontSkin` 直接调用 `SkinBank.getGeneralPicture(name)`，实装时必须接通候选卡片的皮肤显示入口；仅调用 `addSkinPackage` 不代表选将展示已完成。
- `_guest_v01` 是默认槽位，其他槽位不因枚举顺序成为默认。缺图、未注册时正常回退，普通默认图无需在皮肤目录重复保存。
- 初始皮肤在选将及首次入场统一确定；角色后续主动换肤的结果应保存，重连恢复实际选择，不重新初始化覆盖。武将交换、移除与重新加入时按真实武将及状态重新核对，不沿用旧来源。
- 客户端只接收其有权知道的武将与皮肤信息；对他人的暗将不能通过图片泄露身份。
- 验证至少包含：实际替换与未替换、默认皮肤存在与缺失、选将与入场一致、主副将分别处理、主动换肤后重连恢复，以及暗将可见性。按风险选择自动化与人工验收，不要求为每名客将重复实现或重复公共测试。

## 范围边界

本功能改变的是初始外观，不创建新的武将程序 ID，不改客将规则。公共注册入口的具体实现方式留待实装时确定，不预设运行时目录扫描，也不恢复全量图片路径映射框架。联网、重连及人工显示未验收前，应在开发状态中明确标记。
