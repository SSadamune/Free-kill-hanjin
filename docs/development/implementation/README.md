## 分类与检索约定

1. **新增或调整武将。** 首页按武将所属内容包组织。标准包按汉、魏、蜀、吴、群、晋列出势力，君临天下按阵、势、变、权、矢、弩、发列出同级子包。首页只列分组和链接，实装或审阅状态写在相应子页。共用程序加载包、开发批次和测试不改变内容归属。在所属子页按编号增加「编号｜武将｜技能」行。技能按卡面顺序链接，关联、派生技能及专属旗、标记列在卡面技能之后并注明关系。
2. **在分包内按武将维护。** 每张武将牌在所属分包目录有一份逐将页，例如 `generals/standard/han001.md`。按卡面顺序设立技能或效果小节，旗、标记和派生效果归所属武将。翼从在所属分包建立 `retinue-<兵种>.md`。同文共享技能只在主来源武将页写完整说明，其他武将页链接到对应段落。多个机制分支放在本技能小节下。保留以牌面编号和技能顺序组成的锚点，例如 `#han001-1`、`#han016a-1`，运行时 ID 使用实际值。君主版用 `#em-wei001-1` 这类锚点，翼从用稳定的兵种名。按效果检索只维护分类和直达技能或效果段落的链接。
3. **新增公共机制、卡牌或客户端接线。** 先查对应职责组及已有记录。公共模块记录入口、调用双方、数据、时机与正式加载。具体技能写本身如何调用、复核和处理特殊分支。客户端、卡牌内容及加载进入各自分类。部分接入或尚未验证时具体写出对应路径。
4. **每批稳定后同步。** 更新主记录、受影响索引和[开发状态](../status.md)。历史命令、原验证环境和批次结果集中在[共享验证证据](generals/verification-evidence.md)。移动内容后修复入站链接或保留锚点。用一次实际检索复核武将条目和公共机制。规则确认、正式接入、自动化和人工验收分别记录。

### 技能与专属效果条目

| 字段 | 内容 |
| --- | --- |
| **标识与依据** | 名称、所属武将及版本、运行时 ID、源码和项目规则。逐字引用对应牌面文字，用 Markdown 引用块并链接到原始图片、文字提取或外部资料的具体位置，文件链接使用正式文件名。核对正式加载后的说明。遇到异文时记下当前显示、原文与采用依据，缺少可核实来源时注明哪一条原文待核。 |
| **实现与接口** | 用完整句子写清谁在何时发动、验证哪些条件、选择什么、怎样支付和结算。事件名及 API 放在对应步骤中。涉及选牌和正式执行两步时分别写明，明确角色指代和服务端再次校验。明暗置、持续状态和多技能来源要写清归属、迁移和清理。 |
| **验证依据** | 链接能支持结论的用例，说明走了哪个入口、断言什么、是否有预设结果或请求替身。把离屏界面和真人操作实测的范围写清，整包通过数引用历史证据。 |
| **未完成与边界** | 写出与该条特有的暂行口径、限制或待验证场景。通用人工验收范围引用[开发状态](../status.md#当前验收基线)。 |

简单条目见[英姿](generals/standard/wu005.md#wu005-1)。它用一段写出摸牌事件和手牌上限，并指向两项断言。复杂条目见[穿心](generals/shi/qun024.md#qun024-1)，它沿候选产生、请求、变更成功或否则分支展开，并链接来源同步。写清按步骤支付的例子见[骁果](generals/standard/wei016.md#wei016-1)。
