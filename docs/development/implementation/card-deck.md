# 基础牌表：实现与验证

游戏语义见[对应规则](../../rules/card-deck.md)；当前实装与待办见[开发状态](../status.md)。本页保留接口、接线和验收依据，不替代规则裁定，历史覆盖说明不代表已完成全部人工验收。

方天画戟沿用已选国战势备效果，由独立技能 `qiao__halberd_skill` 适配本地引擎：发动扩目标后，【杀】被【闪】抵消时，通过牌效果数据的无效化接口登记全部目标，避免上游调用不存在的 `UseCardData:setNullified` 而报错。扩目标势力筛选、出闪后跳过其余目标、无人出闪时依次伤害及未发动时的隔离行为纳入 `tests/card_reuse.lua` 回归。

正式牌包已登记 162 个基础牌位、12 张替换牌和 7 张特殊加入的势力锦囊。保留独立实体与牌位元数据，逐牌型的既有复用及空壳状态见 `pkg/qiao_cards/data/reuse.lua`。默认套件中的 `tests/card_deck.lua` 验证实体与牌堆构建。

2026-11-18 已确认[锦囊及装备统一采用汉晋版](../../rules/card-deck.md#6-卡牌版本与结算)。现有复用须逐牌按汉晋文本审阅。

州郡领兵印的回合修正和汉晋合纵由 `pkg/qiao_mode/mode.lua` 接入。神授思召经同一合纵入口扩展装备区选牌范围。驺虞幡在实际使用或打出后建立延时效果，血海魔王樽沿原请求核对【酒】合法性，再分别执行协助者的打出和装备者的用牌。

### 势力锦囊

[势力锦囊规则](../../rules/card-deck.md#势力锦囊的结算审阅)通过模式级 `qiao__faction_trick_rule` 接入。正式用牌时以本次用牌数据保存使用者势力条件。移动结算只将势力锦囊实体从本次弃牌堆目的地分出并改至游戏外，保留原移动原因及同批其他牌。

固国安邦以 `askToChooseCardsAndPlayers` 展开本次弃牌，已在真实客户端对象验证选牌和接收者，也通过正常出牌请求验证固定自用目标。党锢之祸通过公开将牌位置筛选与公共暗置事件处理，保护汉晋君主等特殊位置。文和乱武的两类别选牌已覆盖服务端结算。

号令天下、克复中原接入真实嵌套用牌。覆盖号令排除并列最低体力、非魏参与者弃牌后实际出杀、魏参与者取得实际弃置的牌，以及克复的蜀角色用杀伤害 +1 与非蜀角色摸一张。

四海归平接入真实出牌阶段，按当前阶段实例查询实际入弃牌堆的实体，并在结束自由用牌后完成结算。覆盖不分牌仍继续询问晋角色实际用牌，以及后续请求接受合法转化。

洛水之誓接入延时锦囊与公开野心家出现后的诏书候选过滤。立即结算保留目标无效与无懈响应；非区间的重判在下个阶段准备点复核并置回原实体，再替换阶段。覆盖置入后才转野、自用立即判定、目标无效与无懈、改下一阶段并重判、命中但目标非野心家时直接结束，以及公开首次转野后的实际游戏外实体取得。回合内的明置与势力属性变化覆盖已核对，回合外公开转野及绑定阶段被跳过仍待专项验证。

- 定向 `qiao_faction_tricks` 24/24、`card_deck` 24/24、`em_han001_liuxie` 8/8、`second_lord` 34/34。
- `python scripts/test.py --timeout 1800` 默认全量 1,101/1,101。确定化固国安邦的摸牌牌堆及君司马炎首次双亮的剩余将池，保留原结算断言。

### 普通锦囊与装备

首批同步十张印刷牌面，复用接线保留本地牌面和动态印刷标记。重铸仍由原有入口提供。定向 `python scripts/test.py --file tests/card_reuse.lua --timeout 180` 通过 44 项，覆盖三张重铸牌、汉晋牌面以及合纵和应变描述。

远交近攻、联军盛宴及逐近弃远通过复用专项 49/49 和额外目标专项 37/37，覆盖多目标摸牌次数、盛宴逐次混选及无牌目标。青龙偃月刀、五行鹤翎扇、铜雀及黑光铠加入后，复用专项通过 54/54，牌位专项通过 24/24。鹤翎扇使用单实体牌的转化技能，青龙的限制持续到本次用牌收尾。真实客户端界面、联网和重连仍待人工验收。

借刀杀人、护心镜、贯石斧和三尖两刃刀更新后，复用与额外目标专项分别通过 56/56 和 38/38。贯石斧另有 6/6 定向覆盖，含弃置被取消及弃置完成后立即被其他效果取走。君刘协专项 14/14 覆盖敕令从弃牌堆移出、诏书唯一及挟天子的额定回合和支付。调虎离山与玉玺专项 4/4 覆盖了移出保护和归位顺序、用牌与技能限制，以及不同势力同时持有玉玺。

移出期间的技能守卫接在汉晋模式的技能可用性查询、常规触发技消耗前和技能生效前。公共选人、选牌并选人、分牌在服务端预先筛选候选，客户端主动技能入口过滤目标，服务端再拒绝尚带移出者的回复。常规技能的人数、手牌或体力比较统一查询 `room:getPresentPlayers()`。原始存活名单继续用于死亡、复活及胜负等例外。滔乱的回合末选人同时复核发动者与候选是否仍在场。直接读事件对象的固定或延时效果仍须在结算时复核，跨不同移出期限的破军牌归位尚未覆盖。
