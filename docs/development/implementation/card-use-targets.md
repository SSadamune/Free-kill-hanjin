# 效果指定的用牌目标条件：实现与验证

游戏语义见[对应规则](../../rules/card-use-targets.md)；当前实装与待办见[开发状态](../status.md)。本页保留接口、接线和验收依据，不替代规则裁定，历史覆盖说明不代表已完成全部人工验收。

## 实现约定

调用入口应明确传入“沿用原条件”“仅放宽指定限制”或“使用效果自定目标条件”，而非从是否为转化牌、牌名或目标人数推断。界面候选与服务端提交复核须使用同一规则，显式目标条件须与目标数量分别传递。

实现位于 `pkg/qiao_mode/rules/card_use_targets.lua`，房间内筛选代理及宣告复核位于 `skills/card_use_targets.lua`。原牌面条件、仅无距离限制和显式条件三种策略与目标数量分别传递；普通上游国战房间不安装汉晋行为。

【杀】排除用牌者、【桃】排除满体力角色，均由 `extra_targets.meetsIntrinsicTargetRequirements` 检查。普通【杀】与属性【杀】共用牌类判定。显式目标筛选、服务端选择与宣告复核、追加目标候选均保留这些限制。兴图的独立装备转化入口在列选项和筛选时也调用该检查。

【锋械】原先将马隆本人纳入队列目标，又以显式策略替换了【杀】自带的筛选。当时公共资格检查只覆盖【桃】，因此同一队列里的马隆能被自己的【杀】指定。现在交换完成后用 `C.matchesCondition` 筛选队列成员，实际用牌由公共校验复核。见[基础目标资格](../../rules/card-use-targets.md#基础目标资格must)和[锋械实现](generals/zhen/jin023.md#jin023-1)。

用牌为发动消耗或第一个必须执行的动作时，由技能在 `can_use`、`can_trigger` 或列出分支选项时传入实际用牌者、牌与目标。对已知候选可用 `C.matchesCondition` 查询基础资格及显式条件；需要复核完整目标列表时，服务端以 `C.validateTargets` 的 `selection` 阶段检查，并在提交后、支付前再核对实际选项。用牌禁止、材料和时机依当前用牌入口核对。公共校验依据调用方传入的用牌方案，无法从技能描述或 `on_use` 推断后续动作的先决条件。

周仓接入的显式条件增加 `in_attack_range_of = <公开角色 ID>`：目标须在该锚点角色的攻击范围内，距离关系不改用实际使用者计算。条件保持声明式并与目标数量分别传递；选择和执行须沿用同一策略，不能在 `useCard` 时重新套用默认条件。周仓的实牌入口及范围方向回归见[翼从技能](generals/standard/retinue-zhoucang.md#zhoucang)。

## 当前实现核对

### 执行入口与次数

- 汉晋房间由 `slash_use_timing.lua` 按用牌入口识别普通出杀。普通 `PlayCard` 回包只标记直接交给引擎的实体牌或视为牌。用牌过程中的其他【杀】默认不占普通次数，公共请求和目标复核也不受该限制。该次【杀】仍产生真实用牌事件。咆哮、诸葛连弩和应变等原有的牌面效果继续按各自规则处理。依据见[用牌次数](../../../rulebook/topics/card-usable-conditions.md)。
- 技能在发动前需要预览结算中的【杀】目标时，服务端用 `C.effectCandidates` 查询，两端均可用 `C.canEffectUseTo` 检查单个目标。这些接口提供效果用牌的次数语义，目标距离、范围及独立禁止仍用相应规则。
- `askToUseCard` 返回已选择并复核的使用数据，由调用者执行一次。请求的 `names/card_name/name` 是策略白名单，转发给 `Room:askToUseCard` 前必须由公共入口派生引擎 `pattern`（同名转化取 `trueName`，如杀派生 `slash`）；不能只删 `names` 后把 nil `pattern` 交给请求层/AI。
- `explicit` policy 可带 `fixed_targets`（玩家或 ID 列表）。`C.askToUseCard` 在返回前按固定目标复核；目标数量或身份不符即返回 nil，调用方仍需执行一次。固定目标不替代原有牌面目标/禁止检查。
- 真实请求选择/AI 约束使用锁定引擎的 `extra_data.exclusive_targets`（`Card:getAvailableTargets` 按 ID 过滤）；挑衅同时设置该字段和 `fixed_targets`，前者约束选择端，后者保留服务端复核。
- `selectVirtualCard` 强制上游选择阶段 `skip = true`，附加服务端令牌并复核后返回，完全不执行卡牌。公共转换等需把使用数据交回引擎的入口使用此接口。
- `askToUseVirtualCard` 是选择并执行入口：内部先调用 `selectVirtualCard`，验证成功后执行一次 `room:useCard`。包括调用者传入 `skip` 的情况，它都遵循此执行契约；只需选择时必须调用 `selectVirtualCard`，不得再次执行已使用的返回数据。
- `useVirtualCard`／`useCard` 对已构造的使用数据先附加策略并复核，再执行一次。目标不合法、取消或验证失败时不产生使用、移牌及伤害副作用。

### 选择与宣告的两阶段复核

选择阶段通过实际牌技的 `targetFilter`、`feasible`、固定目标及数量限制检查原始选择，并保存服务端选择快照。宣告阶段在引擎执行牌技 `onUse` 之后检查：

- 群体牌、AOE和固定目标可合法展开，不将展开后的目标数量机械套用选择阶段的数量限制。
- 借刀主目标与 `subTos` 分开复核，副目标须符合相应主目标自己的合法杀目标条件；不同主目标可以分别指定同一副目标。
- 原选择中仍存在的角色按原选择条件复核；合法移除的目标不被重新加回，也不再强制满足原始最小数量。
- 展开或新增的主目标使用对应的额外目标规则与上下文；新增副目标独立校验。联军盛宴保留所选势力，即使代表角色后来改变势力也不能切换群体。

两阶段均保留同次请求的距离、次数、固定目标等参数，以及独立的禁止用牌／禁止指定检查。策略令牌与使用者、牌名、请求及原始选择绑定，伪造令牌不能借用或删除其他使用的授权；取消、完成或后续清理时释放授权，嵌套候选查询与异常不残留策略栈。

### 验证与接入边界

`tests/card_use_targets.lua` 与 `tests/extra_targets.lua` 已覆盖默认／无距离／显式策略、两类顺手牵羊的远距离及无牌目标、数量与条件的区别、固定／群体／AOE展开、借刀主副目标、令牌请求绑定、取消及失败无副作用、普通上游房间隔离。

【杀】的基础资格回归覆盖普通及三种属性【杀】，显式条件允许远处的其他角色，候选查询和真实执行入口都拒绝用牌者本人。额外目标回归覆盖声明式和函数式条件。【锋械】验证交换后对队列中其他成员实际结算【杀】。

真实入口回归还包括原技能归属的转换、统领目标不合法时不支付移将代价，以及玉玺 `EventPhaseStart → cost → on_use → 知己知彼 → 查看确认` 的完整流程，检查实际使用及完成事件各一次。内部助手测试不代替这些整链断言。

魏包已接入的代表性入口：神速使用 `bypassDistance` 策略选择并执行一次无距离限制的【杀】；伪溃、驱虎没赢后的【杀】及并州狼骑的【决斗】使用 `explicit` 策略处理效果指定的使用者和目标。技能效果中的用牌不占通常出杀次数；目标策略不额外豁免独立禁止。对应的真实使用、来源与目标断言见[神速](generals/standard/wei008.md#wei008-1)、[伪溃](generals/standard/wei011.md#wei011-1)、[驱虎的用杀分支](generals/standard/wei013.md#wei013-1-outcomes)与[并州狼骑](generals/standard/retinue-bingzhou-langqi.md#bingzhou-langqi)。

本规范不自动为未来技能或任意第三方用牌入口赋予目标策略。新入口须显式接入并补充相应牌的复杂目标回归；人工客户端视觉、联网与重连验收仍待完成。

本轮同类风险核对覆盖 `pkg/` 中全部 `askToUseCard`、`askToUseVirtualCard`、`askToResponse` 调用上下文，包含正式武将、授予技能、翼从及其公共助手。朱儁的无显式 pattern 请求由公共派生修复覆盖；何进与文虎的虚拟牌 name 参数按既有接口处理；其余直接用牌／响应分支已有 pattern，仁德等直接虚拟牌入口使用 name/subcards 契约，未发现其他需修复的同根缺失。该结果属于静态调用核对及代表性真实请求回归，不代表逐将运行了原生 SmartAI 或完成客户端人工验收。

## 自由用牌

风物和四海归平使用 `free_use.askToUseCard`，悖弑在目标策略请求中同样声明 `not_passive`。该请求只给出一次用牌机会，客户端过滤需有响应事件的牌，服务端按请求和现有目标规则复核结果。`askToUseCard` 返回待执行数据，各技能负责执行一次。正式响应窗口沿用现有响应流程。
