# 统领与翼从：实现与验证

游戏语义见[对应规则](../../../rules/commander-retinue.md)；当前实装与待办见[开发状态](../status.md)。本页保留接口、接线和验收依据，不替代规则裁定，历史覆盖说明不代表已完成全部人工验收。

### 公共登记 API

正式内容包或测试内容按以下顺序登记（翼从必须先登记，统领登记时校验其兵种）：

```lua
local C = require "packages.hanjin.pkg.hanjin_mode.rules.commander_retinue"

C.registerRetinue("hanjin__retinue_somekind", { name = "..." })
C.registerCommander("hanjin__somecommander", {
  card = "hanjin__somecard",
  retinues = { "hanjin__retinue_somekind" },
})
```

`registerRetinue` 会把对应武将设为 `hidden`，并调用交换模块的
`Exchange.registerSoldierGeneral(name, "retinue")`；翼从武将本身仍由内容包创建并挂接技能。
`registerCommander` 只登记牌面数据，不创建武将或卡牌。标准包通过这些 API 接入正式统领来源和翼从。

### 识别统领及受益者

以明置的实际主将位或副将位确定统领来源，以国战的当前势力关系（参见 `H.compareKingdomWith`）判断其他角色是否受益，并覆盖统领本人。暗将的真实将名和印刷势力不能用于向其他玩家开放选项。野心家、多势力武将按本模式当时已确定的关系判定。

**能力授权与兵种登记必须分开。** `source.factions` 只表示哪些势力仍可从该来源取得翼从兵种；统领能力只对**来源当前持有者所在势力**开放。暗置迁势力后，旧势力仍可取得兵种，但不能发动该统领能力；明置后能力只随当前持有者所在势力开放。服务端必须在 `buildViewAsCard`/`payCost` 中重新比较来源当前持有者与发动者的势力，不能只检查 `source.factions`。

### 按统领牌保存兵种来源

在房间 tag 中记录每张已提供兵种的统领牌、其最近所属势力和全部兵种。来源以武将牌名为键，随统领牌跨位置追踪；暗置、移除或持有者死亡时继续保留势力登记。变更势力时只迁移这一来源；按势力汇总各来源的兵种并去重供玩家选择。统领明置或转入时检查相应势力，普通角色加入时检查其两个位置，新取得士兵时检查取得的位置。这些入口共用逐位置转换流程，只处理白板士兵。

### 沿用国战移将结算

选定统领、牌名、代价位置及合法用牌方案后，调用 `H.removeGeneral(player, isDeputy)`。锁定实现会明置所选位，处理 `H.GeneralRemoving`、原将技能移除、士兵占位、原将回将池及 `H.GeneralRemoved`。支付成功的判断是所选位置从原武将变为士兵；该士兵可能在同一次结算中立即转为翼从。取消选择或移除被阻止时不生成用牌。其他产生士兵的汉晋效果也接入同一授予逻辑。

### 手动视为技

发动提示直接使用“移除一张不为{统领姓名}的武将牌，视为使用【{牌名}】。”，省略统领姓名前缀及发动前置条件；完整条件仍在技能一览中说明。

统领标注的花色与应变条目须落实到实际视为牌，并在来源按钮、技能说明与发动提示中完整显示。例如司马师提供红桃【出其不意】，具有“助战→目标+1”；该条目由汉晋应变 API 赋予，只属于此统领构造的牌，不自动附加给其他同名牌。

统领标注的使用修正同样须落实到实际用牌判定。例如祝融夫人提供的【杀】无距离限制，仅豁免该统领牌的距离检查，其他用牌限制照常处理。

统领来源按钮组位于读条及说明文本正上方，横向排列并整体居中；超出可用宽度时可横向滚动。

始终区分统领能力与翼从效果。技能一览须按实际来源分别展示对玩家生效的统领能力和翼从效果，写明统领姓名、牌名、移将限制及翼从兵种。发动、选目标及移将代价提示仅描述当前激活的统领能力，不附带翼从效果；提示随激活来源切换。能力限一与偏将限一分别说明，已无可得翼从时不得继续承诺取得该偏将。描述只使用已同步的公开来源信息，保留暗置、跨势力迁移后翼从兵种存续的既定规则。

参考新月杀视为技的 `addEffect("viewas", { ... })` 方式，由可见的 `hanjin_commander_ability`（“统领”按钮）统一提供：

- 玩家通过“统领”按钮选择当前可发动的统领来源；`@[hanjin_commander_sources]` 保存客户端可读取的来源列表，并在界面中隐藏内部标记。该列表只列出**来源当前持有者与玩家同势力**、来源已明置、且自己主副将位均无士兵的角色。
- **入口可用性。** “统领”按钮仅在至少一项能力同时满足以下条件时可点击：存在合法可用的统领来源、存在可为该来源移除的武将牌、当前时机允许视为使用对应牌。当前用牌合法性应使用新月杀视为技的判定路径，涵盖使用/响应窗口、次数及禁止使用；不预先检查是否存在合法目标。目标距离、禁止指定及其他目标限制在进入用牌界面后的选目标与确认阶段检查，未形成合法用牌方案时不能确认，也不支付移将代价。仅存在来源标记不足以开放按钮。
- **同屏选择。** 点击“统领”后，在当前用牌与目标选择界面直接显示全部当前可发动的能力按钮，不再另弹来源选择窗口。按钮文字为“统领武将·牌名”，如“张辽·杀”“赵云·无懈可击”；限一能力附“（限一）”，如“关羽·酒（限一）”。限一说明取自统领能力自身的限制，不能以翼从是否限一代替。
- **默认与切换。** 能力列表按稳定顺序排列，首项默认激活；玩家未切换时使用该首项。点击其他能力按钮立即改变激活项、视为牌与合法目标范围。无目标牌依本身规则确认，有目标牌可在同一界面选择合法目标并确认；切换后重新校验已选目标，不得沿用对新牌非法的目标。
- **客户端路径。** `view_as` 在客户端执行时只能使用客户端已有的可见标记和全局牌面登记（`C.commanders`、`Fk:cloneCard`）构造虚拟牌，并在牌上记录来源；不得读取服务端房间 tag。客户端选择多个来源时，按所选来源键使用其标注牌。
- **服务端复核。** `before_use` 在服务端重新读取房间来源记录，核验来源键与牌面一致、来源仍明置、当前持有者与发动者同势力、无士兵条件、代价候选和支付结果；支付失败或来源失效时返回技能名取消用牌。客户端构造的牌和来源标记不能替代这次复核。
- 只在主动使用和询问「使用」的窗口开放；询问「打出」的纯响应窗口不开放。
- 无懈可击属于「使用」而非纯「打出」：`enabled_at_nullification` 在某个来源确实能形成合法无懈牌时开放（来源牌为 passive 的 `nullification`，并与当前响应 pattern 匹配）；不会因为来源牌不是无懈而伪造，也不恢复纯「打出」授权。

### 翼从卡面、技能与士兵身份

- **卡面。** 每个兵种在汉晋扩展内注册独立的特殊武将，提供武将 ID、兵种名称、立绘和技能说明。选兵时使用 `Room:askToChooseGeneral` 的通用武将卡面，可查看各候选的卡面和技能。选定后同步对应位置的武将 ID 与国战位置记录，使本人和其他玩家在桌面及武将详情中看到该位的翼从。
- **排除普通将池。** 翼从武将设为 `hidden`，并在模式选将前从 `general_pile` 排除；被移除时也从普通将池清理，不作为普通武将回收。
- **技能。** 技能属于翼从所在的主将位或副将位，由服务器按技能类型执行。转换通过 `changeHero` 且不重算体力上限、不改变当前势力和体力，避免重复触发原武将的移除结算。
- **国战兼容。** 普通士兵使用 `blank_shibing` 或 `blank_nvshibing`；公共规则同时识别 `blank_` 前缀和已登记的翼从。翼从通过 `Exchange.registerSoldierGeneral` 登记为 `retinue` 类士兵，交换模块不凭前缀猜测。

## 与交换模块的接口

交换模块由 `pkg/hanjin_mode/rules/general_exchange.lua` 提供；统领模块不再自行模拟一次武将交换。双方约定如下：

1. 交换模块在**双方新位置全部就绪、技能与牌堆都同步完成后**调用 `Exchange.addCompletionListener(fn)` 注册的监听器，参数为 `(room, context)`。
2. `context.sides` 每项含 `player`、`isDeputy`、`previous`、`general`；`context.obtained_soldiers` 列出本次交换到新位置的白板士兵，含 `player`、`isDeputy`、`general`。
3. 统领模块在同一个监听器中先完成来源迁移，再统一处理白板士兵转换：
   - 若新位置是已明置统领，来源改记到新持有者和新势力；旧势力与新势力不同时移除旧势力登记、加入新势力登记。
   - 若统领只是被换走，最终位置复核确认其不再位于持有者任一位置时，停止提供统领能力，但保留原来的势力登记和兵种。
   - `obtained_soldiers` 中的白板士兵按「新位置获得士兵」处理，在所有来源就绪后按新势力转换。
4. 交换模块自身负责明置限制、同势力限制、技能次数/牌堆/体力上限迁移；统领模块只读取 `context`，不重复改写武将、技能或牌堆。
5. 若某个特殊效果绕过上述入口直接移动武将，统领模块的明置、暗置、势力变化和武将移除监听仍会独立处理；但跨势力交换必须以完成监听器作为原子结算入口，否则可能出现提前转换。

## 自动化验收

运行 `python scripts/test.py`；`tests/commander_retinue.lua` 已纳入 `tests/all.lua`。测试只使用独立测试内容，不创建正式武将或卡牌。

覆盖：统领/翼从登记与士兵识别、翼从隐藏与技能、无士兵条件、主将/副将统领分别明置、明置转换、多兵种自选与同兵种双位置、单兵种直接转换、已有翼从保留、暗置/移除/死亡后兵种仍存续、明置与暗置跨势力迁移差异、旧势力仅得兵种而不能发动能力、多来源同类及同牌名来源匹配、代价排除提供能力的统领、真实客户端 `view_as` 路径、服务端同势力/牌面与来源键复核、无懈可击使用窗口与纯打出禁止、翼从技能触发及清理、交换完成监听器中的统领迁移和白板获得。
