游戏语义见[对应规则](../../rules/faction-ban.md)；当前实装与待办见[开发状态](../status.md)。本页保留接口、接线和验收依据，不替代规则裁定，历史覆盖说明不代表已完成全部人工验收。

## 7. 实现位置与公开状态

| 内容 | 文件/接口 |
| --- | --- |
| 三个模式的注册、模式判定与房间设置 | `pkg/qiao_mode/init.lua`、`modes.lua`、`mode.lua` |
| [锁定投胎分配与发将](mode-rules.md#锁定投胎) | `pkg/qiao_mode/rules/locked_factions.lua` |
| 纯势力筛选、候选/上限校验、未来势力登记 | `pkg/qiao_mode/rules/faction_ban.lua` |
| 版本池、效忠版开局计划 | `pkg/qiao_mode/rules/general_versions.lua`、`general_pool.lua` |
| 选将请求、格式检查 | `pkg/qiao_mode/rules/selection.lua` |
| 卡牌归属登记、牌堆策略 | `pkg/qiao_mode/rules/cards.lua` |
| 同房间跨局数据 | `pkg/qiao_mode/rules/session.lua`、`skills/session_history.lua` |
| 正式内容包 | `pkg/qiao_generals`（90 张可选武将，另有 14 种翼从）、`pkg/qiao_cards`（完整独立牌表，包含基础牌位、替换牌及游戏外势力锦囊） |

当前模式注册完成，正式牌包已登记 162 个基础牌位、12 张替换牌及 7 张特殊加入的势力锦囊；67 个牌型已复用或适配，17 个牌型仍为空壳。正式将池已接入标准包，武将与翼从技能的当前完成度见[开发状态](../status.md)。房间可创建条件会拒绝内容不足的配置，不会自动使用上游将池或牌堆。

大合集在游戏设置中禁用选将数目、选将时长、手气卡次数和副将机制。FreeKill 0.5.25 的 Windows 发行包没有「选将与操作时长联动」开关。上游棋盘提供这个开关时，大合集也将其禁用。大合集的实际候选数与时长取自「模式设置」，房间未设置选将时长时，服务器采用 90 秒。自由模式沿用上游棋盘的设置。

## 8. 自动化验收

执行 `python scripts/test.py`。默认套件包括上游流程回归、纯规则测试及独立汉晋场景。

- 默认六候选/上限 4 时禁二；自定义 3 候选/上限 3 时不禁；自定义 5 候选/上限 3 时禁二；候选少于上限时按候选数。
- 候选势力、上限、每势力开关的默认值与动态范围；旧房无新设置键时按默认六势力/4 兼容。
- 非法候选（空、未知、重复、非布尔开关）与非法上限（0、负数、非整数、超过候选数）被拒绝；初始化失败不静默降级。
- 未来第 7/8 势力可通过登记加入候选且不改变默认六势力；候选外武将不可选；将池缺失或仅客将出现的候选势力仍合法。
- 上一局胜利势力必禁、上局被禁势力必留；上局记录指向本局候选外时忽略；候选数不超过上限时上一局也不额外禁选。
- 双势力任一势力允许就保留；初始势力必须属于合法交集。
- 野心家默认四名、设为零、数量少于上限；从公共将池与已选武将合计检查上限。
- 经真实 `Request` 的取消/超时默认回复与非法回复均能得到合法双将。
- 连续两局中，上局胜利势力被禁，上局被禁势力保留。锁定投胎在固定分配前运行大合集的禁选，并记录该步骤的禁选结果。切换至其他国战或其他游戏模式时清除记录。不同房间的记录独立。
- 大合集只有汉、晋候选开关及禁用势力复选框。自由模式保留逐势力开关、可调上限和原有附加规则。锁定投胎在开局确定两个势力。三个模式共用正式分包筛选。
- 君主装备成对替换、赤霄剑只增删、临筱玉舆与绝影互换、势力锦囊禁用。
- 汉晋场景中的每张实体卡与每名可选武将都来自独立汉晋包，原版内容被白名单排除。

测试数据位于 `tests/support/qiao_content.lua`，仅在测试进程中登记独立无效果对象；不被 `init.lua` 引用、不进入发布同步内容，也不代表首批正式武将或卡牌设计。上游回归测试单独使用参考内容，不作为汉晋游戏内容。

本轮未人工验收界面、联网和断线重连；装备具体效果及双坐骑栏位交互属于后续正式卡牌实现验收。
