# 主动技、用牌与目标：跨势力机制实现与验证

本页汇总汉、魏、吴三包中涉及出牌阶段主动技、效果指定用牌、目标与距离处理的技能实现、接口接线与真实验证状态，不替代规则条文。逐将检索见[汉势力标准包](han-standard.md#1-分组与逐将入口)与[魏势力标准包](wei-standard.md#1-分组与逐将入口)；整将记录按主要机制放入对应组，其他组只以锚点引用，不复制正文。

## 魏势力标准包

本页记录[标准武将表](../../../../rules/standard-generals.md)魏区 WEI010 长驱、WEI011 伪溃、WEI012 强袭、WEI013 驱虎的程序接线与验收范围，不是正式规则条文。

### 本轮实质修正

1. **伪溃私看**：`room:showCards(hand, player)` 是全体展示，已改为真实私看 `room:viewCards(player, { cards = hand, skill_name = ..., prompt = ... })`。测试记录 `viewCards` 的收件角色与牌集，防止以 mock 通过保留泄露。
2. **长驱事实层**：不再使用私有 `room:getTag`。新增 [wei_history.lua](../../../../pkg/hanjin_mode/rules/wei_history.lua)（公开标记 `hanjin_wei_damage_targets`、记录/清空/查询）与 [wei_damage_history.lua](../../../../pkg/hanjin_mode/skills/wei_damage_history.lua)（模式级全局 `fk.Damage` 记录器）。`mode.lua` 在 `logic:start` 前安装记录器，因此与长驱武将是否已选、明置或之后换将无关。记录器只把“目标 id 集合”写入同步玩家标记（`room:setPlayerMark`），客户端与服务端 `targetmod` 读同一公开数据，不在客户端回调里读取 server history；每回合开始清空，仅在真实伤害（`data.damage > 0`）后刷新。
3. **费用可用性**：伪溃的 `can_use` 要求 `player.hp >= 1`；强袭要求体力至少 1，或拥有可弃武器牌。失去体力的消耗不得超过当前体力，不把有可弃武器的强袭一并限制为体力至少 1。
4. **驱虎没赢**：拼点 `winner ~= player`（含平局/空结果）走真实视为【杀】分支；新增平局测试验证对手为使用者、发动者为目标并承受伤害（伤害来源为对手）。
5. **鹰视**：新增 `skill_wei002_2.lua`，见 [鹰视实现与验证](retrial.md)。

### 接线要点

1. **长驱**：`targetmod.bypass_distances` 只对公开标记中“本回合未被该来源伤害过”的目标返回真，不修改距离本身；事实由模式记录器负责，技能本身不再记录。
2. **伪溃**：出牌阶段限一次；失去 1 点体力→私看目标手牌；有【闪】则按公共 `explicit` 目标策略视为【杀】，距离固定只对“发动者 → 目标”单向生效（`-turn` 标记）；否则弃置其一张手牌。
3. **强袭**：出牌阶段每目标一次（`-targets-phase` 表标记）；目标先按当前攻击范围确定，再弃武器或失去 1 点体力，然后造成 1 点伤害。
4. **驱虎**：拼点赢→对手为来源、对其攻击范围内由你选择的角色造成 1 点伤害；没赢（含平局）→对手视为对你使用【杀】（`extra=true` 不计次数、显式目标策略）。

### 测试（[wei_active.lua](../../../../tests/wei_active.lua)，已由整合方加入 all.lua）

夹具已改为明确白板双将：`support.initHanjinRoom()` 后统一替换为 `hanjin_test__wei_1/2`，写入 `__heg_general/__heg_deputy`、势力与 `__heg_*` 标记，并用 `getGeneralMaxHp()` 重算 `maxHp/hp`；显式设置当前角色与出牌阶段。这样避免随机真实双将的技能在嵌套【杀】时插入额外询问。

1. 长驱：不授予长驱时，模式记录器仍写入同步标记；距离不变；`TurnStart` 清空。
2. 强袭：无武器时失去体力并对攻击范围内目标造成 1 点伤害，写入每目标标记。
3. 伪溃（无【闪】）：真实私看请求后弃置目标一张手牌，输入回复走 `FkTest.setNextReplies`；收件人与牌集的专门断言在有【闪】用例中覆盖。
4. 驱虎（赢）：赢的伤害来源为对手；该用例仍以测试桩固定拼点结果，属输入夹具。
5. 伪溃（有【闪】）：恢复真实【杀】分支。私看通过包裹原 `room:viewCards` 记录参数（仍调用真实实现），检查发动者收到目标手牌；目标不打出【闪】，真实 `CardUseFinished` 记录显示恰好一次来源为发动者、目标为该角色的【杀】，并验证失去体力、目标受伤与距离标记。
6. 驱虎（平局）：恢复真实拼点与真实【杀】。双方各出一张同点数牌经官方回复队列完成拼点；随后对手视为对发动者使用【杀】，验证恰好一次真实使用、来源为拼点对手、目标为发动者，发动者受伤而对手不受伤。

### HAN005 何进：谋诛、构难实现与验证

最终集成复核（2026-11-13）：本文件对应实现已纳入默认套件，DSH 工具原生检查确认 564/564 通过，发布包内容经核对。以下“未运行”“待集成”等表述如有保留，指前期阶段交回记录，不代表最终自动化状态；逐项客户端、联网／重连及干净本体安装人工验收仍未完成。统一结果见[汉势力标准包总览](han-standard.md)。

游戏语义见[标准武将表](../../../../rules/standard-generals.md)汉区 HAN005；本页记录接口、接线与验收依据，不替代规则裁定。当前完成度由[开发状态](../../status.md)统一登记。

#### 1. 实现结构

- `pkg/hanjin_generals/skills/skill_han005_1.lua`：谋诛，出牌阶段主动技。
- `pkg/hanjin_generals/skills/skill_han005_2.lua`：构难，死亡触发 + 房间级常驻伤害监听。
- 两个骨架均显式赋 `hanjinImplemented = true`，不改 `init.lua` 白名单或 `data/`。

#### 2. 谋诛

- 出牌阶段限一次（效果 `max_phase_use_time = 1`，自定义 `can_use` 内同时检查阶段次数）。
- 目标只要求一名其他存活角色，不把“交牌能否执行”当作目标限制或何进消耗。交牌由被令角色选择一张手牌，再以 `moveCardTo(..., fk.ReasonGive, ...)` 交给何进；目标无手牌时交牌不执行，但继续“然后”的手牌比较与可执行效果。
- 交牌后比较双方**当前手牌数**；仅当目标手牌数小于何进时，目标视为使用一张【杀】或【决斗】。使用入口为 `card_use_targets` 的 `askToUseVirtualCard`，目标由使用者按正常牌面目标条件选择，不添加技能指定的目标例外；虚拟牌默认 `extraUse`，不计通常次数。
- 使用后遍历实际目标，若任一目标与何进势力相同（`compareKingdomWith`），使用者弃置一张牌；无牌则不弃。
- 非法/过期交牌回复会在服务端按当前手牌复核，不移动不属于目标的牌。

#### 3. 构难

- `fk.Death` 触发：死亡时按公共死亡数据取 `data.killer`。无来源不建立印记；来源已死也照常记录，后续不复结算。暗将死亡先经公共 `GameOverJudge` 翻正，再触发。
- 印记为 `hanjin_skill_han005_2_source-noclear`：不带技能名双下划线前缀，避免 Exchange 按来源技能迁移；`-noclear` 使其不随死亡清标记消失，移将、失技、暗置后均已建立的印记持续。
- 伤害监听为房间级延迟技能（`DamageInflicted` + `global`），在获得构难时安装，并在死亡建立印记时再次确保存在；不依赖死者当前 `hasSkill` 门，因此何进死后仍生效。
- 只认正式普通杀牌名 `hanjin__slash`，排除火/雷/冰杀；不以普通伤害属性代替牌名判断。印记角色作为伤害来源（造成）或受伤者（受到）两个方向都加 1，每次伤害事件只加一次。

#### 4. 验证范围

定向套件 `tests/han005_hejin.lua`：

| 用例 | 核心断言 |
| --- | --- |
| 谋诛·异势力目标 | 目标交牌后手牌数小于何进，视为使用【杀】；目标为魏，不弃牌；何进得到交来的牌 |
| 谋诛·同势力目标 | 相邻 p2 明确为汉势力且已明置；p3 对 p2 使用【杀】并真实造成 1 点伤害，目标与何进势力相同，p3 交牌后再弃掉剩余手牌 |
| 构难·普通杀双向 | 暗将何进死亡后来源获得常驻印记；来源造成/受到普通杀伤害各 +1 |
| 构难·属性杀排除 | 同一来源受到火杀伤害仍为 1 |

公共出牌、用牌目标条件、死亡翻正与清牌流程复用现有覆盖；测试通过真实出牌阶段、`room:useCard` 与 `room:killPlayer` 触发，不只手调 `on_use`。同势力用例的【杀】目标必须合法：不修改谋诛的距离/目标规则，改用与 p3 相邻的汉势力 p2，并以实际伤害作为“杀已真实使用”的前置证据。

#### 6. 未覆盖与风险

- 谋诛目标交牌后若没有任何合法【杀】/【决斗】目标，`askToUseVirtualCard` 返回空，后续弃牌也不发生；这是正常牌面条件的结果，不额外补问。

### HAN009 伏完：谋溃实现与验证

最终集成复核（2026-11-13）：本文件对应实现已纳入默认套件，DSH 工具原生检查确认 564/564 通过，发布包内容经核对。以下“未运行”“待集成”等表述如有保留，指前期阶段交回记录，不代表最终自动化状态；逐项客户端、联网／重连及干净本体安装人工验收仍未完成。统一结果见[汉势力标准包总览](han-standard.md)。

#### 1. 范围

- 谋溃：`pkg/hanjin_generals/skills/skill_han009_1.lua`
- 定向用例：[tests/han009_fuwan.lua](../../../../tests/han009_fuwan.lua)

#### 2. 实现要点

- `TargetSpecified` 是每个目标分别生成的时机；谋溃在本次 `UseCardData` 上写入
  已发动标记，因此一张【杀】只发动一次，不会为每个目标重复询问。
- 发动者在本次【杀】的目标列表中选择**一个**目标，再通过 `askToChoices`
  选择一至两项：摸一张、弃置该目标一张牌。执行顺序固定为先摸后弃。
- 双选时在 use 上记录被选目标 id 与“双选”标记；抵消监听器只在
  `CardEffectCancelledOut` 的当前目标正是该目标时触发，其他目标抵消不触发。
  触发后由抵消者选择并弃置伏完一张手牌/装备牌。
- 反弃监听器是模块缓存的房间级对象，使用本次 use 已建立的标记，不依赖伏完
  当前是否仍有谋溃；失技/暗置后双选后续仍结算。
- 无「挂载」式额外技能，也没有为每个目标复制一套谋溃效果。

#### 3. 测试状态与未覆盖

**测试待基础组统一执行。** 本轮未启动 FreeKill、未运行测试，不能视为通过。

- 双选后被选目标用【闪】抵消，弃置伏完一张牌；
- 多目标【杀】中，未被选中的另一目标抵消时不反弃；一张【杀】只发动一次。

未覆盖/需基础组确认：
