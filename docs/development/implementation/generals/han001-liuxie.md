### 核心行为：本轮必须验证

| 验收组 | 合并场景与结果 |
| --- | --- |
| 天命弃摸 | 可弃手牌为 0、1、2、超过 2 张及含禁弃牌时，弃 min(2,K) 张后摸 2 张；只用手牌；拒绝发动不弃不摸 |
| 天命触发时机 | 普通／属性／视为杀均识别；成为目标后、响应前弃摸，新摸的闪可响应；同一张杀的额外结算不再次触发 |
| 密诏交牌与限次 | 自己出牌阶段空闲时间点每阶段一次，最低 max(1,X)，可交手装；取消不计次，支付后无法拼点仍计次且不退牌 |
| 密诏势力数 | 同势力去重、排除自身、未知与死者不计、野心家各自独立；客将或改势力按实际状态处理 |
| 密诏分步选择 | 先交牌再选第三人，排除 A、B；B 可因收牌获得拼点资格，无合法对象则结束 |
| 拼点结果 | B 赢、C 赢、平局三种；采用最终点数，平局无杀；赢家是用牌者及默认伤害来源 |
| 后续杀的接线 | 无实体子牌普通杀，只使用一次；不受且不计通常次数、不叠加距离，独立禁止使用／指定仍生效 |
| 国战技能来源 | 两技能各保留代表性的主副将／暗置集成验证；自写的明置后势力预测须与汉晋公共流程一致，不能仅通过直接授予明将技能的夹具验收 |
| 双技能联动及隔离 | 密诏生成的杀可正常触发目标的天命，原杀继续结算；汉晋测试不污染普通房间 |

### 公共机制：复用覆盖，验证接线

- 正常闪响应、防具、伤害、拼点牌去向、阶段历史与普通牌移动以现有公共套件为基础；本技能只保留必要的真实流程集成验证，不为每种牌／每种座次重复编写一套。
- 技能失去、无效、武将交换／移除优先复用公共来源机制的覆盖。若技能新增自行缓存、预测或特殊分支，针对该分支补测。
- 最终仍运行默认 `python scripts/test.py`；开发轮次先用已有专项入口验证。

### 风险边界：有具体问题再补

- 弃牌／交牌连锁导致中途死亡、牌移动被特殊效果替代、拼点后死亡或技能消失。
- 断线、超时、过期与伪造选择、重复目标等，优先依公共服务端复核；技能自行绕开公共入口或发现漏洞时补针对性回归。
- 少见多技能叠加或特殊国战组合，不作无依据的全排列验收。

新增修改继续按风险分层验证，不要求完整场景映射；扩大协作范围时按项目约定交回审阅。

## 6. 实装与验收边界

- 客户端报错回归：刘协搭配徐晃、明置副将后进入自己的回合时，密诏按钮检查曾因 `ClientPlayer` 没有 `room` 字段而崩溃。现已改为兼容引擎当前客户端房间；新增无 `room` 的真实 `ClientPlayer` 回归，覆盖已确定势力与暗置自身势力预测下的交牌下限、可用性和提示。该自动化回归不代替客户端完整交互的人工验收。
- 提示与选择交互：天命提示使用“弃置两张手牌（不足则全弃，无牌则不弃）”和“请弃置 %arg 张手牌”；密诏后续提示为“选择参与拼点的另一名角色”。密诏收牌者切换由扩展内 `pkg/hanjin_mode/client.lua` 的汉晋专用请求处理器实现，经引擎客户端注册接口接入，随安装包发布，不依赖本地本体适配；其他技能沿用原请求流程。
- 独立汉晋天命、密诏及专项测试已实现并通过自动化回归。客户端人工验收、文中仍标为建议的边界及密诏君主预测的独立运行时用例尚待补充，不宣称全部边界已独立验证。规则文档由 Codex 维护，DSH 默认只读。
