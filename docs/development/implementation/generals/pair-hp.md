# 配将体力：跨势力技能实现与验证

本页记录[配将体力规则](../../../rules/general-principles.md#配将体力贡献与武将状态)的开局和升变接线，以及魏、晋司马懿共用的应期。

## 双 2.5 体力贡献

`pair_hp.lua` 在上游开局广播后将双 2.5 组合的体力上限和体力修正为 4，在已有的 `HalfMaxHpLeft` 记录两枚待领阴阳鱼。双亮时，汉晋规则在上游单枚奖励前发放两枚并清空待领记录。升变使用同一数量查询。原生用例用正式皇甫嵩与关羽，经开局广播及两次明置验证首亮不发、双亮发两枚。

## 技能条目

### 魏

<a id="wei002-3"></a>
#### 应期（WEI002 司马懿；JIN009 同文共享）

- **标识与依据**：
  - 运行时 ID：唯一规范 ID 为 `qiao__skill_wei002_3`，源码 [skill_wei002_3.lua](../../../../pkg/qiao_generals/skills/skill_wei002_3.lua)；晋 JIN009 直接引用同一 ID，不再另设骨架。两处卡面文本统一为魏文本（“☯️+2”），避免同 ID 翻译相互覆盖。晋应期在本页只记录来源，不另写正文。
  - 规则见[应期裁定](../../../rules/generals/wei002-simayi.md)、[JIN009 同文引用](../../../rules/generals/jin009-simayi.md)与[配将体力贡献通则](../../../rules/general-principles.md#配将体力贡献与武将状态)。业务文件：[pair_hp.lua](../../../../pkg/qiao_mode/rules/pair_hp.lua)、`mode.lua`、`rules/ascension.lua`、应期骨架（两版共用一份）。
- **实现与接口**：
  - 数值表示：引擎以**半格**保存体力贡献（1.5 体力记作 `3`，2.0 记作 `4`，2.5 记作 `5`）。国战双将体力上限为 `((主将贡献 + 主将调整) + (副将贡献 + 副将调整) + 应期半格修正) // 2`；半格合计为奇数时 `HalfMaxHpLeft` 标记为 `1`，表示 1 个“半个阴阳鱼”。应期的“☯️+2”是 **2 个半格**（1 点体力上限），不是两枚可消耗的阴阳鱼标记，因此不发放 `@!!yinyangfish` 或 `qiao_ascension_yinyang` 等标记，只在开局把组合上限补 1 点，并沿用引擎写入的奇偶余数标记。
  - 身份判定：`qualifies(name, room)` 保留牌面多主势力，用 `Guest.isGuest(room, name)` 识别客籍本局是否实际生效。仅登记客籍、仍以单一主势力配将时无修正。开局和升变都传入当前房间。同一配将组合由 `yinyang` 返回一次修正。
  - 开局：`mode.lua` 在上游 `HegLogic:broadcastGeneral` 后调用 `PairHp.apply_start`，按实际配将的贡献差值更新体力，补齐待领标记。应期保留牌面和配将用技能标识，骨架没有触发效果，暗置时不提供预亮按钮。
  - 升变：`rules/ascension.lua` 的 `pair_max_hp`、实际主副将读取与阴阳鱼奇偶判断改由 `pair_hp.lua` 提供；升变前后组合上限都按含应期的公式计算，所以“同体力主将升变”不会被误判为上限增加；升变收益仍按原公共流程（新组合上限更高时加 1 点上限并回复 1 点体力）。
  - 不重算：普通交换、移除、替换不调用 `apply_start`／`pair_max_hp`，已确定的体力上限不变；开局后属性变化不会撤回或追加应期收益。
  - 客户端与模式隔离：应期不新增客户端交互或私有字段；`maxHp`、`hp`、`HalfMaxHpLeft` 都是引擎已有公开属性／标记。只在 `qiao_heg_mode` 的 logic 上覆盖 `broadcastGeneral`，不修改上游 `hegemony` 包或其他模式。
- **验证依据**：[wei_pair_hp.lua](../../../../tests/wei_pair_hp.lua) 以开局广播验证魏未禁时曹操搭配司马懿上限为 3、曹操客籍实际生效时两个版本的司马懿搭配均为 4、原牌面多势力的认定，以及升变继续使用同一体力计算入口。应期修正不发放可消耗的阴阳鱼。
- **未完成与边界**：自动化已通过；客户端进房及联网／重连人工验证尚未完成。“普通交换后升变”的组合比较沿用既有实现（比较升变前后的组合上限公式），不改比较实际 `maxHp`；若规则要求以实际上限为基准，需另轮裁定并补测试。若将来出现独立应期君主版／效忠版但使用不同技能名，需要把技能名登记到 `pair_hp.M.YINGQI_SKILLS`。开局广播路径已有正式房间与专项自动化覆盖；不设 GameStart 重算作为回退，新增开局加载路径时应复核仍经过该模式接线。
