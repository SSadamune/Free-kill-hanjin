# 拼点：跨势力技能实现与验证

本页是“拼点”机制的主记录页：发起拼点、拼点结果分支、拼点牌取得与点数修正。不替代规则条文，规则冲突时以 `rules/` 与 `rulebook/` 为准。范围边界：以拼点流程或其结果为技能核心的技能；拼点之外的用牌目标问题归[用牌目标与距离](active.md)，伤害结算归[伤害、体力与死亡](damage.md)。共享命令输出见[共享验证证据](verification-evidence.md)。

#### 密诏（HAN001 刘协）

- **标识与依据**：运行时 ID `hanjin__skill_han001_2`；源码 [skill_han001_2.lua](../../../../pkg/hanjin_generals/skills/skill_han001_2.lua)。规则见[刘协规范](../../../../rules/generals/han001-liuxie.md)。同将天命见[辅助与牌资源](support.md#han001-1)；规范化描述待办同时覆盖天命与密诏，见该条目。
- **实现与接口**：
  - 自己出牌阶段空闲时间点每阶段一次，最低 `max(1,X)`，可交手牌或装备牌；取消不计次，支付后无法拼点仍计次且不退牌。
  - 势力数：同势力去重、排除自身、未知与死者不计、野心家各自独立；客将或改势力按实际状态处理。
  - 分步选择：先交牌再选第三人，排除 A、B；B 可因收牌获得拼点资格，无合法对象则结束。密诏收牌者切换由扩展内 [client.lua](../../../../pkg/hanjin_mode/client.lua) 的汉晋专用请求处理器实现，经引擎客户端注册接口接入，随安装包发布，不依赖本地本体适配；其他技能沿用原请求流程。
  - 拼点结果：B 赢、C 赢、平局三种；采用最终点数，平局无【杀】；赢家是用牌者及默认伤害来源。
  - 后续【杀】接线：无实体子牌的普通【杀】，只使用一次；不受且不计通常次数、不叠加距离，独立禁止使用／指定仍生效。
  - 国战技能来源：两技能各保留代表性的主副将／暗置集成验证；自写的明置后势力预测须与汉晋公共流程一致，不能仅通过直接授予明将技能的夹具验收。密诏君主预测的独立运行时用例尚待补充。
  - 客户端报错回归：刘协搭配徐晃、明置副将后进入自己的回合时，密诏按钮检查曾因 `ClientPlayer` 没有 `room` 字段而崩溃；现已改为兼容引擎当前客户端房间，并新增无 `room` 的真实 `ClientPlayer` 回归，覆盖已确定势力与暗置自身势力预测下的交牌下限、可用性和提示。该自动化回归不代替客户端完整交互的人工验收。
  - 提示与选择交互：密诏后续提示为“选择参与拼点的另一名角色”；界面还须检查 X 与交牌下限、收牌者与拼点对象的分步选择及平局提示。
- **验证依据**：[han001_liuxie.lua](../../../../tests/han001_liuxie.lua) 保留天命、密诏的核心行为、公共机制与风险边界记录；原记录中的验收组（交牌与限次、势力数、分步选择、三种拼点结果、后续【杀】接线、双技能联动及隔离）属于该专项的分层组织，不记作 han_standard_pindian 的覆盖。历史执行见[共享验证证据](verification-evidence.md#汉区)。
- **未完成与边界**：风险边界包括弃牌／交牌连锁导致中途死亡、牌移动被特殊效果替代、拼点后死亡或技能消失；断线、超时、过期与伪造选择优先依公共服务端复核；少见多技能叠加或特殊国战组合不作无依据的全排列验收。新增用例应加入 `tests/all.lua` 的默认国战套件。继续以已确认规则核对现有独立汉晋实现；可参考锁定上游国战流程及 Qsgs-Fans/SP 的天命、密诏源码，但须适配本项目差异，不直接挂接其他版本同名技能。现有实现参考：锁定 `hegemony` 的国战技能来源／明置流程；本地引擎 `ltk/core/player.lua` 的 `canPindian`；`ltk/server/events/pindian.lua` 的拼点结果流程——只用于核对接口，不替代用户规则裁定。界面人工验收与规范化描述仍待完成。

#### 惴恐（HAN008 伏皇后）

- **标识与依据**：运行时 ID `hanjin__skill_han008_1`；源码 [skill_han008_1.lua](../../../../pkg/hanjin_generals/skills/skill_han008_1.lua)。规则见[伏皇后规范](../../../../rules/generals/han008-fuhuanghou.md)。同将求援见[用牌目标与距离](active.md#han008-2)。
- **实现与接口**：
  - `EventPhaseStart` 全局监听其他角色的准备阶段；伏皇后已受伤且可与该角色拼点时，通过正规 `can_trigger/on_cost/on_use` 发动。`createTriggerSkill` 会用 `can_trigger` 覆盖基类 target 门槛，因此不需要 refresh／`room:useSkill` 代理；正常明置来源并记录技能发动。
  - 伏皇后赢：给该角色加本回合 `no_damage` 延迟标记；房间级 `DamageCaused` 监听器按标记把该角色造成的伤害防止，监听器不依赖伏皇后之后是否仍有技能。
  - 没赢（含平局）：该角色可选择视为对伏皇后使用【杀】；使用显式目标策略，目标为伏皇后，不叠加普通距离条件，仍复核禁止使用／禁止指定。
- **验证依据**：[han008_fuhuanghou.lua](../../../../tests/han008_fuhuanghou.lua) 覆盖惴恐赢后防止目标本回合伤害、平局按没赢允许目标视为使用无距离【杀】。历史记录见[共享验证证据](verification-evidence.md#han008_fuhuanghou)。
- **未完成与边界**：未执行真实客户端选目标与拼点交互；未覆盖多个伏皇后同时惴恐、目标中途死亡／失技等排列；依赖公共目标／用牌复核。旧记录保留的计划定向入口为 `python scripts/test.py --file tests/han008_fuhuanghou.lua --timeout 120`（当时标为待基础组执行，未产生该文件单独输出，后由默认套件覆盖）。

#### 承诏（HAN010 董承）

- **标识与依据**：运行时 ID `hanjin__skill_han010_1`；源码 [skill_han010_1.lua](../../../../pkg/hanjin_generals/skills/skill_han010_1.lua)。规则见[标准武将表](../../../../rules/standard-generals.md)汉区 HAN010；用牌目标策略见[效果指定的用牌目标条件](../card-use-targets.md)。
- **实现与接口**：
  - `fk.TurnEnd` 全局监听，任意角色的回合结束都可发动；条件是董承本人本回合得到过至少两张牌，且当前存在可拼点角色（共用 [han_history.lua](../../../../pkg/hanjin_generals/util/han_history.lua) 的本回合得牌查询）。
  - 发动询问与拼点对象都在 `on_cost` 中选定并保存，随后才进入 SkillEffect 的明置／技能效果结算；平局或没赢均不产生【杀】。
  - 赢时视为对拼点对象使用【杀】，使用显式目标策略。该次用牌在 `TargetSpecified` 复用青釭剑的公共无视防具机制（`addQinggangTag`），只在该次结算内令目标防具无效，不改变其他【杀】。
- **验证依据**：[han_standard_pindian.lua](../../../../tests/han_standard_pindian.lua) 覆盖本回合两张得牌的统计、拼点赢生成【杀】、该次用牌的防具无效标记、没赢不生成【杀】。历史记录见[共享验证证据](verification-evidence.md#汉区)。
- **未完成与边界**：未覆盖明置瞬间完整服务端复核、武将交换前后连续操作、死亡中断；防具部分只验证公共标记已生效，八卦阵／仁王盾等完整响应链未覆盖。客户端拼点界面未人工验收。旧记录保留的计划定向入口为 `python scripts/test.py --file tests/han_standard_pindian.lua --timeout 120`（覆盖 HAN006／HAN010／HAN013；当时标为待基础组执行，未产生该文件单独输出，后由默认套件覆盖）。

#### 奋钺（HAN013 皇甫嵩）

- **标识与依据**：运行时 ID `hanjin__skill_han013_1`；源码 [skill_han013_1.lua](../../../../pkg/hanjin_generals/skills/skill_han013_1.lua)。规则见[标准武将表](../../../../rules/standard-generals.md)汉区 HAN013；用牌目标策略见[效果指定的用牌目标条件](../card-use-targets.md)。
- **实现与接口**：
  - 出牌阶段主动技，`max_phase_use_time` 动态取存活且已确定势力的去重数量；每个野心家独立计数，未知势力不计。暗将自身势力沿用汉晋明置／转野公共预测。
  - 拼点赢时记录“下张牌”的待限制角色；皇甫嵩下一张牌被使用声明时，由模块缓存的房间级监听器把全部待限制角色直接写入该次 `UseCardData.disresponsiveList` 并清空待记录。写入的是实际使用数据，不是只对当前 `AimData.to` 调用 `setDisresponsive`，因此下张锦囊指定 C 时未成为目标的 B 也不能用【无懈可击】响应，【决斗】中双方打出【杀】也受同一名单约束。
  - 该监听器不检查皇甫嵩当前是否仍有奋钺，且房间级对象不随 Exchange 迁移；胜出后已建立的延迟限制不会因失技、暗置或武将交换而消失。待限制标记刻意不采用技能名前缀，避免被 Exchange 当作来源技能标记迁走。
  - 拼点牌点数小于 9 时生成的火【杀】也经过同一“下张牌”消费路径，因此目标不能响应这张火【杀】，限制在该火【杀】后即耗尽，不会继续影响再下一张牌。
  - 没赢（含平局）时由皇甫嵩选择失去 1 点体力或结束当前出牌阶段。主动技使用次数由引擎 `skillUsedHistory` 与正式模式已有的 `#hanjin_exchange_history` 逐牌账本迁移；本组没有另建来源侧限次标记。
- **验证依据**：[han_standard_pindian.lua](../../../../tests/han_standard_pindian.lua) 覆盖低点数获胜生成火【杀】并由其消费响应限制、高点数获胜后下一张牌不可响应、未成为下张牌目标的待限制角色仍进入 `disresponsiveList`、没赢时两种选项均可选并执行失去体力、势力数去重与野心家独立、未知不计。历史记录见[共享验证证据](verification-evidence.md#汉区)。
- **未完成与边界**：未覆盖“下张牌”为无目标牌、被取消使用、额外结算及多目标同时命中多个待限制角色的排列；未覆盖奋钺多次获胜累计限制的独立用例；未覆盖明置瞬间完整服务端复核、武将交换前后连续操作、死亡中断。客户端 AskForUseActiveSkill／选牌／拼点界面未人工验收。

#### 戡难（HAN017 刘繇）

- **标识与依据**：运行时 ID `hanjin__skill_han017_1`；源码 [skill_han017_1.lua](../../../../pkg/hanjin_generals/skills/skill_han017_1.lua)。规则见[刘繇规范](../../../../rules/generals/han017-liuyao.md)与[拼点事件](../../../../rulebook/events/pindian.md)。同将逆拒见[本页](#han017-2)。
- **实现与接口**：
  - 出牌阶段主动技；按所选角色分别记录“每名角色限一次”，已选目标 ID 表在发动者身上，采用 `hanjin__skill_han017_1-given_targets-phase` 技能前缀，Exchange 可随来源武将迁移。
  - 拼点结束后，赢家可在结算结束前取得没赢的拼点牌；可取得时同时建立刘繇本回合下一张【杀】伤害 +1。按[“并”](../../../../rulebook/terms/description-terms/and.md)的语义，拒绝取得或无法取得时不单独加伤。
  - 刘繇赢时，在发动者身上加 `hanjin__skill_han017_1-locked-turn`，本回合不能再次发动；目标赢或平局不锁定。平局无赢家，不发生取得或加伤。
  - 拼点后续与下张【杀】加值都由模块缓存的房间级监听器按已建立的 `PindianData`／`UseCardData` 处理，不依赖刘繇当前是否仍有戡难；失技、暗置或武将交换后，已完成的拼点取牌／锁定与已建立的下张【杀】加值仍结算。下张【杀】加值写入该次 `UseCardData.additionalDamage`，一次使用只消费一次。
- **验证依据**：[han017_liuyao.lua](../../../../tests/han017_liuyao.lua) 覆盖刘繇赢（取得拼点牌、锁定、下张杀 +1 且一次消费）、目标赢（目标取牌、不锁定、每角色限次与另一角色仍可选）、平局。历史记录见[共享验证证据](verification-evidence.md#han017_liuyao)。
- **未完成与边界**：未执行真实客户端选牌、拼点询问、赢家“是否取牌”交互；未覆盖“没赢的拼点牌”在拼点结算中被其他效果移走、赢家死亡／中途失技、多目标拼点中同一发起者多次没赢的独立排列；未覆盖武将交换后的连续操作与跨回合清理。旧记录保留的计划定向入口为 `python scripts/test.py --file tests/han017_liuyao.lua --timeout 120`（当时标为待基础组执行，未产生该文件单独输出，后由默认套件覆盖）。

<a id="han017-2"></a>
#### 逆拒（HAN017 刘繇）

- **标识与依据**：运行时 ID `hanjin__skill_han017_2`；源码 [skill_han017_2.lua](../../../../pkg/hanjin_generals/skills/skill_han017_2.lua)。规则见[刘繇规范](../../../../rules/generals/han017-liuyao.md)与[拼点事件](../../../../rulebook/events/pindian.md)。
- **实现与接口**：
  - 锁定技。刘繇作为发起者**或他人拼点的目标**时均监听拼点结果；每次该次结果为刘繇没赢（含平局）：先摸一张牌，再给刘繇本回合累计 +3 拼点牌点数。
  - “没赢”通过正规 global 触发器的 `can_trigger/on_cost/on_use` 执行；`createTriggerSkill` 会用 `can_trigger` 覆盖基类 target 门槛，因此即使 `PindianResultConfirmed` 的 target 为 nil 也能正常明置来源并计入技能发动。
  - 累计值不消费，每次没赢继续 +3；在拼点牌亮出后、结果确定前应用，单次点数由 `changePindianNumber` 封顶 13。累计值与单次封顶分开，不因某张牌已达 13 而丢弃累计值，也不回改已确定的当前结果。
  - +3 的应用由独立房间级延迟监听器按累计标记执行，不检查当前是否仍有逆拒；失技、暗置或交换后已建立的本回合增益仍生效。累计标记采用 `hanjin__skill_han017_2-bonus-turn` 技能前缀，按 Exchange 随来源武将迁移。
- **验证依据**：[han017_liuyao.lua](../../../../tests/han017_liuyao.lua) 覆盖作为他人拼点目标时先摸后累计、11+3 封顶 13、平局继续累计到 6、当前结果不被回溯修改。历史记录见[共享验证证据](verification-evidence.md#han017_liuyao)。
- **未完成与边界**：未执行真实客户端拼点界面；未覆盖多个刘繇同时逆拒时的累计与封顶顺序；未覆盖武将交换后的连续操作与跨回合清理。

#### 天义（WU012 太史慈）

- **标识与依据**：运行时 ID `hanjin__skill_wu012_1`；源码 [skill_wu012_1.lua](../../../../pkg/hanjin_generals/skills/skill_wu012_1.lua)。规则见[标准武将表](../../../../rules/standard-generals.md)吴区 WU012。同将酣战见[本页](#wu012-2)；持续用杀修正的用牌侧分记录见[用牌目标与距离 WU012](active.md#wu012-1)。
- **实现与接口**：拼点赢即获得本回合的用杀增益，没赢包括平局则本回合禁用【杀】；赢后无距离、多目标、额外出杀与失技后持续等具体修正见[用牌目标与距离 WU012](active.md#wu012-1)。拼点发起、点数与胜负判定在本页。
- **验证依据**：[wu_damage.lua](../../../../tests/wu_damage.lua) 覆盖真实拼点与平局、真实 `ClientPlayer` 可用性；历史 22/22。持续修正与失技后的用例见[用牌目标分记录](active.md#wu012-1)。
- **未完成与边界**：客户端拼点与用杀次数提示未人工验收。

#### 酣战（WU012 太史慈）

- **标识与依据**：运行时 ID `hanjin__skill_wu012_2`；源码 [skill_wu012_2.lua](../../../../pkg/hanjin_generals/skills/skill_wu012_2.lua)。规则见[标准武将表](../../../../rules/standard-generals.md)吴区 WU012。
- **实现与接口**：在拼点结束、牌仍在处理区时，取得本次拼点中最大点数的【杀】；并列最大者一并取得，不额外加入只选一张的限制。
- **验证依据**：[wu_damage.lua](../../../../tests/wu_damage.lua) 覆盖酣战取得及并列用例；历史 22/22。
- **未完成与边界**：多人联网、重连或实际客户端拼点交互未验收。
