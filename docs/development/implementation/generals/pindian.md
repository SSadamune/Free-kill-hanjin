##### 核心行为

| 验收组 | 合并场景与结果 |
| --- | --- |
| 天命弃摸 | 可弃手牌为 0、1、2、超过 2 张及含禁弃牌时，弃 min(2,K) 张后摸 2 张；只用手牌；拒绝发动不弃不摸 |
| 天命触发时机 | 普通／属性／视为杀均识别；成为目标后、响应前弃摸，新摸的闪可响应；同一张杀的额外结算不再次触发 |
| 密诏交牌与限次 | 自己出牌阶段空闲时间点每阶段一次，最低 max(1,X)，可交手装；取消不计次，支付后无法拼点仍计次且不退牌 |
| 密诏势力数 | 同势力去重、排除自身、未知与死者不计、野心家各自独立；客将或改势力按实际状态处理 |
| 密诏分步选择 | 先交牌再选第三人，排除 A、B；B 可因收牌获得拼点资格，无合法对象则结束 |
| 拼点结果 | B 赢、C 赢、平局三种；采用最终点数，平局无杀；赢家是用牌者及默认伤害来源 |
| 后续杀的接线 | 无实体子牌普通杀，只使用一次；不受且不计通常次数、不叠加距离，独立禁止使用／指定仍生效 |
| 国战技能来源 | 两技能各保留代表性的主副将／暗置集成验证；自写的明置后势力预测须与汉晋公共流程一致，不能仅通过直接授予明将技能的夹具验收 |
| 双技能联动及隔离 | 密诏生成的杀可正常触发目标的天命，原杀继续结算；汉晋测试不污染普通房间 |

#### 2. 实现要点

<a id="han006"></a>

##### HAN006 连计

- 出牌阶段主动技；“每名角色限一次”的已选目标 ID 表记在**发动者**身上，
  采用 `hanjin__skill_han006_1-given_targets-phase` 技能前缀，随王允的武将牌
  由 Exchange 迁移，不会让两名技能持有者互相阻止。目标身上只保留已建立的
  下一次伤害 +1 延迟效果。
- 只允许交出自己当前手牌；服务端在 `on_use` 重新核对牌仍属于发动者手牌，
  不依赖客户端选择。
- 交给后给目标本回合 `next_damage` 计数。伤害在 `DamageInflicted` 按计数增加，
  在伤害实际发生后的 `fk.Damage` 才清零；被防止的伤害不消费该效果。多个
  “下一次”同时存在时，同一次实际伤害一并增加。
- 加成监听器是模块缓存的房间级单一对象，第一次发动时安装并保留；王允之后
  失技、暗置或武将交换不影响已挂在目标身上的延迟效果。房间级对象不进入
  Exchange 的武将标记迁移。

##### 定著

- `Skill.DeputyPlace` 副将技；主将位不会获得该技能，界面与触发均不提供。
- 记录的是本回合“得到过牌”的角色，不是当前手牌非空；得到后立即用掉/弃掉
  仍满足条件。
- 出牌阶段结束时先询问发动；发动询问、得到过牌角色与另一名目标角色都在
  `on_cost` 中选定并保存，随后才进入 SkillEffect 的明置/技能效果结算，避免
  先明置再选目标。
- 由得到过牌的角色视为对指定角色使用【决斗】。目标条件使用汉晋公共显式目标
  策略，先校验再执行一次真实用牌，不重复结算。

<a id="han010"></a>

##### HAN010 承诏

- `fk.TurnEnd` 全局监听，任意角色的回合结束都可发动；条件是董承本人本回合
  得到过至少两张牌，且当前存在可拼点角色。
- 发动询问与拼点对象都在 `on_cost` 中选定并保存，随后才进入 SkillEffect 的
  明置/技能效果结算；平局或没赢均不产生【杀】。
- 赢时视为对拼点对象使用【杀】，使用显式目标策略。该次用牌在
  `TargetSpecified` 复用青釭剑的公共无视防具机制（`addQinggangTag`），只在
  该次结算内令目标防具无效，不改变其他【杀】。

<a id="han013"></a>

##### HAN013 奋钺

- 出牌阶段主动技，`max_phase_use_time` 动态取存活且已确定势力的去重数量；
  每个野心家独立计数，未知势力不计。暗将自身势力沿用汉晋明置/转野公共预测。
- 拼点赢时记录“下张牌”的待限制角色；皇甫嵩下一张牌被使用声明时，由模块
  缓存的房间级监听器把全部待限制角色直接写入该次 `UseCardData.disresponsiveList`
  并清空待记录。写入的是实际使用数据，不是只对当前 `AimData.to` 调用
  `setDisresponsive`，因此下张锦囊指定 C 时未成为目标的 B 也不能用
  【无懈可击】响应，【决斗】中双方打出【杀】也受同一名单约束。
- 该监听器不检查皇甫嵩当前是否仍有奋钺，且房间级对象不随 Exchange 迁移；
  胜出后已建立的延迟限制不会因失技、暗置或武将交换而消失。待限制标记本身
  也刻意不采用技能名前缀，避免被 Exchange 当作来源技能标记迁走。
- 拼点牌点数小于 9 时生成的火【杀】也经过同一“下张牌”消费路径，因此目标
  不能响应这张火【杀】，且限制在该火【杀】后即耗尽；不会继续影响再下一张牌。
- 没赢（含平局）时由皇甫嵩选择失去 1 点体力或结束当前出牌阶段。
- 连计/奋钺的主动技使用次数由引擎 `skillUsedHistory` 与正式模式已有的
  `#hanjin_exchange_history` 逐牌账本迁移；本组没有另建来源侧限次标记。

#### 2. 实现要点

##### 惴恐

- `EventPhaseStart` 全局监听其他角色的准备阶段；伏皇后已受伤且可与该角色
  拼点时，通过正规 `can_trigger/on_cost/on_use` 发动。`createTriggerSkill` 会
  用 `can_trigger` 覆盖基类 target 门槛，因此不需要 refresh/`room:useSkill`
  代理；正常明置来源并记录技能发动。
- 伏皇后赢：给该角色加本回合 `no_damage` 延迟标记；房间级 `DamageCaused`
  监听器按标记把该角色造成的伤害防止。监听器不依赖伏皇后之后是否仍有技能。
- 没赢（含平局）：该角色可选择视为对伏皇后使用【杀】；使用显式目标策略，
  目标为伏皇后，不叠加普通距离条件，仍复核禁止使用/禁止指定。

##### 求援

- `TargetConfirming` 触发，只在伏皇后成为其他角色【杀】的目标时提供一次；
  同一名伏皇后对同一次 use 不会重复求援。
- 候选使用公共 `ExtraTargets` 显式条件 `other_roles = true`：不按普通攻击
  距离阻挡，但仍排除已禁止、已在本次目标列表中的角色。
- 通过 AimData 的目标加入接口增加目标，新增目标仍会生成
  `TargetSpecified`/`TargetConfirmed` 等正常目标事件。
- 新增目标 id 记录在本次 `UseCardData` 上；效果顺序只在
  `BeforeCardUseEffect` 调整为新增目标优先，不在目标阶段排序，不提前事件。

#### 2. 实现要点

##### 戡难

- 出牌阶段主动技；按所选角色分别记录“每名角色限一次”，已选目标 ID 表在
  发动者身上，采用 `hanjin__skill_han017_1-given_targets-phase` 技能前缀，
  Exchange 可随来源武将迁移。
- 拼点结束后，赢家可在结算结束前取得没赢的拼点牌；可取得时同时建立
  刘繇本回合下一张【杀】伤害 +1。按[“并”](../../../../rulebook/terms/description-terms/and.md)
  的语义，拒绝取得或无法取得时不单独加伤。
- 刘繇赢时，在发动者身上加 `hanjin__skill_han017_1-locked-turn`，本回合不能
  再次发动；目标赢或平局不锁定。平局无赢家，不发生取得或加伤。
- 拼点后续与下张【杀】加值都由模块缓存的房间级监听器按已经建立的
  `PindianData`/`UseCardData` 处理，不依赖刘繇当前是否仍有戡难；失技、暗置
  或武将交换后，已完成的拼点取牌/锁定与已建立的下张【杀】加值仍结算。
  下张【杀】加值写入该次 `UseCardData.additionalDamage`，一次使用只消费一次。

##### 逆拒

- 锁定技。刘繇作为发起者**或他人拼点的目标**时均监听拼点结果；每次该次
  结果为刘繇没赢（含平局）：
  1. 先摸一张牌；
  2. 再给刘繇本回合累计 `+3` 拼点牌点数。
- “没赢”通过正规 global 触发器的 `can_trigger/on_cost/on_use` 执行；
  `createTriggerSkill` 会用 `can_trigger` 覆盖基类 target 门槛，因此即使
  `PindianResultConfirmed` 的 target 为 nil 也能正常明置来源并计入技能发动。
- 累计值不消费，每次没赢继续 +3；在拼点牌亮出后、结果确定前应用，单次
  点数由 `changePindianNumber` 封顶 13。累计值与单次封顶分开，不因某张牌
  已达 13 而丢弃累计值，也不回改已经确定的当前结果。
- `+3` 的应用由独立房间级延迟监听器按累计标记执行，不检查当前是否仍有
  逆拒；失技、暗置或交换后已建立的本回合增益仍生效。累计标记采用
  `hanjin__skill_han017_2-bonus-turn` 技能前缀，按 Exchange 随来源武将迁移。
