## 天命

- **标识与依据**：运行时 ID `qiao__skill_han001_1`；源码 [skill_han001_1.lua](../../../../../pkg/qiao_generals/skills/skill_han001_1.lua)。规则见[刘协规范](../../../../rules/generals/han001-liuxie.md)。同将另见[密诏](#han001-2)。

牌面原文见[石激桑资料](../../../../../assets/docs/石激桑武将列表.json#L488)。

> 当你成为【杀】的目标后，你可以弃置两张手牌（不足则全弃，无牌则不弃），摸两张牌。

- **实现与接口**：
  - 成为【杀】的目标后触发；可弃手牌为 0 张、1 张、2 张或超过 2 张（含禁弃牌）时，弃 `min(2,K)` 张后摸 2 张，只用手牌；拒绝发动不弃不摸。
  - 普通／属性／视为【杀】均识别；在成为目标后、响应前弃摸，新摸的【闪】可响应；同一张【杀】的额外结算不再次触发。
  - 提示文案为“弃置两张手牌（不足则全弃，无牌则不弃）”和“请弃置 %arg 张手牌”。
- **验证依据**：[han001_liuxie.lua](../../../../../tests/han001_liuxie.lua) 保留天命弃摸、公共机制与风险边界记录（旧验收组含触发时机与双技能联动）；原记录未以 han_standard_pindian 覆盖天命，本页不据此套用该文件名。历史执行见[共享验证证据](../verification-evidence.md#汉区)。
- **未完成与边界**：

  - [ ] 待办：将审定后的规范化描述纳入《汉晋规则集》对应武将资料；保留面向玩家的卡面描述。测试说明及 `docs/rules/generals/han001-liuxie.md` 的裁定草案均不替代规范化描述，未决裁定须明确标注。
  - 天命与密诏的联动及汉晋／普通房间隔离沿用原验收组；正常闪响应、防具、伤害、牌移动和来源变化优先复用公共覆盖，按[测试分层](../../../testing.md)决定新增用例，不将场景清单逐项视为测试义务。相关夹具污染的根因与确定性回归入口见[故障案例](../../../lessons.md)。

## 密诏

- **标识与依据**：运行时 ID `qiao__skill_han001_2`；源码 [skill_han001_2.lua](../../../../../pkg/qiao_generals/skills/skill_han001_2.lua)。规则见[刘协规范](../../../../rules/generals/han001-liuxie.md)。同将另见[天命](#han001-1)；规范化描述待办同时覆盖天命与密诏，见该条目。

牌面原文见[石激桑资料](../../../../../assets/docs/石激桑武将列表.json#L489)。

> 出牌阶段限一次，你可以将至少X张牌交给一名其他角色（X为与你不同的势力数），然后令其与另一名由你选择的其他角色拼点：赢的角色视为对没赢的角色使用一张【杀】。

- **实现与接口**：
  - 自己出牌阶段空闲时间点每阶段一次，最低 `max(1,X)`，可交手牌或装备牌；取消不计次，支付后无法拼点仍计次且不退牌。
  - 势力数：同势力去重、排除自身、未知与死者不计、野心家各自独立；客将或改势力按实际状态处理。
  - 分步选择：先交牌再选第三人，排除 A、B；B 可因收牌获得拼点资格，无合法对象则结束。密诏收牌者切换由扩展内 [client.lua](../../../../../pkg/qiao_mode/client.lua) 的汉晋专用请求处理器实现，经引擎客户端注册接口接入，随安装包发布，不依赖本地本体适配；其他技能沿用原请求流程。
  - 拼点结果：B 赢、C 赢、平局三种；采用最终点数，平局无【杀】；赢家是用牌者及默认伤害来源。
  - 后续【杀】接线：无实体子牌的普通【杀】，只使用一次；不受且不计通常次数、不叠加距离，独立禁止使用／指定仍生效。
  - 国战技能来源：两技能各保留代表性的主副将／暗置集成验证；自写的明置后势力预测须与汉晋公共流程一致，不能仅通过直接授予明将技能的夹具验收。密诏君主预测的独立运行时用例尚待补充。
  - 客户端报错回归：刘协搭配徐晃、明置副将后进入自己的回合时，密诏按钮检查曾因 `ClientPlayer` 没有 `room` 字段而崩溃；现已改为兼容引擎当前客户端房间，并新增无 `room` 的真实 `ClientPlayer` 回归，覆盖已确定势力与暗置自身势力预测下的交牌下限、可用性和提示。该自动化回归不代替客户端完整交互的人工验收。
  - 提示与选择交互：密诏后续提示为“选择参与拼点的另一名角色”；界面还须检查 X 与交牌下限、收牌者与拼点对象的分步选择及平局提示。
- **验证依据**：[han001_liuxie.lua](../../../../../tests/han001_liuxie.lua) 保留天命、密诏的核心行为、公共机制与风险边界记录；原记录中的验收组（交牌与限次、势力数、分步选择、三种拼点结果、后续【杀】接线、双技能联动及隔离）属于该专项的分层组织，不记作 han_standard_pindian 的覆盖。历史执行见[共享验证证据](../verification-evidence.md#汉区)。
- **未完成与边界**：风险边界包括弃牌／交牌连锁导致中途死亡、牌移动被特殊效果替代、拼点后死亡或技能消失；断线、超时、过期与伪造选择优先依公共服务端复核；少见多技能叠加或特殊国战组合不作无依据的全排列验收。新增用例应加入 `tests/all.lua` 的默认国战套件。继续以已确认规则核对现有独立汉晋实现；可参考锁定上游国战流程及 Qsgs-Fans/SP 的天命、密诏源码，但须适配本项目差异，不直接挂接其他版本同名技能。现有实现参考：锁定 `hegemony` 的国战技能来源／明置流程；本地引擎 `ltk/core/player.lua` 的 `canPindian`；`ltk/server/events/pindian.lua` 的拼点结果流程——只用于核对接口，不替代用户规则裁定。界面人工验收与规范化描述仍待完成。
