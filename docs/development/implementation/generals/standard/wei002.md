## 狼顾

- **标识与依据**：运行时 ID `qiao__skill_wei002_1`；源码 [skill_wei002_1.lua](../../../../../pkg/qiao_generals/skills/skill_wei002_1.lua)。规则见[司马懿规范](../../../../rules/generals/wei002-simayi.md)。同将[鹰视](#wei002-2)、[应期](#wei002-3)。

牌面原文见[石激桑武将列表.json](../../../../../assets/docs/石激桑武将列表.json#L4823)。

> 当你受到伤害后，你可以获得来源的一张牌。

- **实现与接口**：`fk.Damaged` 触发；获得来源一张手牌／装备牌；来源为自己时只取装备区，与既有反馈类公共处理一致。技能以 `player:hasSkill` 判定当前是否持有，不依赖服务端私有字段。
- **验证依据**：[wei_damage.lua](../../../../../tests/wei_damage.lua) 覆盖狼顾取得来源牌。
- **未完成与边界**：完整死亡、客户端界面与主副将来源切换未人工验收。

## 鹰视

- **标识与依据**：运行时 ID `qiao__skill_wei002_2`；源码 [skill_wei002_2.lua](../../../../../pkg/qiao_generals/skills/skill_wei002_2.lua)。规则见[标准武将表](../../../../rules/standard-generals.md)魏区 WEI002。同将[狼顾](#wei002-1)、[应期](#wei002-3)。

牌面原文见[石激桑武将列表.json](../../../../../assets/docs/石激桑武将列表.json#L4824)。

> 当一名角色的判定牌生效前，你可以打出一张牌代替之。

- **实现与接口**：
  - 规则要点：一名角色的判定牌生效前，发动者可打出一张**自己的手牌或装备牌**代替之；与普通“鬼才”不同，可用牌包含装备区，不限于手牌。
  - 时机为 `fk.AskForRetrial`，条件为拥有鹰视、存在未被禁止打出的手牌／装备牌、同一判定尚未替换过（`data.__qiao_wei002_2_retrial`）。
  - 费用：`room:askToSkillInvoke` 后 `room:askToCards`，候选集为手牌＋装备区中 `player:prohibitResponse(card)` 为假的牌，装备区以 `expand_pile` 提供；禁止打出的牌不能选。
  - 真实打出：现有 `room:changeJudge{ response = true }` 只移牌、不产生 `CardRespond` 事件，因此先 `room:responseCard { from = player, card = card, skipDrop = true }` 完成真实打出，防止牌被默认弃置；打出后复核 `room:getCardArea(id) == Card.Processing`，再调用 `room:changeJudge { card = card, player = player, data = data, skillName = ..., response = true }`，`data` 标记确保同一判定只替换一次。
  - 翻译键：`qiao__skill_wei002_2`、提示 `#qiao__skill_wei002_2-invoke`、`#qiao__skill_wei002_2-ask`。
- **验证依据**：[wei_retrial.lua](../../../../../tests/wei_retrial.lua) 覆盖真实 `room:judge` 流程中替换牌成为最终判定牌（`responseCard` 与 `changeJudge` 均走真实实现，用例只固定是否发动与选择哪张牌两个输入），以及被 `prohibitResponse` 禁止的牌不能作为候选、不产生改判，见[共享验证证据](../verification-evidence.md#wei_retrial)。
- **未完成与边界**：输入选择仍使用测试桩（是否发动、选哪张牌）；判定、真实打出与改判流程未用桩。同一判定多次改判（多角色鹰视／鬼才）的交互未展开。

## 应期

- **标识与依据**： 此运行时 ID 对应 WEI002 司马懿、JIN009 司马懿 的同文技能。

牌面原文见[石激桑武将列表.json](../../../../../assets/docs/石激桑武将列表.json#L1686)。

> 锁定技，若你配将为多势力或客将，☯️+2。
  - 运行时 ID：唯一规范 ID 为 `qiao__skill_wei002_3`，源码 [skill_wei002_3.lua](../../../../../pkg/qiao_generals/skills/skill_wei002_3.lua)；晋 JIN009 直接引用同一 ID，不再另设骨架。两处卡面文本统一为魏文本（“☯️+2”），避免同 ID 翻译相互覆盖。魏、晋两版均引用此条目。
  - 规则见[应期裁定](../../../../rules/generals/wei002-simayi.md)、[JIN009 同文引用](../../../../rules/generals/jin009-simayi.md)与[配将体力贡献通则](../../../../rules/general-principles.md#配将体力贡献与武将状态)。业务文件：[pair_hp.lua](../../../../../pkg/qiao_mode/rules/pair_hp.lua)、`mode.lua`、`rules/ascension.lua`、应期骨架（两版共用一份）。
- **实现与接口**：
  - 数值表示：引擎以**半格**保存体力贡献（1.5 体力记作 `3`，2.0 记作 `4`，2.5 记作 `5`）。国战双将体力上限为 `((主将贡献 + 主将调整) + (副将贡献 + 副将调整) + 应期半格修正) // 2`；半格合计为奇数时 `HalfMaxHpLeft` 标记为 `1`，表示 1 个“半个阴阳鱼”。应期的“☯️+2”是 **2 个半格**（1 点体力上限），不是两枚可消耗的阴阳鱼标记，因此不发放 `@!!yinyangfish` 或 `qiao_ascension_yinyang` 等标记，只在开局把组合上限补 1 点，并沿用引擎写入的奇偶余数标记。
  - 身份判定：`qualifies(name, room)` 保留牌面多主势力，用 `Guest.isGuest(room, name)` 识别客籍本局是否实际生效。仅登记客籍、仍以单一主势力配将时无修正。开局和升变都传入当前房间。同一配将组合由 `yinyang` 返回一次修正。
  - 开局：`mode.lua` 在上游 `HegLogic:broadcastGeneral` 后调用 `PairHp.apply_start`，按实际配将的贡献差值更新体力，补齐待领标记。应期保留牌面和配将用技能标识，骨架没有触发效果，暗置时不提供预亮按钮。
  - 升变：`rules/ascension.lua` 的 `pair_max_hp`、实际主副将读取与阴阳鱼奇偶判断改由 `pair_hp.lua` 提供；升变前后组合上限都按含应期的公式计算，所以“同体力主将升变”不会被误判为上限增加；升变收益仍按原公共流程（新组合上限更高时加 1 点上限并回复 1 点体力）。
  - 不重算：普通交换、移除、替换不调用 `apply_start`／`pair_max_hp`，已确定的体力上限不变；开局后属性变化不会撤回或追加应期收益。
  - 客户端与模式隔离：应期不新增客户端交互或私有字段；`maxHp`、`hp`、`HalfMaxHpLeft` 都是引擎已有公开属性／标记。只在 `qiao_heg_mode` 的 logic 上覆盖 `broadcastGeneral`，不修改上游 `hegemony` 包或其他模式。
- **验证依据**：[wei_pair_hp.lua](../../../../../tests/wei_pair_hp.lua) 以开局广播验证魏未禁时曹操搭配司马懿上限为 3、曹操客籍实际生效时两个版本的司马懿搭配均为 4、原牌面多势力的认定，以及升变继续使用同一体力计算入口。应期修正不发放可消耗的阴阳鱼。
- **未完成与边界**：自动化已通过；客户端进房及联网／重连人工验证尚未完成。“普通交换后升变”的组合比较沿用既有实现（比较升变前后的组合上限公式），不改比较实际 `maxHp`；若规则要求以实际上限为基准，需另轮裁定并补测试。若将来出现独立应期君主版／效忠版但使用不同技能名，需要把技能名登记到 `pair_hp.M.YINGQI_SKILLS`。开局广播路径已有正式房间与专项自动化覆盖；不设 GameStart 重算作为回退，新增开局加载路径时应复核仍经过该模式接线。
