# “X 只能当 Y 使用／打出”：实现与验证

游戏语义见[对应规则](../../../rules/only-as.md)；当前实装与待办见[开发状态](../status.md)。本页保留接口、接线和验收依据，不替代规则裁定，历史覆盖说明不代表已完成全部人工验收。

## 公共实现与接入

公共实现位于 `pkg/hanjin_mode/rules/only_as.lua`，隐藏限制及校验位于 `skills/only_as_prohibit.lua` 和 `only_as_rule.lua`，仅在汉晋房间生效。它们不向角色提供独立的“只能当”技能或可见来源标记。客户端读取同步的内部玩家标记，服务端重新核对来源、底牌访问权、使用／打出权限、请求参数及目标组合；不改实体牌牌名，不修改本体与上游依赖。

| 接口 | 用途 |
| --- | --- |
| `define(key, spec)` | 登记实体牌匹配条件及各转换目标的 `modes = { "use", "response" }` 权限 |
| `addViewAsEffect(skill, definition, prompt)` | 将指定定义的转换效果接入原技能；入口、提示和转换牌来源归属该技能，不能执行另一来源的用途 |
| `addSource(room, opts)` | 按 `def`、`holder`、可选稳定 `id` 登记来源，支持限定实体牌 `cards`、牌区及 `duration` |
| `removeSource(room, uid)`／`clearSources(room, holder)` | 独立撤销来源或清理指定持有者的来源 |
| `refresh(room)` | 重算来源有效性并同步客户端；回合来源在回合结束失效，轮次来源在轮次变化后失效 |
| `actionsForCard`／`availableTargets` | 查询指定实体牌在使用或打出模式下的转换用途并集；此处 target 指转换后的牌名 |
| `validateUse`／`validateCardUse` | 服务端复核转换结果及实际使用／打出，包括同次请求的距离、次数、固定目标等参数 |
| `askRestricted(room, player, params)` | 只在 `params.cards` 明确提供的临时实体牌集中询问用途；不开放无关手牌或其他转换技 |

`addSource` 可使用 `duration = "turn"`、`"round"`、`"game"` 或 `"manual"`。`cards` 限定底牌集合，`match` 可匹配牌名、花色等，`conversions` 可覆盖用途，`view_zones` 与 `direct_zones` 分别限定转换选牌及直接使用／打出的限制范围。未知牌区不予放行。

可选 `skill` 绑定持有者武将上的技能：明暗置与暂时无效化会影响来源是否生效，技能／武将失去后删除来源。已产生且不应随技能失去而结束的持续效果，调用者应按其规则登记独立时效，不机械绑定技能。来源不会仅因静态定义存在就自动生效；正式突袭已在展示本次取得牌后调用 `addSource`，以实体牌集合和独立回合时效登记，不绑定技能。双刃仍待在真实发动时机接入预置的 `shuangren` 定义。

手牌与木牛等合法视为手牌的牌堆使用各来源自己的转换入口。鏖战入口为 `skills/battle_royal.lua` 中的 `hanjin_battle_royal&`，只提供鏖战定义的用途。多个来源的用途并存，不表示可以通过其中一个技能发动另一个技能的效果。临时牌区通过原取牌效果调用 `askRestricted` 授权所选的确切实体牌，完成、取消或移动后清理授权；转化结果保留原取牌效果的来源及底牌。新增第三方取牌入口须明确接入，公共禁止技不会自动为任意“使用实体牌”窗口增加转换交互。

使用窗口的过滤区分普通主动使用与请求型使用（`AskForUseCard`，例如被杀时询问使用【闪】）：请求型使用先按当前 pattern 过滤，被动【闪】/【无懈】按引擎的被动牌例外允许以“使用”响应，但没有请求 pattern 时不得主动使用；服务端复核同样以请求时点为准，唯一合法用途作为默认选中。

## 验证与边界

`tests/only_as.lua` 已纳入默认 `tests/all.lua`，覆盖多来源并集及独立撤销、牌名保持、回合／轮次时效、主副将明暗与技能失效、客户端使用／打出询问、木牛、傲才、急救同名转化及龙胆桃转酒对应物，以及伪造底牌／请求／目标与授权失效。技能对应物位于测试专用 `tests/support/only_as_content.lua`，不发布为正式武将内容。

通用目标约束另见[效果指定的用牌目标条件](../../../rules/card-use-targets.md)。本公共层保留同次请求的合法性参数，并可选接入该目标策略模块；没有该模块时仍可独立运行。规则确认与本次测试不代表所有正式技能或任意第三方特殊取牌入口已接入。傲才采用通用选项及原生目标选择交互，未进行专用 QML 的人工视觉验收。
