# 第二君主：实现与验证

游戏语义见[对应规则](../../rules/second-lord.md)；当前实装与待办见[开发状态](../status.md)。本页保留接口、接线和验收依据，不替代规则裁定，历史覆盖说明不代表已完成全部人工验收。

## 扩展内实现

实现位置：

| 内容 | 文件/接口 |
| --- | --- |
| 显式版本登记 | `pkg/qiao_mode/rules/general_versions.lua`：`Versions.register { normal, lord, loyalty }`、`lord_version`、`lord_kingdoms`、`is_lord`、`selectable` |
| 升变通则 | `pkg/qiao_mode/rules/ascension.lua`：`pair_max_hp`、`population_blocks`、`ascend`、`flip_lord_for_death`、`death_succession`、`convert_to_wild`、`get_winner` |

| 模式规则技能 | `pkg/qiao_mode/skills/ascension_rule.lua`：`fk.TurnStart` 普通升变、`fk.BeforeGameOverJudge` 死亡继位、`fk.GameOverJudge` 胜负 |
| 模式接线 | `pkg/qiao_mode/mode.lua`：`winner_getter = Ascension.get_winner`；其余选将池逻辑由 `Versions.plan` → `Pool.resolve` 使用 |

版本登记使用显式对应关系，不依赖同名替换或上游 `HegUtil.lordGenerals`。君主版程序名不得包含 `lord`，并且登记时设置 `general.is_lord`；这样可以避开上游 `new_hegemony_mode.lua` 死亡奖惩与 `hegemony_rule.lua` 明置处理中只按名字识别的君主特例，汉晋自己接管继位、转野和胜负。普通升变在角色首个回合的 `fk.TurnStart` 提供，先于上游同回合的亮将询问；死亡继位在 `fk.BeforeGameOverJudge` 执行，先于标准游戏结束判定，候选人按当前回合角色起逆时针询问并在提交时复核。涉及暗将时由服务端私下校验和询问，不向全场展示候选名单。

胜负判定一律根据场上是否只剩唯一势力决定游戏是否结束，与是否有君主及势力人数是否超过全场人数一半无关。超员野心家不会因君主存在被并回原势力；各野心家仍按国战规则分别视为独立势力。

## 自动化验收

`tests/second_lord.lua` 覆盖：

- 同势力两人先后尝试普通升变，首位成功后第二位不再获得该势力君主位置。
- 主将已明置或仍然暗置的死亡继位、从当前回合角色起的询问顺序、首人拒绝后次人接受。
- 加入后超员、已因超员成为野心家、受明置限制等不合资格情形。
- 无人继位时按君主死亡转野、已有野心家不回归、继位成功时本次死亡不转野。
- 升变后主将明置、势力同步、技能替换、暗置副将保持暗置。
- 体力上限增加时加 1 并回复 1 点；持平或减少时不调整。
- 珠联璧合与阴阳鱼只在“此次升变首次使两张武将牌均明置”时发放；已花费或升变前已双亮不重领。
- 君主在场不豁免超员；有君主的势力仍会因超员转为野心家。
- 有君主与无君主采用相同的唯一势力胜负判定；覆盖势力人数超过全场人数一半的情况，以及常规势力与野心家并存、多个野心家并存和仅剩一个野心家的情况。
- 真实 `qiao_heg__qun010` + 暗貂蝉普通升变：按 `actual_main` 清理旧普通将 fake/prelight，保留暗副将；弘法可用并实际授予黄巾天兵符，悟心/问道正常；独立同名实际来源不被清理。
- 真实 `qiao_heg__shu001` 升变：章武作为国战君主技能实际进入技能来源；旧的普通仁德移除。
- 真实 `qiao_heg__wu001` 升变为君孙权：嘉禾实际授予缘江烽火图；吴势力角色获得旗入口、异势力不获得；一张装备牌经入口置入旗堆后持旗者攻击范围 +1；敛资以吴势力攻击范围并集为 X 只用于亮牌数，门槛另按场上存活、未移除角色数判断（8 人局 X=4：本回合得牌达到 4 仍不转换，达到 8 才失去敛资、获得 `qiao__skill_wu001_1`）；聚宝取消其他角色对任意宝物牌的非弃置移动而放行弃置；失去嘉禾后旗来源、入口与攻击范围加成一并撤回，入口提交被拒绝。
- 缘江烽火图第二段（准备阶段临时授技）：吴势力角色自己的准备阶段按当次烽火数逐档得到英姿／好施／攻心／度势候选（3 张时三项、5 张时四项且可多选一个不同技能），授技记在角色上、不附武将牌；来源 `qiao__skill_em_wu001_flag_source` 独立记账，本回合结束（或受益者死亡）只撤本次授予，烽火减少不回撤，另一独立来源的同名英姿保留。旗授予的 `qiao__gongxin` 私看目标手牌、候选只列当前红桃，可不选或取消；展示所选红桃后按弃置（受禁止弃置约束）或将同一张牌置于牌堆顶移动，移动前复核原手牌与花色。真实授予后同一回合由该角色实际发动攻心（真实 `AskForPoxi` 回复选中一张红桃，另一张红桃与黑色牌不动）再回合结束撤销本次授予；真实 `ClientPlayer` 经 `ReqPlayCard.setup` → `skillButtonValidity` → `selectSkill` → `targetValidity` → `selectTarget` → `feasible` 走通点击入口。
- 缘江烽火图第三段（锁定技，受牌伤害后）：持旗者受到牌渠道伤害（`fk.Damaged` 且伤害数据带牌，铁索传导沿用原牌渠道）且旗上至少一张烽火时，`on_cost = Util.TrueFunc` 直接发动；原文未指定哪一张，多张烽火时由持旗者经正式 `askToChooseCard`（`card_data` 列出公开的旗牌堆、不可取消）选择一张，单张直接移去，提交结果须仍在旗牌堆；按正常移牌以 `fk.ReasonPutIntoDiscardPile` 置入弃牌堆（非弃置），并以“实际离开该私人牌堆”判定成功，未实际移去则不建立后续；然后增加一次“本回合下次受到的伤害-1”待生效计数。此次伤害已结算，不回溯减免。该减伤由独立房间技能 `qiao__skill_em_wu001_rule` 的 `fk.DetermineDamageInflicted` 执行 `changeDamage(-1)`，不限定伤害渠道、每次消耗一项、用后归零；失去嘉禾或旗后仍执行；任一回合结束时清除所有未消耗的减伤（包括失旗后建立的），受益者死亡时撤销其本次授予与减伤。攻击范围随烽火移去即时下降。定向用例另以三张烽火的真实选牌请求选择第一张（非末张），验证只有所选那张移去、其余保留。
- 君曹操：目标是魏角色准备阶段弃一张牌并实际暗置其预选的位置，按牌面 4 点取得已实装技能；限制绑定该牌，其他角色与君主回合开始不解除、本人下回合开始撤销本次来源。君主牌首次双亮、建安授技、限制与到期、挥鞭、总御及十项授技均已定向通过，详见 status。
- 君司马炎的採幸有多个候选时通过 `AskForCardChosen` 显示公开候选，按装备区与弃牌堆分组。请求携带发动者的角色对象供客户端读取，实际可选牌由明确的卡牌 ID 列表提供。定向测试用真实请求、编码后的客户端回调和选牌回复，验证选择弃牌堆的临筱玉舆后只置入所选牌。
