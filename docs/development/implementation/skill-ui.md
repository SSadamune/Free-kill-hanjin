# 技能选项、按钮与头像详情

## 右下角技能栏调查

锁定的新月杀 v0.5.25 从 `LunarLtk/Components/Dashboard.qml` 直接创建 `SkillArea`。`SkillArea.qml` 将中文界面的预亮、主动和普通技能固定为 2、2、3 列，视口最多 180 px，内容取三组网格中最宽一组并右对齐裁剪。`SkillButton.qml` 的主动及预亮按钮至少 80 px，普通按钮宽度取文字宽度，字号缩到 18 px 后仍可随文字变宽。多个长标签同列或同组时会撑宽网格；实际裁剪和滚动边界随字体、缩放和技能组合变化。

目前的扩展交互 QML 注册点用于具体请求，无法替换这个 `SkillArea`。`Fk:addUIPackage` 可以让玩家选择整套桌游房间页，粒度大于汉晋模式里的单个组件。扩展能提供较短的显示名作为缓解，但逐个改名无法修正通用布局。本轮只调查。若以后修布局，建议用同一组长短混合技能在窄窗口验证文字、排列和点击区域，再选择合适的上游组件改动。

## 头像右键技能详情

`LunarLtk/Pages/Room.qml` 的头像右键事件直接打开 `InfoPopups/PlayerDetail.qml`。该弹窗通过 `Ltk.getPlayerSkills` 获取可见技能名称和描述，在技能页逐行显示，装备区、判定区和已知牌使用各自的页面。当前接口没有来源字段，也没有为该弹窗单独登记页面的入口。要在默认弹窗增加来源分组，需要上游支持来源元数据和分组渲染。扩展可以在已有描述中标注真实来源，沿用引擎对本人和其他角色的可见性规则。

当前 `skill_source_labels` 在正式扩展注册后给诏书、君主旗、统领、翼从的描述加来源标签。诸王敕封册另标注赐的消费入口，描述不列举持有的赐。武将牌技能与装备沿用原描述。按钮悬浮说明共用这条描述路径，也会带标签。`standard_generals` 13/13 通过，覆盖正式注册后的 `Fk:getDescription`、统领动态描述及技能名称，未进行真人点击验收。

## 决策前的详细提示

诏书选势力锦囊、霸者求贤状、六师率义旗和缘江烽火图授技沿用锁定引擎 `askToChoice`／`askToChoices` 的 `detailed` 参数。`ChoicesBox.qml` 在选项旁读取 `:<选项 ID>` 的正式说明，技能的选项数量与确认方式沿原请求。赐的消费请求按所选牌给出实际摸牌或手牌上限效果。巧变和神速在首次确认时显示当前阶段及对应效果或代价。

对应专项 `em_han001_liuxie` 14/14、`em_wei001_caocao` 16/16、`em_shu001_liubei` 4/4、`em_wu001_sunquan` 16/16、`em_jin001_simayan` 7/7、`wei_phases` 16/16 通过。自动化覆盖请求参数、候选正式说明和分支文案，详细面板的实际显示与小窗口布局仍待客户端验收。

## 诏书牌堆入口

诏书公开牌堆使用原生 QML 标记注册，`EdictPile.qml` 扩展原生 `ViewPile`，沿用原有的牌面显示。持有者在同一个弹窗里操作“取锦囊”；其他玩家、旁观和回放只查看牌。按钮仅在当前普通出牌请求允许发动时可点击，提交仍走原有主动技的客户端确认和服务端回包。技能隐藏独立的右下角按钮。旧录像的原牌堆名保留中文翻译。

君刘协专项 14/14，覆盖权限、出牌阶段、发送标准回包及实际付牌。离屏 Qt 检查加载原生查看器，覆盖按钮显隐、禁用和点击时先关弹窗再发请求。实际客户端操作与联网重连尚未人工验收。

## 实战反馈后的显示修正

- 汉晋房间沿用同一已注册桌游引擎，只替换默认房间页入口。房间页继承原生 `Room`，通过头像公开的装备区属性让双副类别坐骑占满该行。单坐骑、卸下坐骑和普通国战保留原生布局。双副类别坐骑标题通过 `ui_name` 显示牌名。
- 持旗角色公开显示带正式旗文的原生状态标记。六师率义旗显示在章武持有者处，蜀势力角色的用旗入口不单独显示旗标。敏思标记仅向对应手牌持有者发送显示更新，原手牌上限判定仍以本次摸牌与受益者为准。断肠标记随失技的武将牌移动，公开状态不包含暗将姓名或牌位。
- 乘流在富文本描述入口转义原文尖括号，原始翻译保留。汉晋技能浮窗使用纯文本，普通日志保留富文本。没有台词字幕的汉晋限定技在原生动画中显示本地化技能名。

对局中的询问按所在时点填写数字和处理对象。英魂从玩家当前已损失体力计算说明与选项；制衡和定澜夜明珠使用当前体力上限；修体、集兵、破军、奋命和横江使用各自的实际数量。烈戎在支付体力后显示攻击范围增加量的上限，膂力按最终实际弃置的牌数描述回复。资料中的通用卡面原文仍用于无对局状态的查阅。

此次检查了汉晋技能与卡牌的直接请求和主动技能提示，补齐只显示名称的选项或选牌说明，并校正源角色、目标角色和数值的参数位置。离屏验证用锁定客户端的 `processPrompt` 执行 13 个代表性载荷，检查实际文本中的角色和数值。
