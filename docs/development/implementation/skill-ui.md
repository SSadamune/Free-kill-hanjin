# 技能选项、按钮与头像详情

## 右下角技能栏调查

锁定的新月杀 v0.5.25 从 `LunarLtk/Components/Dashboard.qml` 直接创建 `SkillArea`。`SkillArea.qml` 将中文界面的预亮、主动和普通技能固定为 2、2、3 列，视口最多 180 px，内容取三组网格中最宽一组并右对齐裁剪。`SkillButton.qml` 的主动及预亮按钮至少 80 px，普通按钮宽度取文字宽度，字号缩到 18 px 后仍可随文字变宽。多个长标签同列或同组时会撑宽网格；实际裁剪和滚动边界随字体、缩放和技能组合变化。

汉晋房间页复用原生 `SkillArea`，在技能栏模型更新后调整标签。有四个及以上汉字的非点选项，若属于君主旗、翼从或其他非武将／非装备来源，从技能栏移除。主动、视为和预亮入口继续显示，武将技能和装备技能沿用原有显隐。三个及以下汉字的标签沿用全名。

技能栏简称按技能 ID 配置。例如六师率义旗显示为「六师」，并州狼骑显示为「并州骑」，血海魔王樽显示为「魔王樽」。保留的其他长标签取前三个汉字。按钮点击仍提交原技能 ID，完整名称用于技能详情、牌面和询问。方天画戟与州郡领兵印沿用现有装备显示和触发询问。

## 头像右键技能详情

`LunarLtk/Pages/Room.qml` 的头像右键事件直接打开 `InfoPopups/PlayerDetail.qml`。该弹窗通过 `Ltk.getPlayerSkills` 获取可见技能名称和描述，在技能页逐行显示，装备区、判定区和已知牌使用各自的页面。当前接口没有来源字段，也没有为该弹窗单独登记页面的入口。要在默认弹窗增加来源分组，需要上游支持来源元数据和分组渲染。扩展可以在已有描述中标注真实来源，沿用引擎对本人和其他角色的可见性规则。

当前 `skill_source_labels` 在正式扩展注册后给诏书、君主旗、统领、翼从的描述加来源标签。诸王敕封册另标注赐的消费入口，描述不列举持有的赐。武将牌技能与装备沿用原描述。按钮悬浮说明共用这条描述路径，也会带标签。`standard_generals` 13/13 通过，覆盖正式注册后的 `Fk:getDescription`、统领动态描述及技能名称，未进行真人点击验收。

### 双暗时查看自己的武将牌

玩家右键自己的头像时，若主副将均暗置，原生角色详情弹窗中的两张武将牌显示正面。扩展使用当前客户端已知的两张牌，核对登录角色和当前视角，仅替换弹窗内的牌面模型。明置任一武将后恢复原生显示，查看其他角色、旁观或回放时沿用原生显示。

## 详情中的引用

汉晋房间的头像技能页和武将详情弹窗，以及图鉴中汉晋武将的技能页，使用 [SkillReferencePane.qml](../../../pkg/qiao_mode/qml/SkillReferencePane.qml)。头像技能由原生 `Ltk.getPlayerSkills` 筛选，选将和图鉴详情由 `Ltk.getGeneralDetail` 提供。房间通过原生信息弹窗的内容变更接入，图鉴通过技能页的加载器接入。

[skill_references.lua](../../../pkg/qiao_mode/skill_references.lua) 根据公开的武将、翼从、大旗、技能和卡牌登记建立索引。军令、国战标记等采用现有翻译和已确认规则。带应变或合纵限定的明确牌名从正式牌位取得牌面，泛指牌名使用基础牌面。正文显示原有措辞，并根据牌名括号、技能和标记等上下文区分同名引用。

武将、翼从和君主大旗的引用打开 page，其他引用打开 tooltip。tooltip 中可以继续打开 tooltip 或跳转 page。点击没有子 tooltip 的 tooltip 范围外会关闭它。关闭父级或离开所属 page 时，子 tooltip 一并关闭。从 tooltip 跳转后，返回栈记录出发的 page 和阅读位置。

链接详情省略三处可从 tooltip 查阅的重复段落。诸王敕封册省略赐的出牌阶段消费说明，黄巾天兵符省略群势力用天兵转化雷【杀】的说明，勇决省略存嗣的完整括注。渲染时按实际技能 ID 匹配已核对的文本，删节结果须仍有指向该说明的可用链接。父级独有的取得、转交、阶段防止、势力人数及授技条件继续显示。牌面翻译、结算和未接入链接的界面继续读取原文。

## 诏书牌堆入口

诏书标记在角色面板上显示牌数和已经置入的花色，同花色只显示一次，按 ♠♥♣♦ 排列。移动和重连均从当前公开牌堆读取。打开标记仍可查看具体的牌。诏书公开牌堆使用原生 QML 标记注册，`EdictPile.qml` 扩展原生 `ViewPile`。持有者在同一个弹窗里操作「获得势力锦囊」，其他玩家、旁观和回放只查看牌。按钮仅在当前普通出牌请求允许发动时可点击，提交走原有主动技的客户端确认和服务端回包。技能隐藏独立的右下角按钮。旧录像的原牌堆名保留中文翻译。

牌堆、技能、公开候选或出牌请求状态变化后，房间页重新查询诏书的可用性。诏书候选在初平与敕令共用的授予入口同步。君刘协专项覆盖两种授予来源、三花色与四花色、空候选与标准回包取得游戏外实体。离屏 Qt 使用实际弹窗及替身宿主，覆盖进度条维持显示、弹窗保持打开时按钮置灰与恢复，及点击分发。原反馈联机对局和重连仍待点验。

「赐」沿用标准出牌请求的技能栏。持有量发生变化时同步独立技能，面板标记仍可查看公开名单。技能按钮打开武将牌选取窗口，选定一枚后方可确认。君司马炎专项 20/20 通过，覆盖受赠者真实技能按钮、选择与回包，及旗失去或失效后的独立结算。

### Issue #28 牌堆显示调查

诏书、烽火、创、天兵都通过 `Card.PlayerSpecial` 的正式移牌维护。锁定引擎的客户端先按 `MoveCards` 更新玩家牌堆，再把移动交给房间页。头像的 `Photo.qml` 通过特殊牌区的添加或移除调用 `getPile`，计数及查看器使用这份数据，查看器再按询问者的可见性过滤。这条链路与旗被授予或技能按钮是否亮起是独立的。

可共同影响四处界面的条件包括服务端未实际移牌、未向对应客户端下发 `MoveCards`、接收方未应用移动，或界面收到移动但未执行特殊牌区刷新。锁定引擎的 `SetPlayerPile` 只更新客户端 Lua 牌堆，单独下发该通知不会重画标记。另有一个可定位的边界，同一角色的两个特殊牌堆共用一个 QML 区域，`RoomBase.moveCards` 遇到同一来源／目的区域对象会提前返回。当前四种牌堆的常规入堆来自手牌、装备区、牌堆或处理区，服务器报告尚不能归因到这个边界。

本地未复现服务器所报的四处同时失效。排查服务器对局时，比较发生移牌的原始数据、报错客户端收到的 `MoveCards`、双方实际加载的扩展及原生客户端版本。用出问题的对局原始录像或同一房间复测分别检查入堆计数和牌面可见性。

## 实战反馈后的显示修正

- 汉晋房间沿用同一已注册桌游引擎，只替换默认房间页入口。房间页继承原生 `Room`，通过头像公开的装备区属性让双副类别坐骑占满该行。单坐骑、卸下坐骑和普通国战保留原生布局。双副类别坐骑标题通过 `ui_name` 显示牌名。
- 持旗角色公开显示带正式旗文的原生状态标记。六师率义旗显示在章武持有者处，蜀势力角色的用旗入口不单独显示旗标。敏思是出牌阶段主动技，房间规则负责独立的显示刷新，敏思标记仅发送给对应手牌持有者。手牌上限判定仍以本次摸牌与受益者为准。断肠标记随失技的武将牌移动，公开状态不包含暗将姓名或牌位。
- 乘流在富文本描述入口转义原文尖括号，原始翻译保留。汉晋技能浮窗使用纯文本，普通日志保留富文本。没有台词字幕的汉晋限定技在原生动画中显示本地化技能名。

对局中的询问按所在时点填写数字和处理对象。英魂按当前已损失体力填写选项，制衡和定澜夜明珠按当前体力上限填写提示，缘江烽火图按本次请求的实际多选上限提示。修体、集兵、破军、奋命和横江使用各自的实际数量。烈戎在支付体力后显示攻击范围增加量的上限，膂力按最终实际弃置的牌数描述回复。有无对局状态都使用卡面原文查看武将技能描述。

### 对局文本本地化

原生战报和技能浮窗直接读取触发回调的技能 ID。「破军」返还和「横江」弃牌阶段后续的 ID 由独立结算技能提供，因此原技能名已经有翻译时仍可能显示 ID。后续结算及其派生效果在战报和触发顺序选项中显示来源技能名，覆盖破军、横江、烈医、遄征、好施和缘江烽火图。同名来源只复制已登记的说明，避免详情把缺失翻译时返回的查找键作为正文。另补实际势力键 `jin`、烈刃拼点赢后的选牌请求，以及并州狼骑距离、八阵兵、飞影来源和飞影四个公开标记。

回归覆盖破军归还、横江弃牌阶段后续的原生战报和烈刃获牌请求。翻译专项从扩展的发布包登记遍历 137 张武将牌和 83 种卡牌，排除使用相同扩展名的测试夹具。离屏 Qt 用原生详情、提示和标记格式化函数核对晋势力、烈刃目标名、触发顺序选项和四个公开标记。

承诏的【杀】在 `TargetConfirmed` 通过锁定引擎的青釭标记落实无视防具，只处理本次用牌数据中明确标记的目标。这个刷新没有独立的发动历史。双雄、双刃及同结构的突袭在 `TurnEnd` 普通触发结束后回收转化权限，日志显示「效果结束」。它们的回收各自作用于自己的权限，无需弹出排序。

戡难的角色标记显示待消费的加伤总量，使用下一张【杀】后消失。乱击通过 QML 标记渲染本回合已用花色，克清显示仍有效的来源数。翼从的公开实例摘要继续供客户端判定，汉晋房间不把它交给头像标记栏。

持续影响玩家决策的特殊状态通常需要在角色头像或相关牌面显示。验收同时检查状态建立、相关数量或限制变化，以及消耗或到期后的移除。

红颜沿用锁定国战 `packages/hegemony/pkg/standard/skills/hongyan.lua` 的锁视机制。汉晋客户端的手牌数据显示印刷花色和颜色，牌的实际花色、判定和请求筛选仍使用有效值。结算区的虚拟牌及转化牌从正式牌 ID 查找汉晋插画，实体素材参与结算的方式保持引擎流程。

此次检查了汉晋技能与卡牌的直接请求和主动技能提示，补齐只显示名称的选项或选牌说明，并校正源角色、目标角色和数值的参数位置。离屏验证用锁定客户端的 `processPrompt` 执行 13 个代表性载荷，检查实际文本中的角色和数值。


## 开局预亮与技能发动请求

当前分支在最后一个初始手牌事件结束时广播一次 3 秒读条，并由服务端等待后再进入首轮。汉晋房间页在顶部显示进度条，预亮继续走原生交互。验收范围见[开发状态](../status.md#最近验证记录)。

汉晋房间以 `skill_prelight.canPrelight` 判断暗将技能是否有实际可触发的非延迟效果。内部刷新使用引擎的 `TriggerSkill` 类，但该类也承载只记账的回调。主动或转化入口按出牌、响应请求启用。限制预亮后，正常技能通知、重连快照和视角重建都保留普通按钮或技能说明。重连的普通按钮同时恢复到客户端请求使用的技能列表，服务端拒绝没有预亮入口的技能的预亮请求。

实战反馈表第 29 项横查了 46 个主动入口和 15 个转化入口，含模式提供的【合纵】。原生普通技能通知会为主动技【三陈】【遄征】【谋诛】及转化技【滔乱】的内部刷新生成预亮按钮。【济世】的触发回调只记录已经转化的【桃】，同样关闭预亮。重连快照和视角重建会直接从暗将技能列表生成预亮按钮，涉及【仁德】【合纵】等技能。【敏思】此前的重连特例也改走通用判断。鸟翔、锥形、应期仍显式关闭预亮。初平、天授、咆哮、【武圣】及【尚义】的真实触发部分仍可预亮。【看破】在刷新回调里提供回合末询问，显式保留预亮。[误判复盘](../lessons.md#把暗将技能登记误判为可预亮实战反馈表第-29-项)

拥有锁定技的暗置武将牌仍通过引擎的 `reveal_skill&` 在自己的出牌阶段主动明置。该普通出牌请求与状态类技能的预亮入口分别校验，面板重建后仍归在主动按钮中。

### 发动时需要玩家决定的输入

- 可选触发的目标和当时可确定的费用通过同一界面选择。进入界面时必选项缺失则「确定」置灰，选够目标和牌后才可提交。需要选择一名角色或一张牌且候选唯一时，界面直接选中对应的头像或牌，保留确定、取消和手动取消选中。仍需选多张牌时按规则检查数量。
- 唯一候选仍走原生选人、选牌、联合选择或用牌请求。暗置技能确认选择后，引擎正常执行明置与技能结算；一次有效的确认足以发动。目标或牌来自后续独立效果时，依该效果实际的候选和时序询问。
- 【流离】与【剽戮】通过[牌和目标联动选择](../../../pkg/qiao_generals/util/card_target_selection.lua)共用原生可取消请求。技能提供每张候选牌对应的合法目标，客户端按先选的牌或目标筛选另一项，服务端在技能按当时状态复核前先检查回包是否属于请求中的合法组合。
- 【天香】先执行弃牌和防止伤害，再选承受后续伤害的角色；【潜袭】【遗计】【腹心死士】交牌分支与【苦肉】在前序效果完成后才知道牌的候选。【前驱】允许确认发动后放弃其用牌收益。【天命】没有可弃手牌时仍可确认摸牌。相关验收见[客户端验收记录](../testing.md#客户端验收记录)。
- 「横置或重置」「叠置或平置」通过 `state_toggle.ask` 在一次请求内选人或取消，结算用 `state_toggle.chain` 或 `state_toggle.stack` 读取目标当时状态。柔克选至多两名，太公阴符选一名。铁索连环直接处理已选用牌目标。只写单个动作的效果按定向操作处理。规则见[武将状态通用约定](../../rules/general-principles.md#配将体力贡献与武将状态)。

#### 发动时直接选择选项

发动时需要选费用，或需要在无费用的效果中选择第一个动作时，直接发送启用选项、置灰选项和取消。服务器使用引擎的单选请求，出牌阶段仅需选项即可发动的技能使用原生选项栏。较短选项使用完整文字，长项使用短按钮和独立说明。只有一个合法选项时也显示该选项。允许任选数项时，可用的组合也可一次点选。

## 私看手牌并操作其中的牌

允许选取或弃置他人的暗手牌时，按操作者原有的可见性显示候选。自定义候选列表须带 `visible_data`，服务端按实际区域和合法候选复核回包。交互是否出现也可能泄露暗牌信息。能被其他角色观察到的请求，应依据公开条件决定是否展示；牌的隐藏花色、类别等由持牌人自己的请求和服务端校验处理。

技能要求「观看手牌」并弃置、获得或操作其中的牌时，观看和决定操作使用同一个私密面板。操作方能正面查看整手牌，只有满足技能条件的牌可以选。用 `askToChooseCardsAndChoice` 向操作方单独发送请求，`all_cards` 是完整手牌，`cards` 是合法候选。确认后由服务端复核牌的归属、区域和操作条件，再执行移动。观看期间其他角色的可见性保持原有规则。[观看](../../../rulebook/terms/card-op-terms/watch.md)

可选操作应提供「结束观看」。只有一张合法牌且操作必做时，观看后自动处理这张牌。有其他结算分支的技能保留该分支的顺序，例如伪溃看到【闪】时先观看，随后按技能结算【杀】。攻心、伪溃和尚义共用此交互。尚义让对方观看自己的手牌和查看对方暗将仍按原时序执行。[攻心的原生面板](https://github.com/SSadamune/Free-kill-hanjin/pull/17) · [Issue #27 补充反馈](https://github.com/SSadamune/Free-kill-hanjin/issues/27#issuecomment-7038741069)

## 交牌和获得牌的可见性

普通交牌或取得他人牌时，交牌人与收牌人能看到具体牌面，其他角色按本次移动中每张牌的来源区域和查看权限显示。调用 `room:obtainCard` 或 `room:moveCardTo` 将手牌移入另一名角色手牌区时，使用 `visible = false`。即使在同一批移动中，原装备区或判定区的牌仍然公开。如【反间】要求先展示再交给，交牌时继续公开。移动动画与战报都使用引擎的 `Player:cardVisible(id, move)`。[手牌区](../../../rulebook/terms/zone-terms/handArea.md) · [移动事件](../../../rulebook/events/move-card.md#附同时移动多张牌的流程)

| 时机 | 调用与用途 |
| --- | --- |
| 【护援】选择要弃置的牌 | 拆他人牌沿用区域参数 `hej`，由原生请求按手牌、装备、判定区分行并遮蔽暗牌。曹洪选自己的牌时按原区域组织筛选后的候选，服务端在执行前复核牌所属区域和自己的禁弃限制。 |
| 【疲攻】等技能实际交牌或取牌 | 客户端以 `Self:cardVisible(id, move)` 逐张决定本座位看到的移动动画和战报。 |

持续公开牌面的技能可使用 [card_visibility.atLocation](../../../pkg/qiao_mode/rules/card_visibility.lua) 声明哪些座位能看见哪个位置的哪张牌。手牌转手时，引擎已经更新牌主，公共接口用本次移动的原牌主、原区域与移动前的牌面标记判断这一次移动。随后查看手牌时重新按当前位置判断。例如【昭然】的【桃】被【白马义从】拿走，全桌看见这次移动，收牌人的普通手牌区随即恢复按其自身权限显示。【西园军】按实体牌的标记公开，同批交出的其他手牌仍各自判断。
