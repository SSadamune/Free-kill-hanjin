# 技能选项、按钮与头像详情

## 右下角技能栏调查

锁定的新月杀 v0.5.25 从 `LunarLtk/Components/Dashboard.qml` 直接创建 `SkillArea`。`SkillArea.qml` 将中文界面的预亮、主动和普通技能固定为 2、2、3 列，视口最多 180 px，内容取三组网格中最宽一组并右对齐裁剪。`SkillButton.qml` 的主动及预亮按钮至少 80 px，普通按钮宽度取文字宽度，字号缩到 18 px 后仍可随文字变宽。多个长标签同列或同组时会撑宽网格；实际裁剪和滚动边界随字体、缩放和技能组合变化。

汉晋房间页复用原生 `SkillArea`，在技能栏模型更新后调整标签。有四个及以上汉字的非点选项，若属于君主旗、翼从或其他非武将／非装备来源，从技能栏移除。主动、视为和预亮入口继续显示，武将技能和装备技能沿用原有显隐。三个及以下汉字的标签沿用全名。

技能栏简称按技能 ID 配置。例如六师率义旗显示为「六师」，并州狼骑显示为「并州骑」，血海魔王樽显示为「魔王樽」。保留的其他长标签取前三个汉字。按钮点击仍提交原技能 ID，完整名称用于技能详情、牌面和询问。方天画戟与州郡领兵印沿用现有装备显示和触发询问。

## 头像右键技能详情

`LunarLtk/Pages/Room.qml` 的头像右键事件直接打开 `InfoPopups/PlayerDetail.qml`。该弹窗通过 `Ltk.getPlayerSkills` 获取可见技能名称和描述，在技能页逐行显示，装备区、判定区和已知牌使用各自的页面。当前接口没有来源字段，也没有为该弹窗单独登记页面的入口。要在默认弹窗增加来源分组，需要上游支持来源元数据和分组渲染。扩展可以在已有描述中标注真实来源，沿用引擎对本人和其他角色的可见性规则。

当前 `skill_source_labels` 在正式扩展注册后给诏书、君主旗、统领、翼从的描述加来源标签。诸王敕封册另标注赐的消费入口，描述不列举持有的赐。武将牌技能与装备沿用原描述。按钮悬浮说明共用这条描述路径，也会带标签。`standard_generals` 13/13 通过，覆盖正式注册后的 `Fk:getDescription`、统领动态描述及技能名称，未进行真人点击验收。

## 诏书牌堆入口

诏书公开牌堆使用原生 QML 标记注册，`EdictPile.qml` 扩展原生 `ViewPile`。持有者在同一个弹窗里操作「获得势力锦囊」，其他玩家、旁观和回放只查看牌。按钮仅在当前普通出牌请求允许发动时可点击，提交走原有主动技的客户端确认和服务端回包。技能隐藏独立的右下角按钮。旧录像的原牌堆名保留中文翻译。

牌堆、技能、公开候选或出牌请求状态变化后，房间页通知诏书及「赐」的可用性重新查询 Lua。诏书候选在初平与敕令共用的授予入口同步。君刘协专项覆盖两种授予来源、三花色与四花色、空候选与标准回包取得游戏外实体。离屏 Qt 使用实际弹窗及替身宿主，覆盖进度条维持显示、弹窗保持打开时按钮置灰与恢复，及点击分发。原反馈联机对局和重连仍待点验。

### Issue #28 牌堆显示调查

诏书、烽火、创、天兵都通过 `Card.PlayerSpecial` 的正式移牌维护。锁定引擎的客户端先按 `MoveCards` 更新玩家牌堆，再把移动交给房间页。头像的 `Photo.qml` 通过特殊牌区的添加或移除调用 `getPile`，计数及查看器使用这份数据，查看器再按询问者的可见性过滤。这条链路与旗被授予或技能按钮是否亮起是独立的。

可共同影响四处界面的条件包括服务端未实际移牌、未向对应客户端下发 `MoveCards`、接收方未应用移动，或界面收到移动但未执行特殊牌区刷新。锁定引擎的 `SetPlayerPile` 只更新客户端 Lua 牌堆，单独下发该通知不会重画标记。另有一个可定位的边界，同一角色的两个特殊牌堆共用一个 QML 区域，`RoomBase.moveCards` 遇到同一来源／目的区域对象会提前返回。当前四种牌堆的常规入堆来自手牌、装备区、牌堆或处理区，服务器报告尚不能归因到这个边界。

本地未复现服务器所报的四处同时失效。排查服务器对局时，比较发生移牌的原始数据、报错客户端收到的 `MoveCards`、双方实际加载的扩展及原生客户端版本。用出问题的对局原始录像或同一房间复测分别检查入堆计数和牌面可见性。

## 实战反馈后的显示修正

- 汉晋房间沿用同一已注册桌游引擎，只替换默认房间页入口。房间页继承原生 `Room`，通过头像公开的装备区属性让双副类别坐骑占满该行。单坐骑、卸下坐骑和普通国战保留原生布局。双副类别坐骑标题通过 `ui_name` 显示牌名。
- 持旗角色公开显示带正式旗文的原生状态标记。六师率义旗显示在章武持有者处，蜀势力角色的用旗入口不单独显示旗标。敏思是出牌阶段主动技，房间规则负责独立的显示刷新，敏思标记仅发送给对应手牌持有者。手牌上限判定仍以本次摸牌与受益者为准。断肠标记随失技的武将牌移动，公开状态不包含暗将姓名或牌位。
- 乘流在富文本描述入口转义原文尖括号，原始翻译保留。汉晋技能浮窗使用纯文本，普通日志保留富文本。没有台词字幕的汉晋限定技在原生动画中显示本地化技能名。

对局中的询问按所在时点填写数字和处理对象。英魂按当前已损失体力填写选项，制衡和定澜夜明珠按当前体力上限填写提示，缘江烽火图按本次请求的实际多选上限提示。修体、集兵、破军、奋命和横江使用各自的实际数量。烈戎在支付体力后显示攻击范围增加量的上限，膂力按最终实际弃置的牌数描述回复。有无对局状态都使用卡面原文查看武将技能描述。

承诏的【杀】在 `TargetConfirmed` 通过锁定引擎的青釭标记落实无视防具，只处理本次用牌数据中明确标记的目标。这个刷新没有独立的发动历史。双雄、双刃及同结构的突袭在 `TurnEnd` 普通触发结束后回收转化权限，日志显示「效果结束」。它们的回收各自作用于自己的权限，无需弹出排序。

戡难的角色标记显示待消费的加伤总量，使用下一张【杀】后消失。乱击通过 QML 标记渲染本回合已用花色，克清显示仍有效的来源数。翼从的公开实例摘要继续供客户端判定，汉晋房间不把它交给头像标记栏。

持续影响玩家决策的特殊状态通常需要在角色头像或相关牌面显示。验收同时检查状态建立、相关数量或限制变化，以及消耗或到期后的移除。

红颜沿用锁定国战 `packages/hegemony/pkg/standard/skills/hongyan.lua` 的锁视机制。汉晋客户端的手牌数据显示印刷花色和颜色，牌的实际花色、判定和请求筛选仍使用有效值。结算区的虚拟牌及转化牌从正式牌 ID 查找汉晋插画，实体素材参与结算的方式保持引擎流程。

此次检查了汉晋技能与卡牌的直接请求和主动技能提示，补齐只显示名称的选项或选牌说明，并校正源角色、目标角色和数值的参数位置。离屏验证用锁定客户端的 `processPrompt` 执行 13 个代表性载荷，检查实际文本中的角色和数值。


## 开局预亮与技能发动请求

当前分支在最后一个初始手牌事件结束时广播一次 3 秒读条，并由服务端等待后再进入首轮。汉晋房间页在顶部显示进度条，预亮继续走原生交互。验收范围见[开发状态](../status.md#最近验证记录)。

汉晋房间以 `skill_prelight` 识别只有状态效果或内部刷新的技能。暗置时面板保留技能说明，服务端统一拒绝其预亮请求。视角切换的面板重建使用同一判断。鸟翔、锥形利用引擎事件写入响应次数或伤害修正，应期通过配将流程计算，三者明确标记为状态类技能。初平、天授有实际结算时机，沿用现有处理。咆哮等混合技能的触发部分沿用原生预亮。

拥有锁定技的暗置武将牌仍通过引擎的 `reveal_skill&` 在自己的出牌阶段主动明置。该普通出牌请求与状态类技能的预亮入口分别校验，面板重建后仍归在主动按钮中。

### 发动时需要玩家决定的输入

- 先确定费用、首个动作以及后续动作依赖的状态。发动时合并需要手动选择的目标和当时可确定的费用；无费用且首个动作操作自己的牌时，也可直接用该选择确认发动。自己的牌从手牌区或规则允许的装备区选。缔盟、结姻、用良覆盖牌与目标同选；定著覆盖有先后顺序的两个目标。
- 候选唯一或范围已固定时，只询问玩家仍有权决定的内容。例如谋溃只有一个目标时确认发动，天命必须弃尽可弃手牌时直接确认，博通只确认是否把仍在处理区的本次转化材料交出及接收者。火攻强制展示唯一手牌时自动选中，但后续弃牌仍可取消。
- 若候选、牌的归属或可见性依赖前序效果，等它结算后再询问。例如苦肉先失去体力，让诈降摸牌结算完毕，再选要交出的牌和接收者；四海流钱先指定目标，再选择其牌。牛金直接询问使用牌，每次实际用牌结算后更新尚可用的类别。相关验收见[客户端验收记录](../testing.md#客户端验收记录)。

## 私看手牌并操作其中的牌

技能要求「观看手牌」并弃置、获得或操作其中的牌时，观看和决定操作使用同一个私密面板。操作方能正面查看整手牌，只有满足技能条件的牌可以选。用 `askToChooseCardsAndChoice` 向操作方单独发送请求，`all_cards` 是完整手牌，`cards` 是合法候选。确认后由服务端复核牌的归属、区域和操作条件，再执行移动。观看期间其他角色的可见性保持原有规则。[观看](../../../rulebook/terms/card-op-terms/watch.md)

可选操作应提供「结束观看」。只有一张合法牌且操作必做时，观看后自动处理这张牌。有其他结算分支的技能保留该分支的顺序，例如伪溃看到【闪】时先观看，随后按技能结算【杀】。攻心、伪溃和尚义共用此交互。尚义让对方观看自己的手牌和查看对方暗将仍按原时序执行。[攻心的原生面板](https://github.com/SSadamune/Free-kill-hanjin/pull/17) · [Issue #27 补充反馈](https://github.com/SSadamune/Free-kill-hanjin/issues/27#issuecomment-7038741069)
