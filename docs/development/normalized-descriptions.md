# 卡面描述与规范描述

本文是规范描述的编写指南，不是《汉晋规则集》的正式条文，也不宣布现有武将和卡牌已完成规范化。正式规则集的组织、格式与文风应接近外部《三国杀规则集》，精炼表达术语和流程；项目实现报告不直接转换为正式条文。

## 三种表达

| 表达 | 用途 | 边界 |
| --- | --- | --- |
| 卡面描述 | 让玩家理解技能、效果及操作 | 可使用规则允许的缩写；不能凭日常语言取代术语定义 |
| 规范描述 | 作为《汉晋规则集》的一部分，精确规定事件、主体、条件、消耗、效果及顺序 | 是游戏结算的抽象表达，不是 Lua 代码、逐行注释或测试报告 |
| 程序实现 | 在锁定的新月杀引擎中执行上述语义 | 引擎事件和数据结构须适配规则；实现差异需要修复或经裁定修订规则 |

现有[标准武将表](../../rules/standard-generals.md)中的「技能原文」作为卡面描述资料保留；逐将裁定草案也不能仅改标题就视为定稿规范描述。

## 编写与核对

- 按[基础描述术语](../../rulebook/terms/description-terms/limit_card.md)及对应事件定义展开语义，说明操作者、目标对应角色、牌区、时点与结算顺序。并非每个技能都要机械填写相同字段；使用规则集针对该类效果已有的结构。
- 明确可选发动、发动消耗、作用效果和延后执行的动作；数量、范围、“然后”、使用与打出等概念按其规则定义解释。
- 继承外部基准的部分注明来源；汉晋修改或新增的部分单独说明；未裁定的分支明确标注，不把实现选择写成已确认条款。
- 使用 `▶`、`❶` 等符号或具体时机名称前核对相关原文，不从例子自行发明通用语法。规范描述中的事件应能与实现事件对应，但正文不以 `ServerPlayer`、`extra_data` 等引擎细节作为游戏概念。
- 对照卡面描述、规范描述、实现和关键测试检查同一含义；测试暴露歧义时先查定义及既有裁定，不能为了适应现有代码而静默改变规范描述。

## 描述层次示例

以下由用户提供的参考例子说明规范描述的精度，不是本轮对汉晋对应卡牌版本或效果作出的新增裁定，也不表示已完成实装核验。

【贯石斧】：

> **武器技能**　当你使用的【杀】被其中的一个目标对应的角色使用的【闪】抵消后，若其存活，你可弃置两张牌▶不会因此【闪】的抵消而不会生成“此【杀】对此目标生效时”和“此【杀】对此目标生效后”这两个时机。

【五谷丰登】：

> **使用时机**　出牌阶段。
>
> **使用目标**　所有角色。
>
> **执行动作**　1.当此牌的使用结算准备工作结束时，系统亮出牌堆顶的X张牌（X为此牌的目标对应的角色数）。2.当此牌的使用结算结束后❶，你将处理区里的以此法亮出的牌置入弃牌堆。
>
> **作用效果**　目标对应的角色获得这些牌中的一张。

前者明确抵消后的条件、消耗与对后续时机的影响；后者区分整张牌的执行动作与对每个目标的作用效果。这种区分是后续规范描述需要保持的语义精度。
