# 测试分层与验收范围

本约定适用于本项目的技能、卡牌与公共规则开发。规则结算场景用于说明正确行为；**不等于每个场景都必须新增独立自动化测试**。Codex 在每轮交接中按实际风险确定少量核心验收项，DSH 不自行将整份规范扩成逐项测试任务。

## 三层测试

| 层级 | 用途 | 默认处理 |
| --- | --- | --- |
| 核心行为 | 新功能的正常流程、关键分支、明确改写的规则及容易实现错误的交互 | 本轮必须验证；相关输入可合并为参数化用例，不按文字条目机械拆分 |
| 公共机制回归 | 已由引擎或项目公共套件覆盖的响应、防具、一般牌移动、阶段历史、基础国战流程等 | 复用已有覆盖；技能只补接线处的代表性集成测试，不重复验证整套公共机制 |
| 风险边界 | 特殊连锁、中途死亡、复杂替代、异常提交、少见多技能组合等 | 出现具体疑点、修复回归或改动公共入口时补测；无依据的排列组合不列为默认阻塞项 |

同一机制按改动调整层级：例如明暗置是公共机制，但技能自行预测明置后势力时，预测与真实结果一致就成为本技能的核心验收风险。不得以“公共机制”为由跳过新代码引入的风险。

## 早期接入与验证

1. 实现前用简短说明确定规则时机、消耗与效果、技能来源、目标条件，列出真正未明确的问题；核对所用回调的执行端、事件数据类型及锁定引擎中的接口。引用已有公共转换、应变和目标策略，不为每个技能重写公共流程。
2. 先打通正常流程及关键分支。复用上游技能时，获得技能或装备安装成功不能代替效果验收；至少触达一次主要效果，有特殊接口的分支需定向验证。例如方天画戟应覆盖扩目标后被闪抵消，而不只检查装备技能已附加。
3. 客户端判定尽早使用真实 `ClientPlayer` 和请求处理器验证，涵盖可用性、候选、确认及取消。提示文本须表达真实数量与限制；需要单选的界面应按单选操作验收，不能只靠确认按钮拒绝多选。涉及客户端基础设施时，增加进房、重连和普通模式隔离的针对性验收，自动化与人工结果分别记录。
4. 先定向后默认全量。涉及发布路径时，构建安装包并核对实现与注册代码已包含、开发脚本及本体补丁未混入；客户端功能应能由正式扩展加载，不能仅在已修改的开发本体中生效。需要成品运行验证时使用未应用开发适配的本体验证。

以上不是每个技能固定新增一组测试的要求；已有覆盖可复用，新入口、特殊接口或改动过的交互才补相应验证。

## 夹具与失败诊断

- 夹具应明确建立本例所需状态，并检查关键前置条件。更换国战双将时，处理原暗将技能、预亮状态、技能来源、势力与相关标记；不能只修改将面和当前势力。使用引擎或项目已有流程清理来源，重复准备操作适合在确认共性后提取为少量公共辅助函数。
- 普通功能测试建立明确场景；随机初始化可作补充稳定性验证。随机失败时记录可复现输入或初始双将、关键标记、技能状态和请求／回复消费，再把已确认原因缩成确定性回归。固定种子可用于复现，不能用特定种子掩盖失败。
- 首次出现间歇失败即保留为未解决问题，不能凭随后一次通过认定已排除，也不能无证据归因为“时序抖动”或“既有问题”。区分断言失败、夹具污染、进程启动失败和测试未执行；模型自述不代替命令输出。稳定性重复运行只用于验证具体修复，不用于刷出全绿。
- 用实际触发、回复、牌移动、使用次数和伤害等可观察结果验收；避免只调用效果函数而绕开本次需要验证的发动和客户端流程。

## 故障记录的保留范围

有明确复用价值的故障保留简短的“现象／触发条件、根因、修复方式、回归入口”，放在所属武将或公共机制的现有规范中。通用约定集中写入本文或项目约定，由案例引用，不重复另定规则。记录应能帮助后来者识别同类问题，不累积完整聊天、逐轮尝试、催办过程或重复的历史测试数量。

案例修复后标明已修复；未确定的根因标明仍在调查，不写成既定结论。临时诊断文件在交付前决定移除或整理为正式工具，不能仅以临时文件名长期混入默认开发入口。

## 执行与停止条件

1. 首轮优先交最小可运行实现和核心测试；审阅后只补明确缺口。默认不要求完整场景映射表、固定测试数量或每轮独立子代理审阅。
2. 开发中先运行相关定向套件。相关改动稳定后运行一次 `python scripts/test.py`，保留默认国战套件作为最终验收入口；不以精简为由跳过项目必需检查。
3. 已通过检查只有在新增相关修改、出现失败或仍有明确疑点时才重跑。相同问题两次尝试未解决时交回证据与阻塞，不无限扩测试夹具或连续重跑全量套件。
4. 同一轮以约 10–15 分钟为交付预算，约每 5 分钟简报；到预算或里程碑即交回阶段成果。阶段成果可未完成，但须说明尚未验证的风险，不能写成已验收。
5. 交付仅需改动文件、完成能力、真实执行命令／结果与未完成项。可用合并场景说明覆盖，不要求一条规则对应一个测试函数。

## 保留与精简

- 优先合并同一逻辑分支的重复准备与断言，避免用例间状态泄漏；测试应验证可观察结果或实际事件，避免只模拟并重复实现内部算法。
- 不为减少数字而删除已有有效回归。删除或合并必须确认覆盖没有丢失；测试代码减量可单独安排，不阻塞与其无关的技能交付。
- 公共套件的失败应区分本次回归与已有问题，不屏蔽失败、不通过修改预期凑通过。
- 汉晋技能 `addTest` 仅在汉晋测试房间运行；新技能测试纳入默认国战套件。`--skills` 使用官方默认房间，仅作工具或上游测试验证，不代替汉晋行为验收。
- `rules/` 的进度由 Codex 依据可核验交付更新。DSH 默认只读；计划、模型自报及未执行用例不能写成验证通过。
