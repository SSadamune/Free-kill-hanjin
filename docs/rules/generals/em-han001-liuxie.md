## 采用版本与来源差异

[药枫 CSV](../../../assets/docs/药枫桑大合集337.csv)“君·刘协”的天授第一段是“其他角色的【玉玺】或【赤霄剑】进入场上或弃牌堆后，你将之置入装备区”，而 JSON 是“置入……时，改为”。用户确认本将以石激桑 JSON 为基准，采用原移动的替换，不先完成原移动再取得。

## 初平与诏书

**技能原文**：初平：君主技，此武将牌明置后，你获得游戏外的“诏书”；你因“诏书”获得的势力锦囊由你选择。

**关联牌原文**：与你势力相同的角色出牌阶段限一次，其可以将一张（若为小势力则改为至多两张）手牌置于此牌上。出牌阶段限一次，若此牌上的牌包含四种花色，你可以移去此牌上的所有牌，然后随机获得一张势力锦囊。

明置时机绑定这张君主牌，不能因副将明置重复取得。初平赋予的是下述特殊标记，不是从游戏外生成一张手牌；不能把取得诏书标记触发为得到手牌或装备进出事件。升变、继位须经过正式公共入口，不能用开局直接发诏书代替。

交牌入口只允许手牌，非小势力一张、小势力至多两张，仍须实际交牌。“与你势力相同”含自己。其他角色按公开势力判断，各自独立的野心家不能互缴；“小势力”采用[定义](../../../rulebook/terms/description-terms/xiaoshili.md)，没有大势力不等于人人小势力。检查四种花色时，天授置于诏书的装备也依牌面花色参与，不能只计算由交牌入口进入的手牌。

消耗原文为“所有牌”，不能只移去凑齐四种花色的四张。初平把此途径的“随机获得”改为君刘协选择；势力禁选、实体可用性和默认牌堆的限制仍适用。

### 诏书的对象裁定

用户确认：本模组的“诏书”**永远是特殊标记，不是实体牌，不会进入手牌或玩家的任何区域**。来源的 `banner` 字段及“获得游戏外”不改变这一对象性质，不能按普通宝物、游戏外装备或可抢夺手牌实现。

诏书标记与“置于诏书上”的实体牌分别处理：标记记录拥有状态，关联实体牌按交牌、四花色消费和天授的效果移动与记账；不为标记本身创建实体牌 ID 或执行牌移动。

## 转蓬

**技能原文**：转蓬：当你成为伤害牌的唯一目标后，你可以交给使用者一张牌并令此牌对你无效；若你已使用过其势力锦囊，改为其需交给你一张牌，否则此牌对你无效。

应在“成为目标后”核对当时唯一目标及伤害牌属性，不限于杀或已实际造成过伤害的牌。普通分支由君刘协选择一张合法牌交给使用者，支付成功后令该伤害牌对自己无效。“无效”不等于取消目标，不应删除后续本应存在的用牌时机。

满足“已使用过其势力锦囊”时，执行替代分支，由使用者交给君刘协一张牌；使用者未实际交牌才令该牌对君刘协无效。不得同时再收取君刘协一张牌。记录是全局已使用过的事实，不因换回合清空；获得但没使用、仅把牌打出，均不等于使用过。势力条件按使用者所指的势力锦囊核对，野心家也有其已登记锦囊，不能漏掉洛水之誓；不查看未公开的他人将牌以推测其势力。

刘协选定一张合法牌并执行交牌动作，即支付了【转蓬】的[发动消耗](../../../rulebook/definitions/skill-elements.md#有消耗)，原伤害牌对其无效。例如交出装备区的【赤霄剑】或【玉玺】时，【天授】将该牌改置于诏书，刘协照常摸两张牌，使用者没有收到该牌也不影响支付。反向分支须由刘协实际收到使用者给的牌。

## 天授

**技能原文**：天授：锁定技，其他角色的【玉玺】或【赤霄剑】置入场上或弃牌堆时，改为置入你装备区。当你从装备区失去这些牌时，改为置于“诏书”上并摸两张牌。

两段都是移动替换，须在移动发生前拆出对应实体改写去向，不能移动完成后再抢回。识别独立正式 ID；其他角色之外无持有者的牌堆／弃牌堆不冒充“其他角色的牌”。自己的装备离开时改置于诏书，并摸两张，不另执行原去向。同批弃置又触发君刘备【天钺】时，两项替换各自处理对应的牌，见[君刘备·天钺](em-shu001-liubei.md#天钺)。

须遵守装备栏、禁移效果及替换优先顺序。原文没有特殊授权忽略[空栏要求](../equipment-movement.md)，不能直接顶掉已有武器／宝物；不能按上游强制置入接口默认行为反推规则。重写一次移动后须防止自身拦截再次递归。天授移动的是玉玺／赤霄剑等实体牌，不是诏书标记；实现必须区分标记拥有状态与其上实体牌的记录。

## 依赖与核心验收

现有天钺的 `BeforeCardsMove` 分拆流程可参考，但取得到手牌与置入装备区不同；君刘协还多出装备→诏书的联动，不能原样复制。转蓬使用锁定引擎 `TargetConfirmed`／`AimData` 的唯一目标、对目标无效接口，服务端处理给牌，客户端仅接收可公开的信息。

诏书、转蓬和天授的实现见[第二君主实现](../../development/implementation/second-lord.md)。诏书可取得的势力锦囊按[各牌的结算规则](../card-deck.md#势力锦囊的结算审阅)执行，验收进度见[开发状态](../../development/status.md)。
