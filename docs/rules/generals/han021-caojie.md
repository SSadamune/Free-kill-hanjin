## 守玺

**技能原文（JSON）**：守玺：与你势力相同的角色装备区的一张牌被其他势力角色不因弃置而移动时，你可以弃置一张同花色的牌并防止之。

**来源差异（CSV）**：[药枫 CSV](../../../assets/docs/药枫桑大合集337.csv) 写作“与你势力相同的角色装备区的牌被**另一名角色弃置或获得**时，你可以弃置一张与该牌花色相同的**手牌**，防止此次移动。”两份资料在移动原因（非弃置移动 vs 弃置或获得）、操作者范围（其他势力角色 vs 另一名角色）和弃牌区域（牌 vs 手牌）三处均不同。

**结算分析（按 JSON 口径）**：
- 触发条件：与曹节势力相同的角色（含曹节本人，按[同势力判定](../general-principles.md)）装备区里有牌即将因**其他势力角色**（按[其他势力口径](../general-principles.md)，含未确定势力角色）的操作而移动，且移动原因**不是弃置**（涵盖获得、移动至其他角色装备区、置入牌堆/武将牌上、移出游戏等，不包含【过河拆桥】等弃置）。
- 发动消耗：曹节弃置一张与该即将移动装备牌花色相同的牌（手牌或装备区牌均可，须排除无花色牌与花色不符牌）；实际弃置后防止该张牌的本次移动。
- 单次移动事件同时涉及同势力角色装备区多张牌时，应明确是逐张分别触发还是单次询问。

**待主创确认**：
1. 【守玺】采用 JSON 版本（“其他势力角色不因弃置而移动 / 弃置同花色牌”）还是 CSV 版本（“另一名角色弃置或获得 / 弃置同花色手牌”）？按本项目既有惯例拟采用 JSON，请确认。
2. 当其他势力角色令同势力角色装备区的**多张牌**同时不因弃置而移动（例如交换装备区【甘露】或一次获得多张装备）时，【守玺】是针对其中每张牌分别触发并可分别防止，还是仅可选择其中一张，抑或防止整次移动？

## 悬壶

**技能原文（JSON）**：悬壶：每回合结束时，若本回合你的红色牌置入过弃牌堆，你可以令一名角色摸或弃置一张牌，然后若其手牌数等于体力值，其回复1点体力。

**来源差异（CSV）**：[药枫 CSV](../../../assets/docs/药枫桑大合集337.csv) 写作“每名角色的**结束阶段**，若你本回合有红色牌置入弃牌堆，你可以令一名角色**摸一张牌**，然后若其手牌数等于体力值，其回复1点体力。”（时机为结束阶段而非回合结束时，且不可选择弃置。）

**结算分析（按 JSON 口径）**：
- 触发时机为**每回合结束时**（回合级时机，见[通用约定](../general-principles.md#易读描述的时机与然后)），即使跳过结束阶段仍可触发。
- 条件判定：“本回合你的红色牌置入过弃牌堆”检查本回合内是否存在原归属为曹节（手牌区/装备区/判定区或本回合曹节使用、打出、弃置、被弃置等失去）的实体红色牌进入过弃牌堆。
- 效果结算：选择一名在场角色并决定令其摸一张牌或弃置一张牌（若选弃置，该角色须有可弃置的牌）；执行完毕后，若该角色当前手牌数等于其当前体力值，则回复 1 点体力（未受伤则不回复）。
- “摸或弃置”的选择权在曹节还是目标角色，须明确。

**待主创确认**：
1. 【悬壶】采用 JSON 版本（回合结束时 + 摸或弃置一张牌）还是 CSV 版本（结束阶段 + 仅摸一张牌）？拟采用 JSON，请确认。
2. “令一名角色摸或弃置一张牌”是由**曹节**决定摸还是弃，还是由**目标角色**二选一？（按“你可以令一名角色摸或弃置一张牌”的常见国战语法，通常由曹节选择；请确认。）
3. “你的红色牌置入过弃牌堆”是否仅统计从曹节区域（手牌/装备/判定区）进入弃牌堆的红色牌，包含曹节本回合使用/打出经处理区进入弃牌堆的红色牌，但不包含曹节摸牌/拼点/判定直接从牌堆顶进弃牌堆的牌？
