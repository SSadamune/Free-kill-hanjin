## 应政

**技能原文（JSON）**：应政：与你势力相同的角色回合内限一次，当其使用应变牌后，其可以令你获得此牌，然后若此牌触发应变，你可以令其变更副将（限一次）。

**来源差异（CSV）**：[药枫 CSV](../../../assets/docs/药枫桑大合集337.csv) 写作“与你势力相同的角色**出牌阶段**限一次”（JSON 为“回合内限一次”）。

**结算分析（按 JSON 口径）**：
- 触发时机：一名与荀勖势力相同的角色（含荀勖本人）在其自己的**回合内**（每回合限一次，按该角色自己回合内计），**使用一张应变牌后**（判断 `isAdaptationCard`，即牌堆里的应变牌或技能赋予应变条目的牌，见[应变规范](../adaptation.md)）。
- 触发顺序（注意主语切换）：
  1. 先由该**同势力角色**选择是否令荀勖获得此牌（从处理区/弃牌堆中取得该实体牌；若是无实体牌的虚拟应变牌或该牌已不在可获取区域，需明确能否发动“令你获得此牌”）；
  2. “然后”：在荀勖实际获得该牌后，若该牌在本次使用中**实际触发了应变效果**（按[应变规范](../adaptation.md)的 `Triggered` 事实判断，不是仅带应变标签），则由**荀勖**选择是否令该角色**变更副将**（限一次：整个【应政】技能来源每局仅能发起一次变更）。
- 若使用应变牌的是**荀勖本人**：令自己“获得此牌”即收回自己刚使用完毕的那张实体牌；若触发了应变，再可选变更自己的副将。

**待主创确认**：
1. 触发窗口以 JSON（“回合内限一次”）还是 CSV（“出牌阶段限一次”）为准？拟以 JSON 为准，请确认。
2. 当该同势力角色使用的应变牌是**无实体牌的虚拟牌**，或该实体牌在结算中途已被他人拿走/移出游戏导致结算后不在处理区时，是否无法执行“令你获得此牌”（从而也不能触发后续变更副将）？另，若使用者是荀勖自己，收回自己刚用完仍在处理区的实体牌合法，请确认。
3. “你可以令其变更副将（限一次）”按[变更武将通则](../card-categories-and-operations.md#变更武将)为整个【应政】技能来源全局限一次，还是每名同势力角色各自限一次？

## 拨律

**技能原文（JSON / CSV 一致）**：拨律：出牌阶段限一次，你可以选择一名角色并重铸一张手牌，根据花色修改其使用下张应变牌的应变条件：黑桃~富甲；红桃~残躯；梅花~助战；方片~空巢。

**结算分析**：
- 主动技，出牌阶段限一次。
- 发动消耗/动作：选择一名在场角色（含荀勖自己），并**重铸一张手牌**（将该手牌置入弃牌堆并摸一张牌；无手牌不可发动）。
- 花色映射：根据重铸的这张手牌的花色，为目标角色建立持续状态（直至其使用下一张应变牌时消耗，**不随当前回合结束消失**）：
  - `♠` 黑桃 → `<富甲>`（手牌数为全场最多）
  - `♥` 红桃 → `<残躯>`（体力值 `<= 1`）
  - `♣` 梅花 → `<助战>`
  - `♦` 方片 → `<空巢>`（使用后没有手牌）
- 生效方式：当目标角色之后使用下一张**应变牌**时，将其原本的应变条件替换为上述指定条件，然后照常走[汉晋应变](../adaptation.md)检测与触发流程（替换后消耗本次【拨律】标记）。

**待主创确认**：
1. **多条目应变牌的处理**：依据[应变规范](../adaptation.md)，一张应变牌可以附带**多项**应变条件与效果（例如同时带 `<残躯>` 和 `<助战>`）。【拨律】修改“其使用下张应变牌的应变条件”时，是把该牌上**全部条目的应变条件统一改为**【拨律】指定的条件，还是由使用者/荀勖选择修改其中一项？
2. **多次施加【拨律】的覆盖规则**：若目标尚未使用应变牌前，荀勖在下个回合再次对其发动【拨律】，新花色条件是**覆盖旧条件**，还是保留队列依次生效？建议新修改覆盖旧修改，请确认。
3. **跨回合持续性**：【拨律】修改目标“使用下张应变牌的应变条件”没有“本回合”限定，是否确认该标记一直保留至目标真正使用下一张应变牌（或目标死亡）为止？
