# 紫乔汉晋国战：应变规范

本规范记录已确认的汉晋应变语义、牌位与效果约束；程序接口及验收资料另见文末开发资料。

`MUST` 为必须满足的约束。本规范覆盖汉晋模式 `hanjin_heg_mode`，不改变原版国战或身份局。

## 2. ADAPT-001：应变牌的定义

完整实体牌位及全部 16 组已确认效果见 [基础牌表第 4 节](card-deck.md#4-已确认的应变效果)。同牌名、同应变条件的效果一致；仅在此分组规则中，普通杀、火杀、雷杀、冰杀视为不同牌名。MUST 使用用户确认的效果，不按上游牌表覆盖或推定。

1. 具有明确应变条件和应变效果的牌，即为应变牌；MUST 同时包含条件和效果。
2. 不限定实体牌、牌堆来源或卡牌物理标记。技能明确赋予应变条件/效果的转化牌、虚拟牌及本次使用对象同样适用。
3. “是应变牌”与“本次已触发应变”是两个不同事实。条件未满足、助战无人响应或取消增减目标，不改变该牌属于应变牌的事实。
4. 例：牵弘转化的【逐近弃远】若明确具有“助战 → 执行两项”，MUST 被 `isAdaptationCard` 识别，供未来铜雀/刘渊/贾充等效果检查；不因没有实体应变标记而排除。
5. 不能仅因某张材料牌具有应变，就自动把其应变附加给另一张转化牌。转化技能 MUST 明确写入其拥有的条件与效果。

## 3. ADAPT-002：条件

| 条件 | 代码 | 判定 |
| --- | --- | --- |
| 富甲 | `fujia` | 使用者手牌数为存活角色中最多，允许并列最多。 |
| 残躯 | `canqu` | 使用者当前体力值恰为1；不是“小于等于1”。 |
| 助战 | `zhuzhan` | 本项询问中至少一名合法协助者成功弃置一张与应变牌同类别的手牌。 |
| 空巢 | `kongchao` | 使用者当前没有手牌。 |
| 孤军 | `gujun` | 使用者已确定势力，且其势力的存活角色数恰为1。 |

孤军统计沿用国战 `HegUtil.getSameKingdomPlayersNum`：未确定势力不能满足，暗置且尚未确定势力的其他角色不计为同势力，阵亡角色不计；野心家/建国关系使用实际国战势力身份，不能简单按武将印刷势力合并。

### 条件检测时点：已确认逐项重检

用户已确认：应变条件 MUST 在每个条目开始结算时重新检测。前一条目及其成功事件监听器完整结束后，再检测下一条目；后续条目按此时的实际状态判定。单张杀的“无视次数”因须在引擎记数前锁定，按第 8 节的专门时点处理。

- 在 `fk.AfterCardUseDeclared` 只固定本次条目、无视令牌和时点策略；默认不提前认定所有普通条件是否成立。
- `sequential`（已确认的正式规则）：每个条目开始结算时，重新读取手牌、体力和势力人数。前一条目及其成功事件监听器完整结束后，再检测下一条目。
- 例：两个“空巢”条目，第一项摸牌后，第二项空巢不再满足；反之，第一项摸牌也可能让之后原本不满足的富甲变为满足。已经处理的条目不会回头再检测。
- `snapshot` 作为现有实现的对照分支保留配置与测试：在 `fk.AfterCardUseDeclared` 缓存普通条件，之后所有条目使用这次快照；第一项摸牌不使后续空巢失效。该分支不属于已确认的正式规则。
- 开发配置在 `pkg/hanjin_mode/rules/config.lua` 的 `adaptation_condition_timing`，实现支持 `sequential`、`snapshot`；正式模式 MUST 使用 `sequential`，不提供房主切换选项。
- 策略在本次使用准备时固定；中途修改配置不改变已经开始准备的这张牌。执行结果记录 `condition_timing` 供审查。
- 两种策略下，助战都在对应条目结算时单独询问，不把交互结果提前视为成立。用牌的实体材料此时已离开手牌。

## 4. ADAPT-003：强制、独立和触发记录

1. 一张牌可有多个独立“条件 → 效果”条目，各条目有唯一 ID，MUST 分别检查、分别执行，不得按效果名称去重。
2. 条目条件满足后，非增减目标的应变效果 MUST 强制触发并执行；不得再询问“是否发动应变”。本扩展所有正式应变牌均适用，不是某张牌的专属例外。
3. 增加/减少目标是例外：使用者可以选择是否增加或减少一个合法目标，MUST 提供可取消的合法目标选择。取消、没有合法目标或没有实际改变目标列表时，本条目 MUST 不计作触发应变，不发出成功事件。
   增加目标的候选范围 MUST 遵循[指定额外目标](extra-targets.md)：`目标+1` 只约束数量，不改写牌面目标条件；逐牌例外及当前公共筛选差异见该规范。
4. 取消某个增减目标条目，不得取消同一张牌上其他已满足条件的强制效果。
5. 在 `fk.AfterCardTargetDeclared` 的低优先级强制规则中按条目声明顺序结算。即使前一个效果移除最后目标，当前应变处理仍继续执行剩余独立条目。
6. 每个真正触发的条目记录一次结果，并发出 `Adaptation.Triggered` 自定义触发事件；仅“条件满足”不能假装已经产生效果。
7. 对同一使用数据重复进入应变处理 MUST 不重复弃牌、加伤害、摸牌或发送成功事件。使用结束清理内部执行状态，结果保留在本次使用数据中供结算/测试检查。
8. 应变区分“使用牌”与“打出牌”；不因 `CardResponding` 的单纯打出而自动触发。响应事件中实际调用“使用牌”的情况仍按用牌流程判断。

## 5. ADAPT-004：无视条件

1. 每项“无视条件应变”效果登记为一个本次使用专属令牌，MUST 仅使一个尚未满足的条目成立。
2. 即使多个条目使用相同条件名，一个令牌也不能使这些条目全部成立。
3. 多个独立来源可分别提供令牌，每个令牌分别作用于一项条件；不得把单个来源变成“所有条件均满足”的布尔标记。
4. 接口允许提供令牌的技能明确指定条目 ID；未指定时，在遇到未满足的条目时从当前不满足的未结算条目中选择一项（多个候选默认由使用者选择），不得暗中开启全部条目。
5. 自然满足的条件不消耗令牌。指定条目已经自然满足时，该令牌无需再替它忽略条件，也不擅自转移到其他条目。
6. 被忽略的助战条件无需再询问、无需协助者弃牌；正常助战不会因某个其他条目被忽略而自动成功。
7. 令牌与成功记录属于本次使用，不能写入共享牌原型或角色永久标记，使下一次使用继承无视条件。
8. 默认逐项模式下，不能在准备阶段因为所有条件暂时满足就丢弃令牌；某个条件因之前的效果才变为不满足时，未使用的令牌仍可作用于它。
9. 已选定或技能指定的条目在轮到它时若自然满足，不支付令牌，也不擅自转移到另一条目。多个令牌不得重复忽略同一条目。

## 6. ADAPT-005：助战

1. 使用者和当前目标 MUST 被排除。候选为其他存活、拥有至少一张可合法弃置的同类别手牌的角色；不按敌友或势力限制候选。
2. 类别指基本牌/锦囊牌/装备牌，与应变牌自身的类别比较，而不是与转化材料、花色、颜色、牌名或锦囊副类别比较。
3. 成本必须是一张协助者自己的手牌；不能弃装备区、他人牌、超过一张牌或被禁止弃置的牌。
4. 使用引擎 `Request:new(candidates, "AskForUseActiveSkill", 1)` 同时发出询问，不按座次逐个弹出窗口。
5. 每份回复在计为竞速成功之前 MUST 校验所有权、手牌区域、类别、数量与弃牌合法性；非法回复视为取消，不能抢先结束其他合法协助者的机会。
6. 首个被引擎处理为合法响应的角色成为本项胜者，其余询问立即终止。仅胜者弃牌，不得让所有已经点击响应的角色同时付费。
7. 若成本在询问后被其他效果使之失效，必须重新校验，不能虚构成功；可继续询问剩余候选。实际没有成功弃出手牌则该助战条件不成立。
8. 全部取消、超时或没有合法候选时，条件不成立；若没有无视令牌，对应效果不执行。
9. 两个独立助战条目分别询问、分别支付，不能以一张弃牌让两个独立条件同时成立。

## 8. ADAPT-006：单张杀的“无视次数”与状态型无次数限制

### 8.1 语义区分

1. `ignore_times` 表示“本次使用不计入次数”，MUST 同时满足“超过上限仍可选择/使用”和“本次不进入 `addCardUseHistory`”。
2. 咆哮、连弩等状态型效果属于 `TargetModSkill.bypass_times`：只让 `withinTimesLimit` 返回真，绕过上限；本次使用照常计数。二者 MUST 分开实现，不能把状态型效果改成 `extraUse`。
3. 正式牌包独立创建 `hanjin__thunder__slash`（雷杀），恰好为♠9、♠10，`trueName == "slash"`、雷电伤害，并自带条目 `{ condition = "gujun", effect = "ignore_times" }`。该牌使用独立的 `hanjin__thunder_slash_skill`，不复制上游 `slash_skill` 或 `thunder__slash_skill`。

### 8.2 时点：选牌/选目标 → PreCardUse → 记数 → 应变常规结算

自由场引擎的顺序是：次数合法性检查早于用牌事件；`ltk/server/events/usecard.lua` 在 `PreCardUse`（约225行）之后、`AfterCardUseDeclared`/`AfterCardTargetDeclared`（约270行）之前，于约261行检查 `use.extraUse` 并调用 `addCardUseHistory`。因此：

1. 选牌与选目标阶段 MUST 只做无副作用判定：读取势力/体力/手牌/存活人数，判断 `ignore_times` 条目是否自然满足，从而让该牌在次数已满时仍可被选中、且只对合法距离目标生效。此阶段 MUST NOT 加伤害、摸牌、弃牌、询问助战、消耗令牌、设置 `extraUse` 或发出成功事件。
2. 正式确认（`fk.PreCardUse`，在记数前）MUST 锁定本条条件的结果，并在需要时设置 `use.extraUse = true`。锁定后，本次使用不再因之后的条件/座次/明置变化而改变。
3. 应变常规结算仍在 `fk.AfterCardTargetDeclared` 按条目声明顺序进行。`ignore_times` 条目使用锁定结果，只在轮到它时发出一次成功事件；不得在选牌、锁定时或重复 `A.resolve` 时重复发事件。
4. 其他条目按已确认的 `sequential` 规则逐项重检、独立执行，取消增减目标不计触发，并遵循“一令牌一项”规则。`ignore_times` 的自然条件不消耗令牌；显式指定该条目 ID 的令牌可在 `PreCardUse` 锁定阶段支付并取得本次豁免；未指定条目的令牌不会被提前挪用，也不会在记数后追认豁免。

## 9. ADAPT-007：已确认效果、UI 文本与卡牌专属结算

### UI 文本与完整语义分离

UI MUST 按用户给定原文显示，不把内部效果标识或扩写后的规则文本当作显示文本。

### 手牌提示与触发显示

- 卡牌标记直接显示条件与效果，省略“应变”二字。选中应变牌后的额外提示只显示在该牌上，不得把所选牌的应变提示复制到其他手牌；其他牌自身已有的牌面标记照常显示。

- 手牌中的应变牌 MUST 显示其明确拥有的应变条件与效果，完整说明同时保留在卡牌动态描述中。同名牌按各自实体牌位显示，多条目分别展示；转化牌及本次使用附加条目按实际赋予的信息处理。
- 牌面提示用于说明条件与效果；实际是否满足仍按逐项重检规则判定，不能将展示提示当作条件已经满足或应变已经触发。
- 每个成功触发的应变条目，画面中央的触发提示 MUST 显示该条目的具体条件，例如“触发<孤军>”。富甲、残躯、助战、空巢、孤军均按对应条件命名，替代通用的“触发汉晋应变”提示，避免同一条目重复播放通用与具体提示。
- 使用无视条件令牌时，触发提示仍显示该条目原有的条件。条件未满足、助战失败，以及取消或未实际改变目标的增减目标条目，MUST 不显示成功触发提示。多条目按实际成功结算的顺序显示，每个成功条目只显示一次。
- 显示功能 MUST 通过扩展可用接口实现，随用户安装包生效，不依赖开发环境对新月杀本体的适配。
- 暗置牌的应变标记只发送给有权查看的客户端。初始手牌与后续手牌通知牌的拥有者，公开区域按公开信息同步；不得预先广播隐藏摸牌堆的牌位标记。条目减少、移除或牌的拥有者变化时，同步更新对应显示。

### 效果名称与 UI 文本

| 效果标识 | UI 文本 | 完整语义 |
| --- | --- | --- |
| `execute_both` | 执行两项 | 强制依卡牌专属顺序执行两个不同效果，不是重复同一效果。 |
| `add_target` | 目标+1 | 使用者可选择增加一个合法目标，也可取消。 |
| `remove_target` | 目标-1 | 使用者可选择减少一个合法目标，也可取消。 |
| `draw` | 摸一张牌 | 使用者摸一张牌。 |
| `damage` | 伤害+1 | 此牌造成的伤害增加 1。 |
| `obtain_response_card` | 获得响应牌 | 获得这张牌所响应的牌，不是获得这张牌本身。 |
| `ignore_times` | 无视次数 | 此牌无视次数，不计入使用次数；不自动豁免距离等其他限制。 |
| `disresponsive` | 不可响应 | 对【借刀杀人】须同时禁止所有角色以无懈可击响应、以及目标角色使用杀响应。 |

全部 16 组实体牌与条件、效果的对应关系以 [基础牌表](card-deck.md) 为准。效果确认不代表卡牌已经实现或 UI 翻译已经更新。

### 水淹七军·助战：执行两项

- MUST 先执行弃置装备牌的效果，再执行造成雷电伤害的效果。
- 两项强制按顺序执行，不允许二选一或交换顺序。

### 逐近弃远·助战：执行两项

- MUST 先弃置目标一张牌（拆），再获得目标一张牌（顺）。
- 应变使本次结算强制执行两项，MUST NOT 再按距离决定只拆或只顺，也不能由使用者选择跳过其中一项。
- 第二项按第一项完成后的实际牌区处理，不虚构已被弃置的牌仍可获得。
- 验收例：对距离 1、只有一张牌的目标使用此牌且助战成功，先弃置该牌，随后无牌可获得。最终效果为拆牌；不能按距离 1 改回顺牌、先获得该牌或只执行原本的距离分支。
- `execute_both` 是效果标记；正式卡牌实现 MUST 主动读取并实现以上顺序。框架登记此标记不等于已完成该卡牌。

### 闪·孤军：获得响应牌

- 指获得这张闪所响应的牌，MUST NOT 错取闪自身。
- 应变在使用牌时触发。单纯“打出闪”MUST NOT 触发；作为响应而实际“使用闪”仍属于使用牌，不得一概排除所有响应场景。
- 未处于可获得区域、无可获得实体材料等边界须按正式卡牌及引擎移牌规则处理，不因条件满足虚构可获得牌；不能为跳过这些边界而把强制效果变成可选发动。

### 借刀杀人·富甲：不可响应

- 所有角色 MUST 不能以【无懈可击】响应此牌。
- 目标角色 MUST 不能使用【杀】响应此牌效果。
- 实现与测试 MUST 同时覆盖锦囊无懈响应窗口和借刀内部询问使用杀的窗口；不能仅设置通用不可响应标记就声称两个窗口均已覆盖。
