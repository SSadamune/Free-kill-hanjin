# 紫乔汉晋国战：应变规范

状态：规则框架与自动化测试已实现；铜雀、牵弘、刘渊、贾充及正式应变牌尚未实装，不得声称已完成这些武将或装备。

`MUST` 为必须满足的约束。本规范覆盖汉晋模式 `hanjin_heg_mode`，不改变原版国战或身份局。

## 1. 源码检查和依赖结论

- 本地 FreeKill v0.5.25 的 `lua`、`ltk` 及已安装内容未发现应变条件/效果结算器；核心仅提供 `Card.extra_data` 等通用扩展接口。
- 应变篇在官方 `Qsgs-Fans/gamemode` 扩展中：`pkg/gamemodes/rule_skills/variation.lua`、`pkg/variation_cards/` 和 `pkg/gamemodes/variation.lua`。
- 已下载到 `.dev/reference/gamemode`，提交固定在 `dependencies.lock.json` 的 `references` 字段。重建可运行 `python scripts/setup_dependencies.py --references`；普通运行不依赖参考目录。
- 上游规则按单个 `{条件, 效果}` 登记，原铜雀会一次放开所有条件，不满足汉晋“一次仅忽略一项”的规则；上游接口还须按当前引擎版本核对，不能直接复制后假定兼容。
- 上游仅供核对，不安装到运行环境 `packages`，不加载其原版应变牌、武将、身份模式或全局应变技能。汉晋实现独立元数据、规则模块和事件。

## 2. ADAPT-001：应变牌的定义

1. 具有明确应变条件和应变效果的牌，即为应变牌；MUST 同时包含条件和效果。
2. 不限定实体牌、牌堆来源或卡牌物理标记。技能明确赋予应变条件/效果的转化牌、虚拟牌及本次使用对象同样适用。
3. “是应变牌”与“本次已触发应变”是两个不同事实。条件未满足、助战无人响应或取消增减目标，不改变该牌属于应变牌的事实。
4. 例：牵弘转化的【逐近弃远】若明确具有“助战 → 执行两项”，MUST 被 `isAdaptationCard` 识别，供未来铜雀/刘渊/贾充等效果检查；不因没有实体应变标记而排除。
5. 不能仅因某张材料牌具有应变，就自动把其应变附加给另一张转化牌。转化技能 MUST 明确写入其拥有的条件与效果。

## 3. ADAPT-002：条件

| 条件 | 代码 | 判定 |
| --- | --- | --- |
| 富甲 | `fujia` | 使用者手牌数为存活角色中最多，允许并列最多。 |
| 残躯 | `canqu` | 使用者当前体力值恰为1；不是“小于等于1”。 |
| 助战 | `zhuzhan` | 本项询问中至少一名合法协助者成功弃置一张与应变牌同类别的手牌。 |
| 空巢 | `kongchao` | 使用者当前没有手牌。 |
| 孤军 | `gujun` | 使用者已确定势力，且其势力的存活角色数恰为1。 |

孤军统计沿用国战 `HegUtil.getSameKingdomPlayersNum`：未确定势力不能满足，暗置且尚未确定势力的其他角色不计为同势力，阵亡角色不计；野心家/建国关系使用实际国战势力身份，不能简单按武将印刷势力合并。

当前实现按“使用时检测条件”的原文采用以下统一时点：

- 在 `fk.AfterCardUseDeclared` 缓存富甲/残躯/空巢/孤军的状态，此时用于使用的实体材料已离开手牌。
- 一张牌上的这些条件使用同一快照。例如先应变摸牌，不会令该次使用原本成立的另一项空巢失效。
- 助战在目标声明完成后单独询问，不把是否有人愿意支付的交互结果提前视为成立。
- 当前未使用“逐项执行后重新读取手牌/体力”的解释；如用户进一步指定其他时点，必须同步本规范、实现与测试。

## 4. ADAPT-003：强制、独立和触发记录

1. 一张牌可有多个独立“条件 → 效果”条目，各条目有唯一 ID，MUST 分别检查、分别执行，不得按效果名称去重。
2. 条目条件满足后，非增减目标的效果 MUST 强制执行；不得再询问“是否发动应变”。
3. 增加/减少目标是例外：提供可取消的合法目标选择。取消、没有合法目标或没有实际改变目标列表时，本条目 MUST 不计作触发应变，不发出成功事件。
4. 取消某个增减目标条目，不得取消同一张牌上其他已满足条件的强制效果。
5. 在 `fk.AfterCardTargetDeclared` 的低优先级强制规则中按条目声明顺序结算。即使前一个效果移除最后目标，当前应变处理仍继续执行剩余独立条目。
6. 每个真正触发的条目记录一次结果，并发出 `Adaptation.Triggered` 自定义触发事件；仅“条件满足”不能假装已经产生效果。
7. 对同一使用数据重复进入应变处理 MUST 不重复弃牌、加伤害、摸牌或发送成功事件。使用结束清理内部执行状态，结果保留在本次使用数据中供结算/测试检查。
8. 本轮只接入“使用牌”；不因 `CardResponding` 的单纯打出而自动触发。响应事件中实际调用“使用牌”的情况仍按用牌流程判断。

## 5. ADAPT-004：无视条件

1. 每项“无视条件应变”效果登记为一个本次使用专属令牌，MUST 仅使一个尚未满足的条目成立。
2. 即使多个条目使用相同条件名，一个令牌也不能使这些条目全部成立。
3. 多个独立来源可分别提供令牌，每个令牌分别作用于一项条件；不得把单个来源变成“所有条件均满足”的布尔标记。
4. 接口允许提供令牌的技能明确指定条目 ID；未指定且有多个候选时，当前默认由使用者选择其中一项，不得暗中开启全部条目。
5. 自然满足的条件不消耗令牌。指定条目已经自然满足时，该令牌无需再替它忽略条件，也不擅自转移到其他条目。
6. 被忽略的助战条件无需再询问、无需协助者弃牌；正常助战不会因某个其他条目被忽略而自动成功。
7. 令牌与成功记录属于本次使用，不能写入共享牌原型或角色永久标记，使下一次使用继承无视条件。

## 6. ADAPT-005：助战

1. 使用者和当前目标 MUST 被排除。候选为其他存活、拥有至少一张可合法弃置的同类别手牌的角色；不按敌友或势力限制候选。
2. 类别指基本牌/锦囊牌/装备牌，与应变牌自身的类别比较，而不是与转化材料、花色、颜色、牌名或锦囊副类别比较。
3. 成本必须是一张协助者自己的手牌；不能弃装备区、他人牌、超过一张牌或被禁止弃置的牌。
4. 使用引擎 `Request:new(candidates, "AskForUseActiveSkill", 1)` 同时发出询问，不按座次逐个弹出窗口。
5. 每份回复在计为竞速成功之前 MUST 校验所有权、手牌区域、类别、数量与弃牌合法性；非法回复视为取消，不能抢先结束其他合法协助者的机会。
6. 首个被引擎处理为合法响应的角色成为本项胜者，其余询问立即终止。仅胜者弃牌，不得让所有已经点击响应的角色同时付费。
7. 若成本在询问后被其他效果使之失效，必须重新校验，不能虚构成功；可继续询问剩余候选。实际没有成功弃出手牌则该助战条件不成立。
8. 全部取消、超时或没有合法候选时，条件不成立；若没有无视令牌，对应效果不执行。
9. 两个独立助战条目分别询问、分别支付，不能以一张弃牌让两个独立条件同时成立。

## 7. 元数据与扩展 API

实现：`pkg/hanjin_mode/rules/adaptation.lua`；事件接入：`pkg/hanjin_mode/skills/adaptation.lua`。

### 卡牌或转化牌明确附带条目

```lua
local A = require "packages.hanjin.pkg.hanjin_mode.rules.adaptation"
A.setCardEntries(card, {
  { id = "skill_support", condition = "zhuzhan", effect = "execute_both" },
})
```

正式牌堆也可在独立卡牌的 `extra_data.hanjin_adaptation` 中写入同样的条目数组。未写 ID 时按 `card:序号` 自动编号；本次使用增加的条目按 `use:序号` 编号。

### 本次使用增添条目、给予一个忽略令牌

```lua
A.addEntry(use, { id = "skill_extra", condition = "gujun", effect = "damage" })
A.grantIgnore(use, "providing_skill", "skill_extra") -- 仅此一项
A.grantIgnore(use, "another_effect")                -- 一个令牌，未指定则选择一项
```

这些接口 MUST 在条件检测前调用，通常在转化牌构建或 `PreCardUse` 阶段完成。不得在条件快照完成后偷偷更改条目。

### 识别与后续技能监听

- `A.isAdaptationCard(card, use?)`：识别明确拥有条件和效果的牌，包括技能赋予的虚拟牌和使用级附加条目。
- `A.getResult(use)`：本次执行结果，含 `triggered`、`triggered_count`、逐项记录和效果次数。
- `A.hasEffect(use, "execute_both")`：供独立卡牌的效果实现判断是否执行两种选项。
- `A.Triggered`：每个成功条目的触发事件，数据含 `use` 和本条目的 `entry` 结果。尚未实装的刘渊、贾充等应明确区分检查“是应变牌”还是检查“本次触发应变”。
- `A.registerEffect(name, {apply = function(room, use, entry) ... end})`：注册明确的新效果。若是增减目标，须声明 `target_change = true` 并以布尔值返回是否实际改变目标。

内置效果：`draw`、`damage`、`disresponsive`、`add_target`、`remove_target`、`obtain_response_card`、`execute_both`。

其中 `execute_both` 仅提供语义标记与次数：未来【逐近弃远】等独立牌的实现 MUST 主动读取并执行两个不同选项；不得把它实现为对原效果再结算一次，也不表示本轮已创建该卡牌。
