# 紫乔汉晋国战：效果指定的用牌目标条件

状态：用户已确认以下规则。本文适用于效果让角色使用牌、视为使用牌或转化使用牌的情形；规则确认不表示所有对应入口已经完成适配。

## 默认条件与显式条件（MUST）

- 效果未另行规定目标条件时，MUST 遵循原牌面的使用目标条件。仅改变牌的来源或生成方式，不自动无视距离等条件。
- 效果直接声明某项例外，例如“无距离限制”，MUST 按声明放宽相应限制；未被该声明改写的条件仍按正常规则处理。
- 效果明确规定对哪些角色使用牌时，MUST 按该效果的目标条件确定候选，不再将原牌面使用目标条件机械叠加。“其他角色”本身就是目标条件，不能因为条件简单就退回原牌面的距离等条件。
- 使用、视为使用、转化使用遵循同一判断原则；不能仅按是否为虚拟牌或转化牌，决定是否忽略目标条件。
- 仅改变目标数量与明确指定目标范围须区分。例如，“多指定至多 X 名角色为目标”仅改变数量；“视为对 X 名其他角色使用……”同时明确了目标为“其他角色”。指定额外目标的对应规则见[指定额外目标](extra-targets.md)。

## 【顺手牵羊】示例

下列两种效果均允许对距离大于 1 的角色使用【顺手牵羊】：

| 效果原文 | 目标条件的处理 |
| --- | --- |
| “你使用【顺手牵羊】（无距离限制）” | 明确取消距离限制，其他未改写条件仍按正常规则处理 |
| “视为对 X 名其他角色使用【顺手牵羊】” | 按效果指定的“其他角色”确定目标，不叠加原牌面的距离 1 条件 |

目标条件被替代不等于已经重新使用一次牌，也不自动改变牌的效果。目标是否实际能被获得牌等结果，仍在结算中依正常流程处理。与其他禁止用牌／禁止指定目标效果的关系不得简单通过跳过全部合法性检查处理。

## 实现约定

调用入口应明确传入“沿用原条件”“仅放宽指定限制”或“使用效果自定目标条件”，而非从是否为转化牌、牌名或目标人数推断。界面候选与服务端提交复核须使用同一规则，显式目标条件须与目标数量分别传递。

规则定义已确认。三种目标策略及部分入口适配和回归已纳入版本控制；尚未对全部使用、视为使用和转化使用入口完成审阅验收。后续须继续覆盖两类【顺手牵羊】示例及复杂目标结构，并与额外目标公共接口保持一致。

## 当前实现核对

结论：**初次用牌公共接口及部分入口接入的初步实现已纳入版本控制，但审阅发现的执行顺序与复杂目标问题仍未解决，不得认定全部符合。** 已覆盖场景的默认回归通过，以下边界仍需修正及补充针对性测试。

- **沿用原条件：已有机制。** 普通选牌及目标选择使用牌技的目标条件；汉晋公共转换代码 `only_as.lua` 的默认复核已检查目标数量、重复目标、固定目标及逐个目标选择条件，并保留同次请求参数；存在可信策略时调用策略模块复核。它不会仅因转化或虚拟牌身份自动取消距离，也不是独立的“只能当”技能。策略草稿的复杂目标问题仍须另行修正。
- **仅放宽指定限制：已有机制，入口传递仍须核对。** 上游【顺手牵羊】牌技读取 `extra_data.bypass_distances`，跳过距离但保留“其他角色、区域内有牌”等条件；统领能力也有按来源标记生效的无距离限制实现。它们不是所有目标条件一并失效的通用开关。
- **显式条件替代：已有公共接口初步实现。** `pkg/hanjin_mode/rules/card_use_targets.lua` 提供 `default`、`bypassDistance`、`explicit` 三种策略，通过汉晋房间内的牌技筛选代理处理界面候选，并尝试以服务端令牌在宣告前复核。公共转换、统领、玉玺入口已有接入改动；额外目标复用同一结构化条件判断。新增接口和已有专测仍不能代替对全部入口、复杂目标结构与执行次数的验收。
- **不能依赖上游虚拟用牌助手兜底。** 引擎 `ltk/server/events/usecard.lua` 的 `useVirtualCard` 只检查禁止使用和禁止指定，不检查距离、区域等完整牌面目标条件。玉玺和统领已有目标策略接线；具体入口及策略复核仍须审阅，不能仅调用上游助手就宣称符合默认条件。
- **审阅发现的执行顺序问题。** 公共 `askToUseVirtualCard` 草稿直接调用上游同名接口，未强制延后使用。上游在未指定 `skip` 时会立即执行卡牌，发生在公共接口附加令牌和复核之前；随后调用者再次 `useCard` 还可能重复执行。必须先完成选择和可信复核，再由约定的单一入口执行，并用实际生效次数测试验证。
- **审阅发现的复杂目标问题。** 草稿 `validateUse` 把每个提交目标都与空已选列表得到的 `getAvailableTargets` 比较，无法验证【借刀杀人】等依赖已选主目标的副目标；宣告前复核又直接把展开后的主目标数量与选牌时目标数量比较，未区分群体展开及主副目标转换。引擎在 `PreCardUse` 之前已执行牌技 `onUse`，因此必须区分选择阶段与此时的目标结构，保留牌自身的目标语义，不能按普通单目标牌处理。

后续须修正以上审阅问题，补测复杂目标、固定／群体展开与虚拟用牌恰好执行一次，并继续验证策略跨请求保留、可信来源绑定、普通上游房间隔离及两类【顺手牵羊】示例。本文规则正文未因实现草稿而改变。
