# 紫乔汉晋国战：势力禁选规范

本文规定房主候选势力、允许上限、配将与牌堆联动、跨局记录的汉晋规则。完整牌位与装备关系见[基础牌表](card-deck.md)。

本文是后续 agent 实现、审查和测试的规则依据。`MUST` 表示必须满足；不得使用其他国战版本的规则替代本文。

## 1. 内容边界与术语

1. 模式代码名为 `hanjin_heg_mode`，显示名为“紫乔汉晋国战”。基础引擎为 FreeKill v0.5.25，上游依赖由 `dependencies.lock.json` 固定。
2. 所有可选武将、可摸实体卡牌 MUST 独立创建于汉晋内容包，使用汉晋独立标识。不得把上游国战或身份局的武将、卡牌直接加入本模式。
3. 上游仅作为规则流程、接口及实现参考。复用其房间、双将明暗、事件、请求和展示框架不表示复用上游游戏内容。
4. `anjiang` 等引擎暗将占位符是显示/流程基础设施，不是加入将池的正式武将。后续士兵、翼从等正式内容仍须独立创建。
5. 默认常规势力集合为 `wei / shu / wu / qun / han / jin`，对应魏/蜀/吴/群/汉/晋。房主可选的候选集以该集合为默认；未来第 7/8 势力通过 `registerKingdom` 登记为可选项，不改变默认六势力，也不因此创建正式内容。野心家专属武将的 `kingdom = "wild"`，不占常规势力名额。
6. 当前阶段，多势力武将的每个所属势力都视为“主势力”。引擎字段 `kingdom` 和 `subkingdom` MUST 同等参与允许集判断；“主势力”不是只指 `kingdom` 字段。未来新机制引入后再修订本条。
7. 用户提供的是实体桌游规则；程序可省略无意义的桌面操作。本次“重摸”实现为发牌前排除，不提供发牌后的重摸按钮。

## 2. BAN-001：本局候选势力与允许势力

后续扩展规则见[客将](guest-factions.md)与[野心家效忠](wild-allegiance.md)。发牌前排除仍适用于完全不能入池的牌；以客将势力入池的牌另有选将阶段自愿重抽权。第 4 节按数量排除的原版也属于开局禁野心家，其效忠版按本局允许势力筛选入池。这些流程由 `faction_ban`、`guest_factions`、`wild_allegiance`、`general_pool` 和 `general_versions` 实现，具体边界见对应文档。

### 输入

- 候选势力集合 `C`：由房主在房间设置中预先选择，默认为魏、蜀、吴、群、汉、晋六项。`C` MUST 来自房主选择，不得由将池武将的主势力、客将势力或效忠版势力反推。可扩展未来第 7/8 势力；新增势力只登记为可选项，不因此创建或虚构正式武将/卡牌。
- 允许上限 `L`：房主选择的正整数，MUST 满足 `1 <= L <= |C|`。未另行指定时默认为 `min(4, |C|)`；即通常延续 4，候选少于 4 项时取候选数。
- 上一局记录：胜利常规势力集合 `W`、被禁势力集合 `P`；首次开局没有此记录。只有仍属于本局 `C` 的势力参与本局约束。
- `general_pile`：本局已经通过模式白名单、禁将及同名替换规则筛选的武将牌堆。将池 MUST NOT 决定 `C` 或 `L`。

设置键：

- `hanjin_candidate_kingdoms`：可选，程序/测试用候选势力数组。提供时以它为准，仍走同一校验。
- `hanjin_candidate_<势力>`：每个已知势力一个布尔开关；未设置时按该势力是否属于默认六势力取值。界面使用这一组开关。
- `hanjin_kingdom_limit`：允许上限 `L`；缺省按 `min(4, |C|)`。
- 旧房没有上述键时按默认六势力与默认上限处理；不得因旧房间缺少设置而拒绝开局。旧上游开关 `notBanToFourKingdoms` 不再作为本模式的免禁依据，避免绕过候选/上限校验。
- 未来第 7/8 势力通过 `faction_ban.registerKingdom(id, { default = false })` 登记为可选项；应在模式创建前登记，默认候选集仍为六势力。登记只增加房间设置选项和势力识别，不创建正式武将/卡牌，也不自动把该势力纳入默认候选。

### 结果与约束

1. 时机 MUST 在分发任何武将牌之前；MUST 先解析并校验房主设置，再计算允许集。
2. 非法设置 MUST 明确拒绝继续初始化，不得静默截断或猜测：候选为空、候选含未知势力、候选重复、候选开关不是布尔值、`L` 不是正整数或 `L > |C|` 均属非法。初始化失败后旧跨局记录不得再次冒充“上一局结果”。
3. 当 `|C| <= L` 时，允许势力为 `C`，禁选集合 `B` 为空。即使上一局有胜利势力，也不额外禁选。
4. 当 `|C| > L` 时，选出禁选集合 `B`，使 `|C - B| = L`。
5. 对当前仍在 `C` 中的上一局胜利势力，MUST 有 `W ∩ C ⊆ B`。
6. 上一局被禁势力，本局 MUST 不被禁，即 `P ∩ B = ∅`。
7. 先满足必禁、必留约束，再使用房间随机数发生器从剩余候选势力中无放回补足 `B`。不得使用全进程共享随机结果代替房间随机数。
8. 上局记录指向本局 `C` 外的势力时，不为该势力保留名额，也不参与必禁/必留计算。
9. 如果记录相互矛盾，或必留/必禁约束不足以合法补足 `B`，MUST 明确拒绝继续初始化，不得偷偷忽略约束。
10. 禁选结果一经确定，本局保持不变；不得在后续取将时重新随机势力。
11. 候选外不可选：一张武将只有在至少一个印刷势力、客将势力或效忠版自身势力落入本局允许集时才能进入发将/后续取将；主势力、客将势力与效忠版势力一视同仁。仅作为客将势力出现、或将池中没有原版武将的候选势力，仍是合法候选，不因将池缺失而被删除。

## 3. BAN-002：武将筛选和选将

### 测试用自由选将例外

用户确认：开启房间公共设置 `enableFreeAssign` 时，自由选将作为测试功能，允许手动替换为候选外或被禁势力的武将，并忽略汉晋及国战的配对限制（包括势力交集、同名配对、野心家副将限制）。仍须是已登记的两张不同武将牌。选将界面的自由选将入口、客户端确认与服务端落将须共同生效，不能仅放宽回复校验。

初始势力优先采用正常配对结果；正常结果为空时，采用所选武将原有势力的交集，无交集时从并集中选择，不受本局禁势力过滤；两将均无常规势力时，以本局首个允许势力兜底（允许集也为空时取内置首个常规势力）。该例外只放宽测试选将，不把上游或测试武将加入正式随机将池，不改变正常牌堆策略。关闭自由选将时，以下正常规则完整生效。

1. 非野心家武将仅在其所有所属常规势力（含客将/效忠版自身势力）均不在本局允许集时排除。
2. 例如魏/蜀双势力武将：魏被禁、蜀仍允许时 MUST 保留，但只能选择蜀势力；若两者都不在候选集或被禁，则排除。
3. 排除的武将 MUST 同时加入本局 `disabled_generals`，避免同名替换和后续随机取将把它们重新引入。
4. 将牌分发 MUST 无重复；每位玩家保留至少一组合法主副将。野心家专属武将只能作主将，不能作副将。
5. 选将回复 MUST 在服务器端验证：属于该玩家获分发的武将或合法同名替换、在允许集内、主副将不重复、存在允许的共同势力。
6. 多势力组合按双方势力交集再与本局允许集合求交；不得因为交集中另一项被禁就清空仍合法的势力。
7. 超时、取消、格式错误、越界武将、重复武将或无效势力回复 MUST 回退到该玩家获发的合法组合；无效势力不能被写入角色初始标记。
8. 未被选择的将牌只放回一次。最终选中的牌（含合法同名替换所消耗的原牌）不得同时留在公共将池。
9. 将池无法支持所有玩家合法双将时，MUST 报告初始化失败，不得借用上游武将补齐。

## 4. BAN-003：野心家专属武将数量

- 房主可将 `hanjin_wild_count` 设为 `0` 至 `12` 的整数，默认 `4`。
- 此选项直接替代实体规则中“若将池不大”的判断，不设置隐含将池大小阈值。
- 设定值 `N` 表示本局随机保留至多 `N` 张野心家专属武将。少于 `N` 张时全部保留；设为 `0` 时全部排除。
- 筛选发生在发将前，使用房间随机数进行无放回抽样；未保留的专属武将亦加入 `disabled_generals`。
- 本条不针对游戏过程中因人数规则变为野心家的普通武将，也不限制野心家玩家人数。

### 牌堆构建

1. 输入牌堆 MUST 仅来自允许的独立汉晋卡牌包。
2. 有替换牌且所属势力允许时，君主装备占用与替换牌共用的牌位；替换牌仅移出匹配的那一张，不得按牌名批量删除所有同名牌。
3. 匹配位置以登记的替代牌名、相同花色和点数确定。后续成套牌堆定义 MUST 保持配对牌位一致。
4. 该势力被禁时，君主装备移入本局游戏外区；有替换牌时恢复对应替换牌。保留原牌位花色与点数，不改变其他牌。
5. 已存在对应普通实体牌时 MUST 复用，不能重复加入。自定义牌堆缺少对应实体副本但已定义该独立普通牌类型时，可用 `Room:printCard` 创建房间内替代副本；普通牌类型本身未定义时不得用上游同名牌兜底。
6. 赤霄剑没有替代关系：汉允许时保留 EX/♥/9 的赤霄剑（已计入 162 个基础牌位），汉被禁时移出且不生成替代牌。
7. 七张势力锦囊只通过特殊手段加入，均不进入默认牌堆。已有的常规势力禁选规则仍适用：所属常规势力被禁时，从摸牌堆移出其锦囊，不补牌。洛水之誓归属野心家；常规势力允许集不含野心家，不能据此判定其被禁。
8. 七张的牌名、花色、点数与归属见[基础牌表第 5 节](card-deck.md#5-势力锦囊仅通过特殊手段加入)。七张默认位于游戏外区。
9. 虚妄之冕 MUST 当且仅当魏、晋均被禁用时移出且不补牌；任一允许即保留。此装备 MUST 使用多势力 OR 加入条件，不能误写为两势力均允许或仅绑定一个势力。候选外势力沿用本规范的不可用处理。
10. 合纵标记属于具体的特殊装备或替换牌：太平要术替换为带合纵标记的惊帆；神授思召带合纵标记，其替换牌青龙偃月刀不自动继承该标记。
11. 全部基础牌位、实体牌名、花色点数见[基础牌表](card-deck.md)，EX 六张固定纳入，非可选扩充。逐牌实装与待办另见[开发状态](../docs/development/status.md)。本规范不授权自行编造效果或把无效果测试牌发布为正式卡牌。

## 6. BAN-005：同房间上一局记录

1. 使用引擎 `Room:getSessionData()` / `Room:setSessionData()` 保存到原生房间对象；禁止按进程全局变量、全服最近一局或用户账号共享记录。
2. 命名空间键为 `hanjin_faction_ban_v1`，结构为：

```lua
{ version = 1, winners = { "wei" }, banned = { "han", "jin" } }
```

3. 不得覆盖 SessionData 内其他扩展的字段。
4. 正常 `fk.GameFinished` 时，从胜利角色的实际常规势力去重得到 `winners`，并保存本局 `banned`。野心家胜利不伪装成某个常规势力；平局的 `winners` 为空。
5. 下一局开始筛选时读取并消费上一局记录；只与上一局胜利/被禁势力在本局候选集 `C` 中的部分参与计算，候选外记录忽略。如果这局初始化失败或被异常中断，旧记录不得再次冒充“上一局结果”。
6. 同一房间改玩其他模式时，在 `fk.GamePrepared` 清除汉晋历史字段，避免隔局误用。
7. 原生房间关闭时记录随之销毁；新房间即使复用了数字房间号，也不得继承旧记录。游戏进程重启后不保留。
8. 不使用 `getSessionId()` 推断跨局间隔：核对的 Qt 引擎同版本源码虽公开该接口，但未发现实际递增实现。本规则依赖房间 SessionData 生命周期及事件。
